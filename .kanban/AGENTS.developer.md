# developer: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets (repo structure, build/test recipes, general shell traps, workflow tips). Never edit this file as the role agent.

- Fixed end-of-run sequence, the same for every task: (1) load the kanban tools with `tool_search("kanban")` in the first block; (2) verify with a scoped test run, then a build; (3) apply the commit rule below; (4) record assumptions, measured values, and results in one `kanban_update`; (5) stop. These rules answer the "commit, verify, or update the card" questions, so do not spend thinking blocks on them.
- Worktree startup, one block: worktrees live in `.worktrees/<branch>` and track `main`. A fresh worktree has no `node_modules`, so start `npm ci > /tmp/npm-ci.log 2>&1 &` immediately and read the log before the first vite/vitest use ("Cannot find module" means a missing install, not broken code). Parallel tasks land on `main`, so a worktree can be stale: run `git log HEAD..main --oneline` and `git merge --ff-only main` before work. Never investigate branches or empty log ranges for it.
- Verification strategy is decided once, in the first planning block, from the task type and frontmatter complexity (trivial → skip tests; new feature → tests first; refactor → tests before code; fix → failing test first, written together with any integration-level regression test, before the code change). Scoped suites are the ones owning the touched files. Never reopen scope after green, and never re-choose suites in a later block. Ambiguous spec wording (heights, tolerances, injectable parameters): decide once, record the assumption on the card, move on.
- Stack: Vite + Vitest, ESM (`"type": "module"`). Scripts: `npm run dev`, `npm run build`, `npm test` (= `vitest run --passWithNoTests`). Tests sit next to sources as `src/**/*.test.js`; Vite and Vitest share `vite.config.js`. `npm run build` parses only modules reachable from `main.js`; parse-check anything else with `node -e "import('<path>')"`. A green build is a green build: never spend time on bundle size, asset counts, or module counts.
- `src/math/` holds vec3/mat3/quat/mat4 helpers, out-param style (`add(out, a, b)`, column-major); reuse them, always pass a destination. Never alias `out` with an input, in production code, probes, or test helpers. Before writing a probe or test that calls a helper, grep the module's exported names once; a guessed API name (`fromX` vs `setX`) costs a full run-and-fix round.
- New dependencies: redirect install output to a log (`npm install --loglevel=http > /tmp/npm.log 2>&1`), never a bare install against a long timeout. `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true`; check `npm view <pkg> time` before version floors. On failure read the log and `cat ~/.npmrc`; verify with cheap metadata, not blind retries.
- Commit rule: code changed and tests green → one commit, lockfile included when deps changed. Verification-only run on a clean tree → nothing to commit; put results on the card and stop. Never commit TASK.md, AGENTS.md, or `.kanban/`. Clean-room acceptance (`git archive HEAD | tar -x -C /tmp/check`, then `npm ci && npm test && npm run build` in the copy, confirm relative asset paths in `dist/index.html`, delete the copy) is required only when the run changed committed code.
- Settle deliverable, file placement, and data contracts in the first planning block. When a convention is derived (sign, axis, numbering, units, per-unit vs total), write it once as an input-to-expected table and freeze it; never re-derive it in a later block. Every thinking block must end in a decision or a tool call. Cap option-weighing at one block per decision: when a block only re-lists alternatives, take the cheapest one, record it, and move on. Do not re-decide choices this file already fixes (revert recipe, regression proof, browser delegation): execute the recipe. While a background subagent runs, spend no thinking block on re-derivations; commit, update the card, or end the block.
- Batch independent calls in one block, and read each file at most once: keep a running map of what has been read; re-reading or re-printing a returned section is waste, grep with context instead. Read files with the `read` tool, not `cat`; use offset/limit for large files. For `edit`, keep each `oldText` short, exact, and unique; merge nearby changes into one edit, because overlapping edits are rejected.
- Test discipline: after writing a module, run its suite at once. Never run the same suite twice without an intervening code or test change. When a run fails, analyze it fully first, then batch the fix and the rerun into one step; if the identical failure persists, re-read the edited region before new hypotheses. Long simulations in vitest: default timeout is 5 s, pass an explicit one (`it(name, fn, 30000)`); never put `expect` inside per-step loops, accumulate a worst case and assert once. Vitest adds roughly 1.5-2x wall time over a standalone `node` run: measure standalone once, set thresholds with 2x headroom.
- Stop rule: a green scoped run is the evidence; report the pass count and move on. After green, edit again only to fix a real defect. Batch hygiene (dead code, unused imports, debug leftovers, grep the diff for their markers) into the same edit pass as the last functional change, before the final green run. A post-green cleanup pass forces another full test-plus-build cycle.
- Temporary code changes (regression proof, debug logging in sources): copy the file to `/tmp` first, and restore it in the same bash block chained with `;` so the restore always runs (`cp src/f.js /tmp/f.bak; ...; cp /tmp/f.bak src/f.js`). Regression proof: revert the fix, run only the one test file, restore the fix. Expected result: red pre-fix, green post-fix. Prefer a probe that wraps or imports the real module over editing source.
- Instrumented probes that copy production modules must trace the full call path, caller included, not one helper: caller-side transforms (normal flips, argument order, early exits) decide which face or value is under test, and a partial copy makes probe and production disagree in ways that cost many blocks to untangle. Regenerate instrumented copies from HEAD at the start of every measurement run, or import the real module and copy nothing; a stale `/tmp` copy reports phantom failures against already-fixed code. Delete `/tmp` copies when done.
- Repro search for numerically degenerate bugs: a hand-built pose almost never lands on the degenerate set, so do not hand-tune poses. In one script, sweep the parameter axes the spec names or implies (tilt or twist about every angular axis, lateral offset, overlap) over a decade around the failure scale, seeded with one known-yes case, with a pass predicate that catches every symptom shape. A zero-hit sweep means widen axes or shrink steps, not an instant verdict on the production code. When a sweep hits, minimize the hit (freeze seed and parameters, shrink the case) and use it as the regression test; never go back to hand-designed poses.
- Pick tuned constants (epsilons, welds, tolerances) from one sweep, not two: in the same probe that searches for failures, sweep the candidate threshold axis and choose the smallest value with zero failures across every symptom shape and every probe fixture. Keep the constant unexported with a one-line unit comment. If a later probe still shows failures, widen the pass predicate before touching the constant again.
- A spec-suggested fix is a hypothesis, not the answer: before implementing it, print the actual intermediate values at the failure site (distances, coordinates, counts) in one probe and check the suggested mechanism against the data. Implement the root cause, and record the deviation from the suggested fix as an assumption on the card.
- Simulation and physics probes: a `/tmp` probe must replicate the production step sequence exactly, every substep in the same order; a partial re-implementation produces false contradictions and wasted reruns. Probes import repo modules by absolute path or `file://` URL, and never suppress errors (`try { } catch { }` and ignored exit codes hide failures). Validate the fixture before trusting its measurements: spawn positions clear of geometry by body radius or extent margins, a physically valid initial state, one sanity-checked step. Never tune production constants from a broken fixture.
- When a computed magnitude is implausible (too small, too large, wrong units), print the whole value chain in one probe: input → geometry or shape constant → density or mass scale → derived tensor. Do not re-derive units mentally across blocks. Check first for a scale applied twice or not at all, a per-unit vs total convention mix-up, a swapped table entry, an argument in the wrong slot. For contact or normal signs, gate on signed approach velocity (`v·n < 0`), never absolute speed. Validate layered derivations (raw vertices → discovered faces → mass properties) one layer at a time against known reference values; a bug in a base layer poisons every layer above it.
- Precision and expectations: use `Float64Array` for math and physics state, Float64 in test expectations, and relative tolerances for accumulated sums; pick the precision once for the whole module family. Tests compute expected values through the module's own helpers and constants, derived with a one-line `node -e` script in the same block as the assertion; never mental arithmetic, and never reconcile a red test's expected against actual by hand: print both from one script, then decide. Verify fixture facts (face layouts, lookup tables, counts) against the module that owns them before asserting; a fact recalled from memory costs a failed run plus a fix round. When a red test shows a plausible actual value, suspect the expected value or the fixture first. Where an exact count is fragile, assert a range. Formula-dense code (matrix math, geometry, shaders, contact solvers): transcribe implementation and expected values from one known-good reference in a single pass; cap convention research (axis signs, coordinate frames, vendor quirks) at one search round plus one fetch, then derive once, freeze, record as an assumption.
- Modules that touch browser APIs cannot run under plain Node: define `document`/`OffscreenCanvas`/2d-context shims in the first draft of any such probe. With a mock or recorder harness (Proxy-based GL context, call log), print one sample record before asserting on indices or tuple positions; a harness failure means the harness is wrong, so fix the harness and never change production code based on it. Delegate reference research and browser checks (dev server on an uncommon port, console error scan, kill the server and leave the repo clean) to background subagents in the planning block; never let two agents run npm or git commands in the same worktree. Headless Chromium WebGL needs the flag `--use-angle=swiftshader`; if the page under test does not wire a renderer, import and call the renderer factory directly from page context.
