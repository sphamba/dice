# developer: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets (repo structure, build/test tips). Never edit this file as the role agent.

- Stack: Vite + Vitest, ESM (`"type": "module"`). Scripts: `npm run dev`, `npm run build`, `npm test` (= `vitest run --passWithNoTests`). Tests sit next to sources as `src/**/*.test.js`; Vite and Vitest share `vite.config.js` (relative `base`, node test env).
- Tasks run in git worktrees under `.worktrees/<branch>`; `main` is the default branch. Give empty scaffold dirs a `.gitkeep` file.
- Fresh worktrees have no `node_modules`. `npm ci` against the lockfile is routine: run it once in the background with output redirected to a log, and read or write code while it runs; never spend a block idle-waiting or re-checking it. "Cannot find module vite/vitest" at startup means a missing install, not broken code.
- Installing new dependencies: redirect output to a log (`npm install --loglevel=http > /tmp/npm.log 2>&1`), never a bare install against a long timeout. `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true`; versions younger than a week are invisible to resolution and can hang installs in a retry loop, so check `npm view <pkg> time` before version floors. On failure, read the log and `cat ~/.npmrc`; verify hypotheses with cheap metadata (`npm view`, `npm ping`), not blind retries.
- Decide the deliverable, every internal file placement, and every cross-module data contract in the first planning block. If a contract belongs to a module another task will add, state the assumed contract on the task card and move on. Do not grep sibling branches or worktrees to pre-empt their design, do not relitigate placement mid-run, and do not adjudicate design questions the card does not ask about; record those as assumptions on the card.
- Batch independent calls in one block: source reads, `git status`, and test runs do not depend on each other. Do not serialize them and then re-plan, and do not spend a thinking block choosing between background and timeout for a routine command.
- Never re-run a failing test suite until you have changed something (code, test, or config); batch the fix and the rerun into one step. After writing a module, run its suite at once instead of a self-review thinking pass: the run answers name, spelling, import, and load-behavior questions in one step.
- Use `Float64Array` for math and physics state, and Float64 in test expectations. Float32 storage rounds constants and breaks tight assertions. Pick the precision once, up front, for the whole module family, and prefer relative tolerances (for example a `nearRel` helper) over absolute 1e-12 for accumulated sums.
- In tests, derive expected values from the imported module constants (caps, fixed dt, gravity, damping) instead of restating literals or mental arithmetic; where an exact count is fragile, assert a range. Write tests only against the planned public API of the module, and never invent helper properties or placeholder exports that no module provides. In test-first work, an import-resolution red for a module you have not written yet is the expected first red; write the module next, do not investigate it.
- Load kanban tools via tool_search ("kanban") during initial recon, not at the end. Record assumptions, versions chosen, and verification results on the task card in one update at the end.
- Commit the lockfile; `npm ci` needs it. Never commit TASK.md, AGENTS.md, or `.kanban/`; their tracking status is settled, so do not re-check it. Default to one commit per card when tests and implementation land together, and do not spend planning turns on commit granularity.
- Clean-room acceptance before finishing: `git archive HEAD | tar -x -C /tmp/check`, then run `npm ci && npm test && npm run build` in the copy, confirm `dist/index.html` references relative asset paths, and remove the copy afterwards. This validates the committed tree without touching the worktree's `node_modules`.
- actionlint is not installed. Validate workflow YAML with `python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" <file>`. Verify GitHub Action majors against their release tags, not memory. Reuse the existing workflow in `.github/workflows/` when one exists.
- Implement small, self-contained logic tasks (pure modules, unit tests, verification) directly in this role. Delegate to subagents only browser checks (dev server on an uncommon port, desktop plus mobile viewports, console error scan, concrete layout or rendering assertions, subagent kills the server and leaves the repo clean) and independent work that can run in parallel. While a subagent runs, do unrelated local work; block on `get_subagent_result` only when truly blocked. Never let two agents run npm or git commands in the same worktree at the same time.
- For pure logic, go test-first: write the test, run to red, implement, run to green.
- For formula-dense code (matrix math, projections, physics), pick one known-good reference and transcribe both the implementation and the expected test values from it in a single pass. Do not hand-derive expected values from memory or from a closed-form shortcut that differs from the code's actual recurrence. When a new test is red, compare the expected value against the reference first, and change the code only after the reference confirms the test is right.
- Cap convention research for platform or standards behavior (axis signs, coordinate-frame rotation, vendor quirks): one search round plus one fetch attempt. If the source does not state the mapping outright (specs often defer to other specs, and grepping spec HTML returns CSS noise), stop consulting sources. Derive the mapping once, freeze it as an input-to-expected test table, note platform differences as an assumption on the task card, and move on. Never spend a second thinking block re-deriving the same convention.
- A failed tool call (missing or invalid argument) is fixed by re-issuing the corrected call in the next block; do not spend a thinking block re-planning around it.
- Shell trap: `ls` or `cat` on missing paths exits non-zero and prints to stderr; treat this as noise, not failure. Use `ls -a` to confirm dotfiles such as `.gitkeep`.
