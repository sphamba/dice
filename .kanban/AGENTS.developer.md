# developer: project guidance for future agents of this role. The doctor rewrites this file after every run and keeps only durable, task-agnostic bullets. Never edit this file as the role agent.

- **Startup trio, first block, exactly three parallel invokes:** the `tool_search("kanban")` call (or the kanban read tool if `tool_search` is absent — settle tool availability from the tool list itself, never in a thinking block), the TASK.md read, and the worktree bash of the next bullet. Issue tool calls in parallel whenever no call consumes another's output.
- **Worktree startup, one bash call, before any source read.** Worktrees live in `.worktrees/<branch>` and track `main`. One call runs: `cd <worktree> && ls -a && if test -d node_modules; then echo 'deps: present'; else echo 'deps: install started'; (npm ci > /tmp/npm-ci.log 2>&1 &); fi ; git merge --ff-only main; git log --oneline -1; git status --short; ls; ls src/*/`. Read the install-state echo from the output; never re-derive it. A failed `git merge --ff-only main` means divergence: never retry a merge (the merger role owns merges) — record one Blockers line and continue. The shape is mechanical from this output plus the prior notes: verification-only when the tree is clean, `main` is up to date, and the notes report the deliverable complete with green evidence; implement on a first run, an incomplete or silent card, or a dirty tree. State the shape as one lead-in line on the next tool call, never in a thinking block. Never re-run startup facts, never grep source to pre-confirm a deliverable the notes already report, never investigate branches or empty log ranges. Parallel tasks land on `main`; after a late merge, re-read code before editing.
- **Turn budgets, per shape.** Verification-only (HEAD holds the deliverable): startup trio, one chained bash, one `kanban_update`, final text; zero thinking blocks — this file is the plan, and the bash, in order, is: `tail /tmp/npm-ci.log` only when the startup echo said install started, the card-pinned acceptance command verbatim, then `npm run build` plus the asset check unless the deliverable is test-only. Prior notes are the evidence of record: never audit, re-derive, or re-probe their claims. Implement: startup trio, one planning block, one batched read block, write, one scoped verify, commit, live check if the card pins one, `kanban_update`, final text. A fix adds one expected red→green cycle, preceded by the premise probe when the card pins a numeric effect; every further round names the rule that justifies it. End-of-run order is fixed: green evidence → commit → launch any live check → `get_subagent_result(wait:true)` as one bare call → `kanban_update` (wrap-up reasoning goes into the card notes) → short final text → stop. A block between the green run and the card update is a breach. A checkpoint that blocks on a card write gets one mechanical call with the notes as they stand.
- **Batch reads — never one read per block.** In the turn right after the startup trio, one lead-in line, then one block of parallel `read` calls covering every file the change touches: each module under change, its `.test.js`, and every module defining data the assertions use, whole under ~400 lines; targeted partial reads ride the same batch. A batch announced in a planning block is a batch sent in the next block. A file that surfaces later joins the next batch; it never starts a solo chain. Self-check on every read block: after two read-only blocks with no edit sent, every still-unread file goes out in one batched block — solo read chains are the largest recorded time sink in this role and they recur. Read each file at most once per run, with `read`, not `cat`. A steer or review note never invalidates in-hand contents: the one reconciliation is a single `git diff` read, then resume the plan. A truncated read does not count as having the file: batch re-read its target regions before editing it. After compaction, batch re-read every file an edit will touch — memory is stale.
- **Edit discipline.** All changes to one file are one `edit` call in one block. `oldText` is the current file text; keep it to a few unique anchor lines; unique means unique in the whole current file. Copy `oldText` from a fresh read or a verbatim `grep -n` of the exact lines — indentation and whitespace byte-for-byte, never from memory of an early or truncated read. Edit calls are atomic: a rejected call applied nothing, so the retry is one call resending the whole corrected set — no verification grep, no partial-application check, no thinking block. The block after a rejected edit is one corrected-anchor retry, no analysis; when the same anchor fails twice, the next block is one grep printing the target lines verbatim, then one resend with that text unchanged. Never append to an edited file with a bash heredoc. Before sending an edit, verify every symbol `newText` references is imported or defined in that file, that no duplicate object key is left behind, and that module-level statements sit below every declaration they reference. After a multi-function edit the scoped suite runs before the next edit. A deletion, rename, or signature change greps every callsite once in the planning block and moves all consumers in the same pass. Trust edit success: the suite is the re-check, never a re-read of fresh output. A newly added setup or builder function needs a callsite before commit — grep each new symbol's uses in the verify block; a zero-use grep on a non-entry-point symbol is a defect. A fallback path masks a dead real path: prove the real path ran (one-shot console marker or an assertion), and surface the marker to the live check.
- **Planning discipline: one planning block settles everything.** Shape, deliverable, placement, data contracts, test scope (trivial → skip tests; new feature → tests first; refactor → tests before code; fix → probe-validated failing test first). A numeric acceptance criterion freezes its metric, fixture, seeds, and aggregation in that same decision list before the first probe; a metric re-chosen after the first probe means the criterion was never parsed — reread the card line once, freeze, move on. End with the decisions listed one line each; a decision absent from that list is settled by the next block's one grep or probe, never by more weighing. Issue the greps the plan depends on inside the planning block or the next batched block. Later blocks amend the decision list only with a new grep or probe fact, stated in one lead-in line. Freeze every derived convention (sign, axis, units, fraction, threshold, coordinate space, row order) once as an input→expected table and never re-derive it. A numeric, geometric, or compositing question still open after one thinking block becomes a probe command in the next block; a second speculation block on the same question is a breach. Keep a thinking block short enough to finish: a truncated block is lost work — move the derivation into a probe script or the card notes. A thinking block never restates card text, task lines, or lead-ins already given. Ambiguous wording: decide once, record the assumption on the card, move on. Never spend a block weighing whether an action breaches a rule — act on the mechanical recovery instead.
- **Premise probes before effect tests.** A card that pins a numeric effect of a constant change states a hypothesis until measured. After the planning block, one A/B probe runs both variants — old and new constant — over the card's own scenario, seeds, and metric, and prints both aggregates. A delta inside run-to-run noise kills the premise: record the Open question, skip the red test, and never build acceptance tests, sweeps, or patch/revert ceremonies around a dead premise. One A/B sweep decides; a null is a finding — never re-measure it. Compare variants by probe parameter or by a /tmp copy of the module; never flip-flop a source constant with `git stash`, `git checkout`, or `sed` mid-run. A pinned threshold the A/B proves unachievable is decided once: keep the code change, leave the pinned test red, record both measured numbers as an Open question.
- **Red runs and failure triage.** A fix ships a red test before the code change, and the fixture is validated first: one probe run with the exact test setup proves the symptom reproduces before the regression test is written. An expected-red test that reports green is a fixture miss: the next block is one probe that sweeps the fixture axes; swap it in and rerun. The first red run runs untouched production code. A red caused by a syntax error, a dangling name, or a wrong-module import is not evidence: repair in one edit and rerun without analysis. A failure showing NaN or out-of-bounds indexes in fresh grid, atlas, or geometry code is index-space mixing — absolute versus cell-local coordinates, canvas rows versus output rows, flipped versus unflipped — so align the test's decode with the module's mapping in one edit, no hypothesis chain. Before a test imports production symbols, one grep of the sibling modules' exports settles each symbol's home module in the same block. Write expectations in final form on the first pass. On a failing run, one command prints every failing test's full output first — no `tail` or `grep` filter on that first failing run; if a filter ate the detail, one rerun with full output next block, sent without deliberation. After a failed command, the next block is one tool call that gathers the missing evidence, never a plan revision. Then analyze fully, batch fix and rerun into one step; if the identical failure persists, re-read the edited region before new hypotheses. Never run the same suite twice without an intervening change; green closes it. No hypothesis names test order, parallelism, gravity, or fixture reuse before the failure output is read. Vitest default timeout is 5 s; pass an explicit one for long simulations and keep `expect` out of per-step loops.
- **Fixture and assertion robustness.** Derive fixture layout from geometry constants before writing the test: spacing derived from body geometry survives scale changes — absolute gaps do not. Test bodies come from the project's own factories, never hand-written literals: read containment, sleep, and step early returns before asserting what they do. Never assert a threshold exactly at the boundary accumulated steps reach — use an absolute floor; assert one step before and one past the window. A multi-body settle test asserts rest, containment, and finiteness. A physics outcome with legitimate variance gets one aggregate assertion over seeded cases, thresholds from one probe over the same seeds. Clear per-frame accumulators before asserting a single step's output; count only contact depth > 0. A source-pattern assertion pins an exact string copied verbatim from the card's Change section. An assertion that failed twice on fixture grounds is demoted to the robust form in the next edit, never a third fixture re-tune. A production constant changed to make a marginal assertion pass is a threshold decision: one sweep over the failure metric, recorded on the card.
- **Stack and shell traps.** Vite + Vitest, ESM (`"type": "module"`). Scripts: `npm run dev`, `npm run build`, `npm test`; call pinned scripts, never `npx <tool>` (the one exception filters a single test: `npx vitest run <file> -t '<name>'`; a card-pinned command overrides). Tests sit next to sources as `src/**/*.test.js`; Vite and Vitest share `vite.config.js`. The build parses only modules reachable from `main.js`; parse-check anything else with `node -e "import('<path>')"`. Log installs (`npm install --loglevel=http > /tmp/npm.log 2>&1`); `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true` — check `npm view <pkg> time` before version floors. Piping to `tail` or grepping test output masks the exit code: `set -o pipefail` first, or judge green from the reporter line. `pkill`/`pgrep -f` match their own command line: use a bracket pattern (`pkill -f '[v]ite'`) or PIDs you own, and fold cleanup into the next verification bash. A zero-hit grep on one file: rerun directory-wide in the same block. Prefer `grep -oE`; check an awk field separator against one input line before reading its output.
- **Build evidence rules.** A change confined to `*.test.js` never enters the build graph: skip `npm run build` and the asset check, and say so in one lead-in line. A fresh build's hashed asset name proves nothing. The one asset check: after a green build line, run `grep -oE '(src|href)="[^"]+"' dist/index.html` once, chained in the same bash. After a failed build the on-disk `dist/` is stale: skip the grep or mark it stale on the card.
- **Git rules.** Code changed and tests green → one commit, lockfile included when deps changed. Verification-only on a clean tree → no commit, card only. Never commit TASK.md, AGENTS.md, or `.kanban/`. Settle ignore/tracked questions with one `git status` plus one `.gitignore` read in the same block. Clean-room acceptance, only when committed code changed: `git archive HEAD | tar -x -C /tmp/check`, then in the copy `npm ci ; npm test ; npm run build` separated by `;` never `&&`; on failure read the log tail; then delete the copy. Sibling-task dependency: stage exactly the named files with `git show <ref>:<path> > <path>`; never stage the sibling's tests, never merge the branch, never write a shim; verify against the copy, remove it in the commit block, record it on the card; on a ref error run `git branch --list '*<fragment>*'` once in the same block and retry. A dependency decision is closed once made; only new tool evidence reopens it.
- **Card notes.** Compose from the TASK.md copy read at startup, changing only the lines new evidence changes. In the commit block write a notes draft — deliverable line, evidence lines with counts, the HEAD short hash, assumptions, blockers, open questions — to `/tmp/run-notes.md`; after a context compaction compose the final notes from that file, never from recalled memory, and recovery from compaction is at most one recall call for the startup context — a second recall on the same gap is a breach. Fixed sections: Deliverable / Verification / Assumptions / Blockers / Manual checks left to other roles; placement is never debated (a merge divergence is a Blockers line, an out-of-scope defect is an Assumptions note). The verification line names the HEAD short hash. Numeric lines come from recorded probe output. Never re-enumerate deliverables, exports, or test counts when prior notes carry them. `kanban_update` replaces the whole notes field, so carried lines are resent verbatim. One call per run, sent once after green; resend only for a factual error. After it returns, the run is closed — never re-read the card to audit wording.
- **Subagents and live checks.** A background `Agent` call returns at once; `get_subagent_result(wait:true)` blocks the turn as one bare tool call next turn — never in a thinking block. Batch independent calls into the launch turn. The launch text is self-contained: it inlines browser flags (`--use-angle=swiftshader`), the `chrome-headless-shell` fallback, dev-server port, repo paths, probe locations, and the full assertion list — the subagent never reads this file or the worktree context. Delegate reference research in the planning block; launch browser checks only after the scoped suite, build, and commit are green, and only for acceptance criteria that name them. One check runs every scenario and reports each independently. Fix all reported defects in one edit pass, then one re-check; never interleave per defect. Check contract: dev server on an uncommon port, console error scan, probe scripts under `/tmp`, server killed, port or PID reported back, repo left clean. Never let two agents run npm or git in one worktree. Live checks use `playwright-core` with the cached browser in `~/.cache/ms-playwright` — locate it in one command. Full Chromium can crash at launch: fall back to `chrome-headless-shell` once, do not debug it.
- **Stop rule.** A green scoped run is the evidence; report the pass count and move on. After green, edit only to fix a real defect; post-green cleanups go to the card notes, never into the tree. No thinking block sits between a green run and the commit; act on a settled rule in the next tool call with its one-line lead-in. Batch hygiene (dead code, unused imports, debug leftovers) into the same edit pass as the last functional change. Never expand scope to justify the run. After `kanban_update`, the run ends — no post-send block of any kind.
- **Test environment and UI.** jsdom under Node exposes only some browser globals (no `AudioContext`, no `navigator.vibrate`): feature-gate browser APIs on the function (`typeof navigator.vibrate === 'function'`). Design fakes as minimal recorders (settable clock, call log, injectable functions); print one sample record before asserting on indices or tuples; a harness failure is a harness bug. A fake input event carries the exact coordinates the production code reads; a quantity assertion recomputes from the same event data the code saw, never from the test's intent. If unsure what the environment provides, probe once (`node -e "console.log(typeof navigator, typeof AudioContext)"`) in the same block as the test draft. DOM: `setAttribute('aria-label', ...)`, never `element.ariaLabel`; never attach custom properties to DOM nodes; a builder returns `{ element, sync }` pairs and one `syncAll` refreshes them.
- **Physics and numeric probes.** Replicate the production step sequence exactly. Validate the fixture before trusting any measurement: drop-and-settle or clean spawn, then confirm rest-state drift is ~zero over N steps — a body spawned at rest height with a random orientation intersects the floor and solver kicks masquerade as the effect under test. A probe samples at the same point in the run as the assertion it supports. Probes import project modules by absolute path; a `/tmp` probe with relative `./src` imports dies before it runs. When a magnitude is implausible, print the whole value chain (input → constant → derived); suspect a scale applied twice, a per-unit vs total mix-up, or an argument in the wrong slot. Gate contact or normal signs on signed approach velocity (`v·n < 0`), never absolute speed. Never suppress errors. A spec-suggested mechanism is a hypothesis: the instrumented probe printing the value chain at the failure site goes out before the hypothesis is written. One probe per hypothesis; two dead hypotheses mean the probe measured the wrong thing — change the measurement, never add hypotheses. Sweep a parameter only against a validated fixture; when sweep results contradict a derived expectation, suspect the fixture before the formula. Tuned constants come from a sweep: the smallest value with zero failures, unexported with a one-line unit comment. Temporary copies: copy to `/tmp`, restore or delete in the same bash block chained with `;`.
- **Numeric traps and precision.** Unary minus on a typed array yields `NaN`, not element-wise negation. After any sign flip or formula edit in vector math, print one concrete derived vector from a `node` probe before rerunning the suite. When two mathematically equivalent forms disagree, print both from the same inputs in one probe; never alternate edits hoping the suite turns green. `src/math/` holds vec3/mat3/quat/mat4 helpers, out-param style (`add(out, a, b)`, column-major); grep the module's exported names before first use; never alias `out` with an input. JS-mirror tests never reuse the Float32Array-backed helpers to compute expected values: build mirrors from plain numbers and compare with ~1e-6 relative tolerance; a mismatch at the 8th decimal in fresh geometry code is a precision signature, not a logic bug. Use `Float64Array` for math state, relative tolerances for accumulated sums. Compute expected values through the module's own helpers with a one-line `node -e` script in the same block as the assertion — never mental arithmetic. Quantities that physics lets collide tie legitimately: assert ordering non-strictly unless the spec demands strictness.
- **Reference math, operators, shaders.** Delegate reference research (GLSL, ported algorithm math, published formulas) to a background subagent in the planning block; while it runs, build research-independent scaffolding. Transcribe its formulas verbatim; make JS-mirror tests check transcription against the reference's own worked cases; never re-derive a fetched formula in a thinking block — a suspected contradiction is a transcription or unit bug: print the value chain from the reference's worked case in one probe, fix the transcription. Cap: one research round, one transcription pass, one mirror test. Any operator assembled by hand gets a write-time identity check in the same block as the write: apply it to one concrete state and print achieved-minus-requested. A library convention used for the first time is settled by one probe at first use and frozen. Shader sources ship with a frozen validation recipe: one node script extracts each template-literal source to /tmp files, then one chained bash runs `glslangValidator -S vert <f>.vert` and `-S frag <f>.frag` per stage plus `-l <vert> <frag>` per pair — every stage and pair reports in that one run.
- **Visual symptoms and live state.** Evidence before hypotheses: batch the screenshot read with the camera and shader reads in one block, then give the verdict in the next block; a second weighing block on the same artifact is a breach, and an artifact that matches the expected shading math is recorded as expected behavior on the card, never re-litigated. A reported visual symptom is a measurement claim: first check what the camera projection can show — an orthographic view collapses one axis, so screen-space math cannot see a symptom defined along that axis. Headless sweeps that fail to reproduce a live symptom neither disprove it nor localize it: after two dead sweeps, stop sweeping and instrument the live page — add a temporary hook (`globalThis.__world = world`) in the entry module, drive the real page, read engine state per frame; remove the hook in the commit block. Headless probes read the owning module or its test first; a FAIL on an invented expectation is a probe bug. An intermittent or pre-existing console error outside the deliverable: one repeat run confirms it is intermittent, then it goes on the card as an out-of-scope note — never a fix debate.
