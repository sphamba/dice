# developer: project guidance for future agents of this role. The doctor rewrites this file after every run and keeps only durable, task-agnostic bullets. Never edit this file as the role agent.

- **Startup trio, first block, exactly three parallel invokes:** the kanban read tool (settle tool availability from the tool list itself, never in a thinking block), the TASK.md read, and the worktree bash of the next bullet. A call that consumes another's output waits one turn.
- **Worktree startup, one bash call, before any source read.** Worktrees live in `.worktrees/<branch>` and track `main`. One call: `cd <worktree> && ls -a && if test -d node_modules; then echo 'deps: present'; else echo 'deps: install started'; (npm ci > /tmp/npm-ci.log 2>&1 &); fi ; git merge --ff-only main; git log --oneline -1; git status --short; ls src`. Read the install-state echo from the output, never re-derive it. A failed `git merge --ff-only main` is one Blockers line, never a retry, the merger role owns merges. The run shape is mechanical from this output plus the prior notes: verification-only when the tree is clean, `main` is current, and the notes report the deliverable complete with green evidence; implement on a first run, an incomplete or silent card, or a dirty tree. State the shape as one lead-in line on the next tool call, never in a thinking block. Never re-run startup facts, never grep source to pre-confirm a deliverable the notes report, never investigate branches or empty log ranges. After a late merge, re-read code before editing.
- **Planning block before any source read, and it freezes the convention table.** Shape, deliverable, placement, test scope (trivial → skip tests; feature → tests first; refactor → tests before code; fix → probe-validated failing test first). A numeric acceptance criterion freezes metric, fixture, seeds, and aggregation before the first probe. A visual acceptance criterion freezes the analyzer, crop geometry, and the variant matrix before the first probe. Freeze every derived convention once as an input→expected table: sign, axis, units, threshold, coordinate space, order, and the unit semantics of named constants (circumradius vs half-extent, per-type vs global). A constant's meaning re-derived mid-run is a breach; one grep of its definition settles it. Numeric layout and placement factors (label centers, fit boxes, glyph sizes, margins) are settled by one sweep script that prints the metric per candidate, never by feasibility algebra; the sweep prints one known-input check beside the metric, and all-zero or always-true output is broken plumbing, fixed and rerun in one block. Any numeric, cost, or design question still open after one thinking block becomes a probe command in the next block; a second speculation block on the same question is a breach. Keep thinking blocks finishable: move derivations into probe scripts or card notes. Never spend a block weighing whether an action breaches a rule, run the mechanical recovery. End with the decisions one line each plus the list of files every later read and edit will touch.
- **Batch reads: one parallel block, directly after the planning block.** In the turn after planning, one lead-in line, then one block of parallel `read` calls covering the named list: each touched module, its `.test.js`, package.json/config when dependencies, scripts, or test setup matter, every module defining data the assertions use, and every module a touched module imports (helpers, math, config, shader sources), whole files under ~400 lines. The recorded failure mode is reading one file per turn to decide what to read next, and a second read wave trickling across later turns: both are this role's recurring top time sinks, so a read issued outside a batch block is a breach, and a file that surfaces later joins the next batch, never a solo chain. Read each file at most once, with `read`, not `cat` or `sed` prints; an edit anchor is located by one verbatim `grep -n`, not a re-read. Two separate slices of one file in different blocks are one wasted block. A truncated read does not count as having the file: batch re-read its target regions before editing. After compaction, batch re-read every file an edit will touch.
- **Edit discipline, and structural changes go in stages.** All changes to one file are one `edit` call in one block. `oldText` comes from a fresh read or a verbatim `grep -n` of the exact lines, never from memory. Edits are atomic: a rejected call applied nothing, the retry is one call resending the whole corrected set, no verification grep, no thinking block. A reported-successful edit is in the file, and doubt never earns a block. The scoped suite is the proof. Replacing a literal with a named constant greps the old literal across `src/` in the same block and moves every callsite in the same pass. When the same anchor fails twice, the next block is one grep printing the target lines verbatim, then one resend with that text unchanged. Never append to an edited file with a bash heredoc. Before sending, check every symbol `newText` references is imported or defined, no duplicate declaration is left, and module order holds; a SyntaxError from a self-inflicted duplicate or stray paren is one read of the edited region plus one fix call, no deliberation. A deletion, rename, or signature change greps every callsite once in the planning block. Structural changes to selection, scoring, or ranking logic land in stages, each stage with the scoped suite green before the next stage starts; only a measured defect justifies changing logic that currently passes its suite. When a structural edit turns a green suite red, the first step is reverting that file to the last green stage (git stash or checkout of the single file), then re-applying in smaller steps, never a new hypothesis on top of a broken stage.
- **Turn budgets and fixed run order.** Verification-only: startup trio, one chained bash (install-log tail only when the echo said install started; card-pinned acceptance command verbatim; `npm run build` plus the asset check unless the deliverable is test-only), one `kanban_update`, final text, zero thinking blocks. Implement: startup trio, one planning block, one batched read block, edits, one scoped verify, commit, card-pinned live check, `kanban_update`, final text; a fix adds one red→green cycle, and every further round names the rule that justifies it. End-of-run order: green evidence → commit → live-check launch → `get_subagent_result(wait:true)` as one bare call → `kanban_update` (wrap-up reasoning goes into the card notes) → short final text → stop. The run ends when `kanban_update` returns. If the harness re-invokes afterwards with a cleared or empty Notes field, the recovery is mechanical: one read of `/tmp/run-notes.md`, one `kanban_update` with those notes, one final line, stop; never re-run tests, rebuild, or re-verify work the run already proved, and a second recovery cycle is a breach. No thinking block sits between a green run and the commit: commit-message composition goes in the lead-in of the commit bash. No block of any kind sits after `kanban_update` returns. Never expand scope to justify the run.
- **/tmp probes: one heredoc write, proven plumbing, validated probe.** Write the whole probe file in one `cat > /tmp/x.mjs <<'EOF'` heredoc with real absolute import paths baked in; never build a probe from shell placeholders or template substitution, and never patch probe or harness content with sed or python replaces (sed may rewrite one-line import paths only): unresolved placeholders, unescaped `&`, stray parens, and duplicate declarations in patched copies cost more blocks than probes save. Chain probe steps with `;` after any grep, never `&&`: a zero-hit grep exits 1 and silently skips the write. Probes import project modules by absolute path; a relative import dies before it runs. Prove plumbing in the same block: one import check (`node -e "import('<copy>').then(() => console.log('import ok'))"`), one grep proving the patched line is present, and for an instrumented copy one print proven to fire on a case known to reach the branch; when outputs can interleave, run one case per process. When a probe prints NaN, impossible units, or absurd magnitudes, suspect the probe first: wrong helper signature, missing argument, a helper applied to the wrong type, a wrong default fixture value. Validate the probe on one trivially known input before trusting it against production code; a probe bug is never production evidence. Temporary copies are deleted in the same block or in the commit block.
- **Probes, fixtures, and oracles come before conclusions.** A card that pins a numeric effect states a hypothesis until measured: one A/B probe runs both variants over the card's scenario, seeds, and metric and prints both aggregates; a delta inside run-to-run noise kills the premise, record the Open question, skip the red test. Compare by probe parameter or a /tmp copy of the module, never flip a source constant mid-run. An evidence pair (before/after, with/without) comes from one harness run that takes the variant as a parameter, so both sides share fixtures, crops, and metric code; a missing baseline is never manufactured with a stash-rerun-unstash cycle, which is a source flip plus a wasted full re-run. A pinned threshold the A/B proves unachievable is decided once: keep the code change, leave the test red, record both numbers as an Open question. An exactness or reference test needs one independent oracle: the simplest correct one (brute force over a fixture small enough), chosen in the planning block, never redesigned mid-run; slow oracle runtime earns one timing probe, then an explicit vitest timeout, never helper optimization. Pin every numeric expectation from the oracle or probe output with the default reporter tolerance; a hand-tuned epsilon that fails on precision grounds is replaced once by the probe-measured value, never re-tuned twice. Validate every hand-picked tolerance, radius, or epsilon from one probe that prints the real worst case on the real fixture before the red run ships. Keep `expect` out of per-pixel and per-step loops: accumulate the worst case, assert once. Randomized fixtures validate inputs first: one print of worst-case orientations and points before any sweep, and check quaternion norms. Seed every trial independently; before a sweep rests on a seeded helper, one line proves the helper consumes the seed. Test bodies come from the project's own factories, never hand-written literals. Never assert a threshold exactly at a boundary accumulated steps reach. An assertion that failed twice on fixture grounds is demoted to the robust form, never re-tuned a third time. A production constant changed to pass a marginal assertion is a threshold decision: one sweep, recorded on the card.
- **Red runs and failure triage.** A fix ships a red test before the code change, and one probe with the exact test setup proves the symptom before the test is written. An expected-red test reporting green is a fixture miss: the next block is one probe that sweeps the fixture axes, swap it in and rerun. The first red run runs untouched production code and prints every failing test's full output, no filter on it. A red that already printed its assertions needs no rerun to capture names: any second run of the same suite without an intervening change is a breach. After a failed command, the next block is one tool call that gathers the missing evidence, never a plan revision. Then analyze fully, batch fix and rerun into one step. If the identical failure persists, re-read the edited region before new hypotheses. When failures follow a multi-file change set, the first diagnostic is one stash-based A/B per suspect file (baseline HEAD vs working tree over the failing suite), run before any hypothesis churn. A passing test whose premise the change invalidated (a pose the new geometry cannot reach, a helper measuring a surface the spec no longer names) is re-posed and re-pinned from one probe in one edit pass, together with every helper definition that shares the measure, and is never re-probed from the old pose. Green closes it.
- **Root-cause escalation is mechanical.** One probe per hypothesis, and two dead hypotheses mean the probe measured the wrong thing: change the measurement, never add hypotheses. A hypothesis killed by reasoning alone counts as dead: the limit does not reset because no probe ran. The measurement of record is a per-phase instrumented script (hook or copy the step pipeline and print state after each phase at the failing frame). It goes out after the second dead hypothesis, not a third speculation block. When the suspect code is a measurement or analysis script, the escalated probe is a standalone Node reproduction of its math on synthetic input with known answers. Reproduce symptoms with your own minimal fixture: other roles' logs and harnesses are context at most. When sweep results contradict a derived expectation, suspect the fixture before the formula. When a held or supported body rests with near-zero velocity and a fixed offset, list contacts and containment geometry first. Tuned constants come from one sweep: smallest value with zero failures, unexported, one-line unit comment. A spec-suggested mechanism is a hypothesis: the instrumented value-chain probe at the failure site goes out before the hypothesis is written.
- **Physics and numeric probes.** Replicate the production step sequence exactly. Validate a fixture's rest state first: a body spawned at rest height with a random orientation intersects the floor, and solver kicks masquerade as the effect under test. A probe samples at the same point in the run as the assertion it supports. When a magnitude is implausible, print the whole value chain (input → constant → derived) and suspect a scale applied twice, a per-unit vs total mix-up, or an argument in the wrong slot. Gate contact or normal signs on signed approach velocity (`v·n < 0`), never absolute speed. When the spec names an offset surface (a rounded or inset shape), helpers and probes measure the offset surface (base point plus the named offset), not the base hull, which can overshoot the surface by up to twice the offset. Never suppress errors.
- **Hot-path cost is a regression, not a tradeoff.** A rewrite that multiplies per-item work inside a hot loop (broadphase, per-step, per-pixel, per-contact) is a performance defect even when numerically correct. Keep cheap early-exit gates (distance culls, separation tests, deduplicated candidate directions) in front of any exhaustive enumeration (all edge pairs, all feature pairs). A suite that jumps from sub-second to tens of seconds is triaged as a cost bug with one timing probe, not accepted and not tuned around; the fix is a cheaper gate or fewer candidates, never a weaker test.
- **Numeric traps.** Unary minus on a typed array yields NaN, not element-wise negation. Indexing a typed array with a fractional or negative value yields `undefined`, and the NaN surfaces far from the bad line: round and wrap every array index before use, and when one report field prints null/NaN while its neighbors print fine, grep the producer for unrounded indexing first. After any sign flip or formula edit in vector math, print one concrete derived vector from a probe before rerunning the suite. When two mathematically equivalent forms disagree, print both from the same inputs in one probe. `src/math/` holds vec3/mat3/quat/mat4 helpers, out-param style (`add(out, a, b)`, column-major); grep exported names and signatures before first use and never alias `out` with an input. JS-mirror tests never compute expected values with the Float32Array-backed helpers: build mirrors from plain numbers, compare with ~1e-6 relative tolerance. A mismatch at the 8th decimal in fresh geometry code is a precision signature, not a logic bug. Use `Float64Array` for math state. Compute expected values through the module's own helpers with a one-line `node -e` script in the same block as the assertion, never mental arithmetic. Quantities that physics lets tie assert ordering non-strictly.
- **Stack and shell traps.** Vite + Vitest, ESM (`"type": "module"`). Scripts: `npm run dev`, `npm run build`, `npm run preview`, `npm test`; the one `npx` exception filters a single test, a card-pinned command overrides. Tests sit next to sources as `src/**/*.test.js`, and Vite and Vitest share `vite.config.js`. The build parses only modules reachable from the entry: parse-check anything else with `node -e "import('<path>')"`. Log installs (`npm install --loglevel=http > /tmp/npm.log 2>&1`). `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true`, so check `npm view <pkg> time` before version floors. Piping test output through `tail`/`grep` masks the exit code: `set -o pipefail` first, judge green from the reporter line, and write machine-readable probe and harness output to a file in the producing block, never recover it from filtered stdout; re-running a harness to recover a number lost to console truncation is a breach. A zero-hit grep on one file reruns directory-wide in the same block, and never gates a following command in an `&&` chain. Never `pkill -f` a broad pattern (vite, node): it matches the agent's own command line and kills the run's own process tree (exit 143, cleanup lost); kill only PIDs the run captured, or use a bracket pattern. Prefer `grep -oE` and check an awk field separator against one input line. A minified bundle inlines source literals: grep a built constant by its inlined form or verify through the served asset hash, never expect source spelling.
- **Long-lived dev servers: owned port, proven freshness.** Stale servers from earlier runs or other worktrees hold the default port and serve old code; never trust a server the run did not start. Pick a fresh port, then start detached in the same bash block as its health check: `setsid nohup npm run preview -- --host 127.0.0.1 --port <port> --strictPort >/tmp/preview.log 2>&1 &` plus a curl retry loop for 200. Bind `--host 127.0.0.1` explicitly: vite may bind IPv6 localhost only. In the same block compare the served asset hash with the local build: `diff <(grep -oE 'index-[^"]+\.js' dist/index.html) <(curl -s http://127.0.0.1:<port>/ | grep -oE 'index-[^"]+\.js')`; a mismatch means a stale server, so kill the owned PID and restart on a free port, never diagnose the app against stale output. `--strictPort` makes vite fail instead of drifting to another port silently. Capture the PID at launch and stop the server with it in the last server block of the run.
- **Build evidence rules.** A change confined to `*.test.js` never enters the build graph: skip `npm run build` and the asset check, say so in one lead-in line. A fresh build's hashed asset name proves nothing by itself; the one asset check is `grep -oE '(src|href)="[^"]+"' dist/index.html` chained after a green build line. After a failed build the on-disk `dist/` is stale: skip the grep or mark it stale on the card.
- **Git rules.** Code changed and tests green → one commit, lockfile included when deps changed. Verification-only on a clean tree → no commit, card only. Never commit TASK.md, AGENTS.md, or `.kanban/`. Settle ignore/tracked questions with one `git status` plus one `.gitignore` read in the same block. Clean-room acceptance, only when committed code changed: `git archive HEAD | tar -x -C /tmp/check`, then in the copy `npm ci ; npm test ; npm run build` with `;` never `&&`, read the log tail on failure, delete the copy. Sibling-task dependency: stage exactly the named files via `git show <ref>:<path> > <path>`, never stage the sibling's tests, merge the branch, or write a shim, verify against the copy, remove it in the commit block, record it on the card, and on a ref error run `git branch --list '*<fragment>*'` once and retry. A dependency decision is closed once made, only new tool evidence reopens it.
- **Card notes and card writes.** Compose from the TASK.md copy read at startup, changing only the lines new evidence changes. In the commit block write a notes draft (deliverable, evidence lines with counts, HEAD short hash, assumptions, blockers, open questions) to `/tmp/run-notes.md`. After compaction, and after any post-release re-invocation, compose from that file, never memory. Fixed sections: Deliverable / Verification / Assumptions / Blockers / Manual checks left to other roles. Placement is never debated: a merge divergence is a Blockers line, an out-of-scope defect is an Assumptions note. The verification line names the HEAD short hash, and numeric lines come from recorded probe output. Closing an open question folds the answer into the card field that holds it and clears the question in the same call. `kanban_update` replaces whole fields, carried lines are resent verbatim. Take the task id verbatim from the kanban tool's card list or a `kanban_get`, never hand-compose it from a slug; a rejected update is one mechanical retry with the corrected id, no deliberation. One update per run, sent once after green. Resend only for a factual error, and the deliberation about resending never earns a block, the run is closed when the update returns.
- **Subagents, live checks, and reference research.** A background `Agent` call returns at once, and `get_subagent_result(wait:true)` blocks the turn as one bare tool call next turn, never in a thinking block. Batch independent launches into one turn. The launch text is self-contained (browser flags, dev-server port, repo paths, probe locations, full assertion list), the subagent never reads this file or the worktree context. A live check with several scenarios or a measurement harness is one background Agent: the role agent writes the script and reads the report, never drives the browser across many turns. A matrix that needs a server, a browser, and per-case captures is delegated by definition: the recorded failure mode is writing that harness inline and debugging it across turns (null element lookups, stale module reloads, patch churn), and inline browser debugging past one mechanical fix is a breach. Decide the live-check design (scenarios, viewports, screenshot set, crop and metric definitions, variant matrix) in the planning block, never in a late weighing block. Delegate reference research (GLSL, ported algorithm math, published formulas) in the planning block and build research-independent scaffolding while it runs. Transcribe formulas verbatim, mirror-check against the reference's own worked cases, print the value chain in one probe. One research round, one transcription pass, one mirror test. A library convention used for the first time is settled by one probe at first use and frozen. Shader sources ship with a frozen validation recipe: one node script extracts each template-literal source to /tmp files, one chained bash runs `glslangValidator -S vert` / `-S frag` per stage plus `-l <vert> <frag>` per pair. Acceptance live checks launch only after the scoped suite, build, and commit are green, and only for acceptance criteria that name them; a diagnostic browser probe may run before the fix lands under the same /tmp harness rules, and its verdict on a suspect metric is charged to the classifier first. One check runs every scenario and reports each independently, fix all reported defects in one edit pass, then one re-check, never interleave per defect. Live checks use `playwright-core` with the cached browser in `~/.cache/ms-playwright`: verify `~/.pi/agent/skills/web-browser/node_modules/playwright-core` with one `ls` before any install search, import it from there by absolute path, run scripts from a `/tmp` harness directory, and never npm-install test tooling into a worktree. Full Chromium can crash at launch: fall back to `chrome-headless-shell` once, never debug it. Size one invocation to the tool timeout: one viewport or one scenario group per check run with progress logged to stderr. A subagent may start `npm run dev` and read files, it never runs npm ci/install or git in the worktree, and never let two agents run npm or git in one worktree.
- **Browser, visual, and pixel evidence.** Visual symptoms: batch the screenshot read with the camera and shader reads in one block, verdict in the next block, and a second weighing block on the same artifact is a breach. A reported symptom is a measurement claim: first check what the camera projection can show, an orthographic view collapses one axis. A pixel analyzer or classifier is validated before it touches a live render: synthetic fixtures with one known positive and one known negative per class, one printed sample classification, and the plumbing check that all-zero or always-true counts mean broken measurement; every hypothesis cycle spent on a suspect count is charged to the classifier, never to the production code. Build the analyzer rotation-invariant from the start, and merge same-class components split by specular rims before measuring. Crops derive from projected geometry, never hand-tuned pixel offsets, and two crops with different geometry are never compared: an empty or off-target crop is a harness bug fixed before any verdict. Anti-aliased boundaries bias measurements by one to two pixels, record as tolerance; a residual inside the recorded tolerance is noted once, never investigated across blocks. After two dead headless sweeps, instrument the live page with a temporary `globalThis` hook in the entry module, drive the real page, remove the hook in the commit block. jsdom lacks browser globals (`AudioContext`, `navigator.vibrate`): feature-gate on `typeof`, and one environment probe (`node -e "console.log(typeof navigator, typeof AudioContext)"`) rides the test-draft block when unsure. Design fakes as minimal recorders (settable clock, call log, injectable functions), print one sample record before asserting on indices or tuples, treat a harness failure as a harness bug, and use a rasterizing fake canvas to drive real pixel-baking paths. A fake input event carries the exact coordinates the production code reads. DOM: `setAttribute('aria-label', ...)`, never `element.ariaLabel`, no custom properties on DOM nodes, builders return `{ element, sync }` pairs refreshed by one `syncAll`.
