# developer: project guidance for future agents of this role. The doctor rewrites this file after every run and keeps only durable, task-agnostic bullets. Never edit this file as the role agent.

- **Startup trio, first block, three parallel invokes:** the kanban read tool, the TASK.md read, and the worktree bash of the next bullet. A call that consumes another's output waits one turn. Settle tool availability from the tool list, never in a thinking block.
- **Worktree startup, one bash call, before any source read.** Worktrees live in `.worktrees/<branch>` and track `main`. One call: `cd <worktree> && ls -a && if test -d node_modules; then echo 'deps: present'; else echo 'deps: install started'; (npm ci > /tmp/npm-ci.log 2>&1 &); fi ; git merge --ff-only main; git log --oneline -1; git status --short; ls src`. Read install state from the echo, never re-derive it; a later block that re-checks deps, merge state, or `git status` is a breach. A failed `git merge --ff-only main` is one Blockers line; the merger role owns merges. Never re-run startup facts, and never grep source to pre-confirm a deliverable value the suite or the notes report. After a late merge, re-read code before editing.
- **Planning block, one only, and it freezes everything.** Shape, deliverable, test scope (trivial → skip tests; feature → tests first; refactor → tests before code; fix → probe, red test, then code). Freeze every derived convention once as an input→expected table: sign, axis, units, threshold, coordinate space, order, constant semantics. Restate every spec number as a metric definition (quantity, units, fixture, aggregation); the probe measures that definition, never a stand-in, and a probe that cannot reproduce its definition is a probe bug fixed in the same block. Freeze the full test design before writing it: the measured quantity (point samples or bounding box, one- or two-sided band), constants, the shared measurement helper, the helpers it calls, assertions, call sites; one edit implements the whole design, and a helper added or refactored in a second pass is a breach. Freeze the measurement chain for every numeric question: which instrument measures what, in dependency order; a probe that consumes a not-yet-measured value waits for the probe that measures it. Freeze the live-check design here in full: scenarios, metric and band, synthetic fixtures with expected values, screenshot set, crops. End with decisions one line each plus the list of files every later read and edit touches. Any numeric or design question still open after this block becomes a probe command in the next block; count open questions by name, not by facet, and a second speculation block on any one of them is a breach. Derivations live in probe scripts or card notes, never re-derived from scratch mid-run.
- **Batch reads, one parallel block, directly after planning.** The task file and the startup `ls src` already name the targets: one lead-in line, then parallel `read` calls for each touched module, its `.test.js`, package.json or config when scripts and test setup matter, every module defining data the assertions use, and every module a touched module imports, plus any discovery bash (sibling dirs, entry-point greps) in the same block. A solo read of a file the task already names, in a later turn, is a breach. Whole files under ~400 lines. A file that surfaces later joins the next batch, never a solo chain. A truncated read is not having the file: re-read its target regions in the next batch. After compaction, batch re-read every file an edit touches. Edit anchors come from one verbatim `grep -n`, never a re-read.
- **Probes before algebra.** Numeric layout and placement factors are settled by one sweep or probe script that prints the metric per candidate plus one known-input check; never by feasibility arithmetic, and a value recomputed twice by hand is a breach. Browser text metrics (baseline shifts, ink boxes, advance widths) are font-dependent: one pixel-scan probe measures them before any placement sweep consumes them. Every sweep takes its tunable constants as argv, so a rerun with corrected values is one command line; a sweep that runs on an assumed value and must rerun after the real value arrives is a breach. All-zero, always-true, or NaN output is broken plumbing: suspect the probe first (wrong helper signature, missing argument, wrong fixture value), fix and rerun in one block. An A/B question is one probe that takes the variant as a parameter and prints both aggregates over the card's scenario and seeds; compare through the probe or a /tmp copy of the module, never a source flip. Keep `expect` out of accumulation loops: record the worst case, assert once. Validate every hand-picked tolerance from one probe that prints the real worst case; pin expectations from probe output, never re-tune a failing epsilon a second time.
- **/tmp probe hygiene.** Write the whole probe in one `cat > /tmp/x.mjs <<'EOF'` heredoc with absolute import paths; never patch probe content with sed or python replaces — regenerate the heredoc or pass argv. Chain steps with `;` after greps, never `&&`: a zero-hit grep exits 1 and silently skips the rest. Prove plumbing in the same block: one import check and one print proven to fire on a case known to reach the branch. A probe validates on one trivially known input before its production numbers are trusted. Temporary files are deleted in the commit block.
- **Red→green recipe, mechanical, no policy deliberation.** Fix = probe proves the symptom → red test written from probe-measured values → code change → green. If the code change already landed, prove red with one stash→run→restore cycle; the ordering is never debated. An expected-red test reporting green is a fixture miss: one fixture sweep probe, swap, rerun. A lone red after the implementation edit is a premise audit, not an implementation hunt: print the fixture's actual measured quantity first, then rewrite the side that is wrong. An assertion that bounds a produced quantity reads that quantity back from the artifact inside the test; it never assumes the fixture crosses or clears a threshold. The first red run prints every failure's full output unfiltered; a red that already printed needs no rerun. After a failed command, the next block is one call that gathers the missing evidence, then one batched fix+rerun. An identical failure twice means re-read the edited region before new hypotheses. When failures follow a multi-file change, one stash-based A/B per suspect file runs before hypothesis churn. Re-pose a test whose premise the change invalidated from one probe, together with every helper that shares the measure.
- **Edit discipline.** All changes to one file are one `edit` call in one block; nearby hunks merge into one edit, never overlapping. Anchors come from a fresh read or a verbatim `grep -n`, never memory. A rejected edit applied nothing: the retry is one call resending the whole corrected set, no verification grep, no thinking block. Check every symbol `newText` references is defined before sending; a self-inflicted SyntaxError is one read of the region plus one fix call. A rename or signature change greps every callsite in the planning block and moves them in one pass. Structural changes land in stages, scoped suite green between stages; never change logic that passes its suite without a measured defect. When a structural edit turns green red, revert the file to the last green stage, then re-apply in smaller steps.
- **Run order and budgets.** Implement: startup trio → planning block → batch reads → edits → scoped verify → full `npm test` → commit → live check → `get_subagent_result(wait:true)` as one bare call next turn → one batched read block for the returned screenshots → one verdict block → notes update → short final text → stop. After a background launch, the next turn is the bare wait call; an idle thinking block between launch and wait is a breach. Verification-only: startup trio, one chained bash (scoped suite plus the `node -e` numeric check together), `kanban_update`, final text, zero thinking blocks. A question one test run answers — will the suite stay green, does a value sit in band — is never speculated on or answered by reading test internals first; run the suite. Include every check in that bash; deliberating whether a check is worth a call is the breach. No thinking block sits between a green run and the commit; the commit message is composed in the commit bash lead-in. Never expand scope to justify the run. The run ends when `kanban_update` returns; a re-invocation with cleared notes is one read of `/tmp/run-notes.md`, one update, one line, stop, never re-verified work.
- **Root cause is mechanical.** One probe per hypothesis; two dead hypotheses mean the probe measured the wrong thing: change the measurement, never add a third hypothesis, and a hypothesis killed by reasoning alone counts as dead. The instrumented per-phase script goes out after the second dead hypothesis. Reproduce symptoms with your own minimal fixture. Physics: validate a fixture's rest state before measuring dynamics; gate contact signs on signed approach velocity (`v·n < 0`); measure offset surfaces (base plus the named offset), not the base hull. Tuned constants come from one sweep: smallest value with zero failures, unexported, one-line unit comment. Never suppress errors.
- **Numeric traps.** `src/math/` holds vec3/mat3/quat/mat4 helpers, out-param style, column-major; grep signatures before first use, never alias `out` with an input. Use `Float64Array` for math state. Round and wrap typed-array indices; unary minus on a typed array yields NaN; a fractional index yields `undefined` far from the bad line. After a sign flip or formula edit, print one concrete derived vector before rerunning. JS-mirror tests compute expected values from plain numbers, ~1e-6 relative tolerance, never from the Float32Array-backed helpers. One scripted check per numeric claim: a one-line `node -e` min/max/band script in the same block as the run that produces the numbers, never mental arithmetic, and never a second check of numbers already checked. A mismatch at the 8th decimal in fresh geometry code is a precision signature. Quantities that can tie assert ordering non-strictly.
- **Stack and shell traps.** Vite + Vitest, ESM. Scripts: `npm run dev`, `npm run build`, `npm run preview`, `npm test`; one `npx` exception filters a single test; tests sit next to sources as `src/**/*.test.js`; Vite and Vitest share `vite.config.js`. The build parses only modules reachable from the entry: parse-check anything else with `node -e "import('<path>')"`. `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true`; check `npm view <pkg> time` before version floors. `set -o pipefail` before piping test output through `tail`/`grep`; judge green from the reporter line. Write machine-readable probe output to a file in the producing block; re-running a harness to recover a number lost to truncation is a breach. A zero-hit grep on one file reruns directory-wide in the same block and never gates `&&`. Never `pkill -f` broad patterns (vite, node): it kills the run's own tree; kill captured PIDs or use a bracket pattern. A minified bundle inlines source literals: grep the inlined form or verify through the served asset hash. Prefer `grep -oE`; check an awk field separator against one input line.
- **Long-lived dev servers: owned port, proven freshness.** Never trust a server the run did not start. Pick a fresh port, start detached with its health check in one block: `setsid nohup npm run preview -- --host 127.0.0.1 --port <port> --strictPort >/tmp/preview.log 2>&1 &` plus a curl retry loop for 200. In the same block compare the served asset hash with the local build; a mismatch means a stale server: kill the owned PID, restart on a free port. Capture the PID at launch and stop the server with it in the last server block.
- **Build evidence.** A change confined to `*.test.js` never enters the build graph: skip `npm run build` and the asset check, say so in one lead-in line. After a green build, one asset check: `grep -oE '(src|href)="[^"]+"' dist/index.html`. After a failed build the on-disk `dist/` is stale: skip the grep or mark it stale on the card.
- **Git rules.** Code changed and tests green → one commit, lockfile included when deps changed. Verification-only on a clean tree → no commit. Never commit TASK.md, AGENTS.md, or `.kanban/`. Settle ignore questions with one `git status` plus one `.gitignore` read in the same block. Clean-room acceptance, only when committed code changed: `git archive HEAD | tar -x -C /tmp/check`, then in the copy `npm ci ; npm test ; npm run build` with `;`, read the log tail on failure, delete the copy. A dependency decision is closed once made; only new tool evidence reopens it.
- **Card notes and card writes.** In the commit block write the notes draft (Deliverable / Verification / Assumptions / Blockers / Manual checks left to other roles) to `/tmp/run-notes.md`; after the live check returns, update that file once with the verdict. Compose from TASK.md and that file, never memory. The verification line names the HEAD short hash; numeric lines come from recorded probe output. `kanban_update` once per run, after green; take the task id from the kanban tool's card list, never hand-composed; a rejected update is one mechanical retry; resent only for a factual error, and the deliberation about resending never earns a block.
- **Subagents and live checks.** A background `Agent` call returns at once; `get_subagent_result(wait:true)` blocks the turn as one bare tool call next turn. Batch independent launches into one turn. The launch text is the evidence contract, self-contained (ports, paths, browser flags, full assertion list, acceptance band, and the interaction model from the planning block); it states the expected value of every synthetic validation fixture so the subagent fixes its own plumbing before reporting production numbers, and a canvas-size floor so measured ink never clips. Read the pointer-input and camera handlers before launch and state the true model in the launch text: never assume drag orbits or wheel zooms; state what drag actually does and which storage key seeds the target scene. When the check needs a fixed scene state, script a deterministic seed plus a capture loop instead of pointer or camera choreography. A check with a server, a browser, and per-case captures is delegated by definition; inline browser debugging past one mechanical fix is a breach. Live checks use `playwright-core` from `~/.pi/agent/skills/web-browser/node_modules` (one `ls` first, import by absolute path), scripts from a /tmp harness directory, `chrome-headless-shell` as one fallback after a launch crash; never npm-install tooling into a worktree. A subagent never runs npm ci/install or git in the worktree, and two agents never run npm or git in one worktree. A green verdict ends deliberation: never re-audit the subagent's actions or card writes, never re-litigate whether the agreed evidence set suffices. Acceptance live checks launch only after suite, build, and commit are green.
- **Visual and pixel evidence.** Screenshot, camera, and shader reads batch in one block; verdict in the next block; a second weighing block on the same artifact is a breach. Validate a pixel analyzer on synthetic fixtures (one known positive and one known negative per class) before it touches a live render; all-zero or always-true counts are broken measurement. Crops derive from projected geometry, never hand-tuned offsets; empty or off-target crops are harness bugs fixed before any verdict. Record anti-aliased boundary bias as tolerance once. After two dead headless sweeps, instrument the live page with a temporary `globalThis` hook and remove it in the commit block. jsdom lacks browser globals: feature-gate on `typeof`. Fakes are minimal recorders with a printed sample record; a rasterizing fake canvas drives pixel-baking paths; a fake input event carries the exact coordinates production reads. DOM: `setAttribute('aria-label', ...)`, no custom properties on nodes, builders return `{ element, sync }` pairs refreshed by one `syncAll`.
- **Hot-path cost is a regression.** A rewrite that multiplies per-item work inside a hot loop is a defect even when numerically correct. Keep cheap early-exit gates in front of exhaustive enumeration. A suite that jumps from sub-second to tens of seconds is triaged with one timing probe, never accepted and never tuned around.
- **Reference research and shaders.** Delegate research (GLSL, ported algorithms, published formulas) in the planning block and build research-independent scaffolding while it runs. One research round, one transcription pass, one mirror test against the reference's worked cases, one probe printing the value chain. A library convention used for the first time is settled by one probe at first use and frozen. Shader sources ship with a frozen validation recipe: one node script extracts each template-literal source to /tmp files, then `glslangValidator -S vert` / `-S frag` per stage plus `-l <vert> <frag>` per pair.
