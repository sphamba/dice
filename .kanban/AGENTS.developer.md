# developer: project guidance for future agents of this role. The doctor rewrites this file after every run and keeps only durable, task-agnostic bullets. Never edit this file as the role agent.

- **Startup trio, first block, exactly three parallel invokes:** the kanban read tool (settle tool availability from the tool list itself, never in a thinking block), the TASK.md read, and the worktree bash of the next bullet. A call that consumes another's output waits one turn.
- **Worktree startup, one bash call, before any source read.** Worktrees live in `.worktrees/<branch>` and track `main`. One call: `cd <worktree> && ls -a && if test -d node_modules; then echo 'deps: present'; else echo 'deps: install started'; (npm ci > /tmp/npm-ci.log 2>&1 &); fi ; git merge --ff-only main; git log --oneline -1; git status --short; ls src/*/`. Read the install-state echo from the output; never re-derive it. A failed `git merge --ff-only main` is one Blockers line — never retry a merge, the merger role owns merges. The shape is mechanical from this output plus the prior notes: verification-only when the tree is clean, `main` is current, and the notes report the deliverable complete with green evidence; implement on a first run, an incomplete or silent card, or a dirty tree. State the shape as one lead-in line on the next tool call, never in a thinking block. Never re-run startup facts, never grep source to pre-confirm a deliverable the notes report, never investigate branches or empty log ranges. After a late merge, re-read code before editing.
- **Turn budgets and fixed run order.** Verification-only: startup trio, one chained bash (install-log tail only when the echo said install started; card-pinned acceptance command verbatim; `npm run build` plus the asset check unless the deliverable is test-only), one `kanban_update`, final text; zero thinking blocks. Implement: startup trio, one planning block, one batched read block, edits, one scoped verify, commit, card-pinned live check, `kanban_update`, final text; a fix adds one red→green cycle, and every further round names the rule that justifies it. End-of-run order: green evidence → commit → live-check launch → `get_subagent_result(wait:true)` as one bare call → `kanban_update` (wrap-up reasoning goes into the card notes) → short final text → stop. No thinking block sits between a green run and the commit, and no block of any kind sits after `kanban_update` returns — no card re-read, no wording audit, no resend weighing. Never expand scope to justify the run.
- **Batch reads — the largest recorded time sink, and it recurs.** In the turn after the startup trio, one lead-in line, then one block of parallel `read` calls covering every file the change touches: each module, its `.test.js`, package.json/config when dependencies, scripts, or test setup matter, and every module defining data the assertions use; whole files under ~400 lines. All orientation fits in at most two read blocks per run; a file that surfaces later joins the next batch and never starts a solo chain. Read each file at most once, with `read`, not `cat`. A steer or review note never invalidates in-hand contents: one `git diff` read reconciles, then resume. A truncated read does not count as having the file: batch re-read its target regions before editing. After compaction, batch re-read every file an edit will touch.
- **Edit discipline.** All changes to one file are one `edit` call in one block. `oldText` comes from a fresh read or a verbatim `grep -n` of the exact lines, never from memory. Edits are atomic: a rejected call applied nothing; the retry is one call resending the whole corrected set — no verification grep, no thinking block. A reported-successful edit is in the file: doubt about it never earns a block of its own; a `node --check` or grep proof rides the next planned bash. When the same anchor fails twice, the next block is one grep printing the target lines verbatim, then one resend with that text unchanged. Never append to an edited file with a bash heredoc. Before sending, check every symbol `newText` references is imported or defined, no duplicate key is left, and module order holds. After a multi-function edit the scoped suite runs before the next edit. A deletion, rename, or signature change greps every callsite once in the planning block and moves all consumers in the same pass; a newly added helper needs a callsite before commit (a zero-use grep on a non-entry-point symbol is a defect). A fallback path masks a dead real path: prove the real path ran.
- **Planning: one block settles everything.** Shape, deliverable, placement, data contracts, test scope (trivial → skip tests; feature → tests first; refactor → tests before code; fix → probe-validated failing test first). A numeric acceptance criterion freezes metric, fixture, seeds, and aggregation before the first probe. Freeze every derived convention (sign, axis, units, threshold, coordinate space, order) once as an input→expected table and never re-derive it. End with the decisions one line each; an item absent from the list settles by the next block's one grep or probe, never by more weighing. Any numeric, cost, or design question still open after one thinking block becomes a probe command in the next block — a second speculation block on the same question is a breach; repeated test-design weighing (oracle choice, harness strategy, tolerance) is this role's recorded top time loss. Keep thinking blocks finishable: move derivations into probe scripts or card notes. Never spend a block weighing whether an action breaches a rule — run the mechanical recovery.
- **Test oracles, tolerances, and runtime.** An exactness or reference test needs one independent oracle: choose the simplest correct one (brute force over a fixture small enough) in the planning block and never redesign it mid-run. Oracle runtime earns at most one timing probe; if it stays slow, set an explicit vitest timeout on the test instead of optimizing the helper — helper optimization is one more edit-rerun cycle for no acceptance value. Validate every hand-picked tolerance, radius, or epsilon from one probe that prints the real worst case on the real fixture before the red run ships; a quantity that legitimately saturates or plateaus (quantized bytes, clamped values, flat regions) is excluded structurally — mask the region out of the assertion — never fenced by a re-tuned radius. Keep `expect` out of per-pixel and per-step loops: accumulate the worst case, assert once. Vitest default timeout is 5 s.
- **/tmp probes: one bash block, proven plumbing.** Probes import project modules by absolute path; a relative import in a /tmp probe dies before it runs. For an A/B against a patched copy, one chained bash block does all of it: copy the module to /tmp, sed its relative imports to absolute paths of the original repo modules (paths that exist — never to other /tmp paths), apply the patch after any regeneration so it is not overwritten, `node -e "import('<copy>').then(() => console.log('import ok'))"` to prove the copy resolves, one grep proving the patched line is present, then run. A probe that fails to import or prints from an unpatched copy is broken plumbing, not evidence: one block fixes and reruns, no deliberation. Temporary copies are deleted in the same block or in the commit block.
- **Premise probes before effect tests.** A card that pins a numeric effect states a hypothesis until measured. One A/B probe runs both variants over the card's scenario, seeds, and metric and prints both aggregates. A delta inside run-to-run noise kills the premise: record the Open question, skip the red test, never build sweeps or patch/revert ceremonies around a dead premise. One A/B sweep decides; a null is a finding — never re-measure it. Compare by probe parameter or a /tmp copy of the module; never flip a source constant mid-run. A pinned threshold the A/B proves unachievable is decided once: keep the code change, leave the test red, record both numbers as an Open question.
- **Fixture validity before measurement.** A probe that presses, picks, or grabs asserts engagement in the same run: held body non-null, point interior to the target face (boundary points fail float picking), body state as intended. A press that misses invalidates every number that run printed — discard, fix, rerun. Randomized fixtures validate inputs first: one print of worst-case orientations and points before any sweep; check quaternion norms. Seed every trial independently from the start; before a sweep rests on a seeded helper, one line proves the helper consumes the seed — two replays disagreeing is a seeding bug: fix the seeding, never analyze the values. Derive layout from geometry constants, not absolute gaps. Test bodies come from the project's own factories, never hand-written literals. Never assert a threshold exactly at a boundary accumulated steps reach — one step before and one past. Legitimate variance gets one aggregate assertion over seeded cases, thresholds from one probe over the same seeds. An assertion that failed twice on fixture grounds is demoted to the robust form, never re-tuned a third time. A production constant changed to pass a marginal assertion is a threshold decision: one sweep, recorded on the card.
- **Red runs and failure triage.** A fix ships a red test before the code change, and one probe with the exact test setup proves the symptom before the test is written. An expected-red test reporting green is a fixture miss: the next block is one probe that sweeps the fixture axes; swap it in and rerun. The first red run runs untouched production code and prints every failing test's full output — no `tail`/`grep` filter on it. A red that already printed its assertions needs no rerun to capture names: any second run of the same suite without an intervening change is a breach. After a failed command, the next block is one tool call that gathers the missing evidence, never a plan revision. Then analyze fully, batch fix and rerun into one step; if the identical failure persists, re-read the edited region before new hypotheses. Green closes it.
- **Root-cause escalation is mechanical.** One probe per hypothesis; two dead hypotheses mean the probe measured the wrong thing — change the measurement, never add hypotheses. The measurement of record is a per-phase instrumented script (hook or copy the step pipeline and print state after each phase at the failing frame); it goes out after the second dead hypothesis, not a third speculation block. Reproduce symptoms with your own minimal fixture: other roles' logs and harnesses are context at most — one orientation read, never root-causing inside them. When sweep results contradict a derived expectation, suspect the fixture before the formula. When a held or supported body rests with near-zero velocity and a fixed offset, list contacts and containment geometry first. Tuned constants come from one sweep: smallest value with zero failures, unexported, one-line unit comment. A spec-suggested mechanism is a hypothesis: the instrumented value-chain probe at the failure site goes out before the hypothesis is written.
- **Physics and numeric probes.** Replicate the production step sequence exactly. Validate a fixture's rest state first: a body spawned at rest height with a random orientation intersects the floor, and solver kicks masquerade as the effect under test. A probe samples at the same point in the run as the assertion it supports. When a magnitude is implausible, print the whole value chain (input → constant → derived); suspect a scale applied twice, a per-unit vs total mix-up, or an argument in the wrong slot. Gate contact or normal signs on signed approach velocity (`v·n < 0`), never absolute speed. Never suppress errors.
- **Numeric traps.** Unary minus on a typed array yields NaN, not element-wise negation. After any sign flip or formula edit in vector math, print one concrete derived vector from a probe before rerunning the suite. When two mathematically equivalent forms disagree, print both from the same inputs in one probe; never alternate edits hoping the suite turns green. `src/math/` holds vec3/mat3/quat/mat4 helpers, out-param style (`add(out, a, b)`, column-major); grep exported names before first use; never alias `out` with an input. JS-mirror tests never compute expected values with the Float32Array-backed helpers: build mirrors from plain numbers, compare with ~1e-6 relative tolerance; a mismatch at the 8th decimal in fresh geometry code is a precision signature, not a logic bug. Use `Float64Array` for math state. Compute expected values through the module's own helpers with a one-line `node -e` script in the same block as the assertion — never mental arithmetic. Quantities that physics lets tie assert ordering non-strictly.
- **Stack and shell traps.** Vite + Vitest, ESM (`"type": "module"`). Scripts: `npm run dev`, `npm run build`, `npm test`; the one `npx` exception filters a single test (`npx vitest run <file> -t '<name>'`); a card-pinned command overrides. Tests sit next to sources as `src/**/*.test.js`; Vite and Vitest share `vite.config.js`. The build parses only modules reachable from `main.js`; parse-check anything else with `node -e "import('<path>')"`. Log installs (`npm install --loglevel=http > /tmp/npm.log 2>&1`); `~/.npmrc` sets `min-release-age=7` and `ignore-scripts=true` — check `npm view <pkg> time` before version floors. Piping test output through `tail`/`grep` masks the exit code: `set -o pipefail` first, or judge green from the reporter line — and a filter that eats failure detail costs a rerun, so print full output on the first run. `pkill`/`pgrep -f` match their own command line: bracket pattern or owned PIDs. A zero-hit grep on one file reruns directory-wide in the same block. Prefer `grep -oE`; check an awk field separator against one input line.
- **Build evidence rules.** A change confined to `*.test.js` never enters the build graph: skip `npm run build` and the asset check, say so in one lead-in line. A fresh build's hashed asset name proves nothing. The one asset check: after a green build line, `grep -oE '(src|href)="[^"]+"' dist/index.html` once, chained in the same bash. After a failed build the on-disk `dist/` is stale: skip the grep or mark it stale on the card.
- **Git rules.** Code changed and tests green → one commit, lockfile included when deps changed. Verification-only on a clean tree → no commit, card only. Never commit TASK.md, AGENTS.md, or `.kanban/`. Settle ignore/tracked questions with one `git status` plus one `.gitignore` read in the same block. Clean-room acceptance, only when committed code changed: `git archive HEAD | tar -x -C /tmp/check`, then in the copy `npm ci ; npm test ; npm run build` with `;` never `&&`; read the log tail on failure; delete the copy. Sibling-task dependency: stage exactly the named files via `git show <ref>:<path> > <path>`; never stage the sibling's tests, merge the branch, or write a shim; verify against the copy, remove it in the commit block, record it on the card; on a ref error run `git branch --list '*<fragment>*'` once and retry. A dependency decision is closed once made; only new tool evidence reopens it.
- **Card notes and card writes.** Compose from the TASK.md copy read at startup, changing only the lines new evidence changes. In the commit block write a notes draft (deliverable, evidence lines with counts, HEAD short hash, assumptions, blockers, open questions) to `/tmp/run-notes.md`; after compaction compose from that file, never memory; compaction recovery is at most one recall call — a second recall on the same gap is a breach. A checkpoint that blocks on a card write gets one mechanical call with the notes as they stand. Fixed sections: Deliverable / Verification / Assumptions / Blockers / Manual checks left to other roles; placement is never debated (a merge divergence is a Blockers line, an out-of-scope defect is an Assumptions note). The verification line names the HEAD short hash. Numeric lines come from recorded probe output. Closing an open question folds the answer into the card field that holds it and clears the question in the same call. `kanban_update` replaces whole fields: carried lines are resent verbatim. One update per run, sent once after green; resend only for a factual error, and the deliberation about resending never earns a block — the run is closed when the update returns.
- **Subagents, live checks, and reference research.** A background `Agent` call returns at once; `get_subagent_result(wait:true)` blocks the turn as one bare tool call next turn — never in a thinking block. Batch independent launches into one turn; the launch text is self-contained (browser flags, dev-server port, repo paths, probe locations, full assertion list) — the subagent never reads this file or the worktree context. Delegate reference research (GLSL, ported algorithm math, published formulas) in the planning block and build research-independent scaffolding while it runs; transcribe formulas verbatim, mirror-check against the reference's own worked cases, never re-derive a fetched formula in thinking — print the value chain in one probe. One research round, one transcription pass, one mirror test. A hand-assembled operator gets a write-time identity check in the same block as the write. A library convention used for the first time is settled by one probe at first use and frozen. Shader sources ship with a frozen validation recipe: one node script extracts each template-literal source to /tmp files, one chained bash runs `glslangValidator -S vert` / `-S frag` per stage plus `-l <vert> <frag>` per pair. Launch browser checks only after the scoped suite, build, and commit are green, and only for acceptance criteria that name them; one check runs every scenario and reports each independently; fix all reported defects in one edit pass, then one re-check — never interleave per defect. Live checks use `playwright-core` with the cached browser in `~/.cache/ms-playwright`; full Chromium can crash at launch: fall back to `chrome-headless-shell` once, never debug it. Never let two agents run npm or git in one worktree.
- **Browser, visual, and UI-test evidence.** Visual symptoms: batch the screenshot read with the camera and shader reads in one block, verdict in the next block; a second weighing block on the same artifact is a breach. An artifact matching the expected shading math is recorded as expected behavior on the card, never re-litigated. A reported symptom is a measurement claim: first check what the camera projection can show — an orthographic view collapses one axis. After two dead headless sweeps, stop sweeping and instrument the live page: a temporary `globalThis` hook in the entry module, drive the real page, read engine state per frame, remove the hook in the commit block. An intermittent console error outside the deliverable: one repeat run confirms it is intermittent, then it is an out-of-scope card note — never a fix debate. jsdom under Node exposes only some browser globals (no `AudioContext`, no `navigator.vibrate`): feature-gate browser APIs on the function (`typeof navigator.vibrate === 'function'`); unsure what the environment provides, one probe (`node -e "console.log(typeof navigator, typeof AudioContext)"`) rides the test-draft block. Design fakes as minimal recorders (settable clock, call log, injectable functions); print one sample record before asserting on indices or tuples; a harness failure is a harness bug. A rasterizing fake canvas (fill, ellipse, getImageData) drives real pixel-baking paths without jsdom. A fake input event carries the exact coordinates the production code reads; recompute expected quantities from the same event data. DOM: `setAttribute('aria-label', ...)`, never `element.ariaLabel`; never attach custom properties to DOM nodes; a builder returns `{ element, sync }` pairs and one `syncAll` refreshes them.
