# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and planning

- Read the task file first and fix the acceptance scope and task id from it. Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors, serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time; one multi-file dump truncates). All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; drop precedent checks that do not map to acceptance; never revisit or re-enumerate that list in later turns. Live-testing can run after the merger (`git log --grep "<task-id>"` locates the commits): match verification depth to the diff — small or deletion-only diffs need static proof only, and no live run unless acceptance demands one.
- Map every phase to an acceptance criterion or a PM-named check before writing it. Cut a phase on its second non-converging design iteration in favor of the minimal phase that exercises the same constant; never carry a half-designed phase into a run and delete it after it fails there.
- Before authoring any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle or motion is detected). Every expected value an app asserts about itself — sizes, caps, clamps, dpr handling — is grepped from source lines first, never assumed. Tag harness quantities with units; every threshold must trace to a measured reference captured in the SAME run; every settle or flight timer arms BEFORE its trigger. A check copied from precedent must DISCRIMINATE (stress the constant it tests), else it passes on pre-fix code and is void as regression evidence.

## Probes and diagnosis

- Front-load ONE timed environment probe that answers every environment unknown once: fps, WebGL2, reported viewport, canvas backing size versus the source-derived expectation, helper return shapes, event injection, console texts, and the latency of one synthetic input dispatch. Print one whole `JSON.stringify` sample of every captured event and helper return BEFORE consuming fields. Build it only from primitives verified standalone FIRST (a risky primitive gets a 10-line probe before it enters the shared harness). `node --check` passes code with undefined identifiers and wrong property names.
- Deliberation is not inspection. An open "how do I measure or access X" or "does X throw or degrade" that survives one read is answered by a 10-line probe or ONE targeted grep, not by tracing call paths in-head. Three self-corrections in a row (wait / actually / BUT / a re-derivation) mean STOP and print live values or pixel data. One hypothesis cycle per anomaly, then measure. Sign and direction conventions (into/out of a surface, axis handedness) are written once from printed source lines; a second in-head re-derivation of the same sign means print a truth table with real coordinates or demote the check to observation-only.
- A TypeError or undefined-field error whose stack points inside harness or driver code is a data-shape bug in your OWN glue: read the exact call site and the producer of its argument (grep where the variable is assigned) BEFORE any probe or app-side theory. Never rewrite a driver to escape an unexplained failure — the rewrite reproduces the bug.
- If a reproduction probe does not reproduce, STOP probing and diff the probe's code path against the failing path line by line (what each one feeds into the failing call). Two failed reproductions mean the difference is in your own code, not the app.

## Headless rendering and emulation

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await, while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side, arm traces before triggers, and measure fps once in the environment probe. SwiftShader runs far below display fps: use the fewest bodies that exercise the check.
- Read pixels with `gl.readPixels` inside the same rAF tick after the app's draw: one read per region (slice it in-page), Y-flipped, edge-clamped. `preserveDrawingBuffer` is false by default: a read outside the render rAF, or via drawImage/getImageData, returns stale or black. Cache `WEBGL_lose_context` with `getExtension` BEFORE calling `loseContext`. Assert fractions over spans or windows, never single pixels, and window each body separately. Force viewports with `page.setViewportSize`, never raw CDP metric overrides (they do not stick and fire no resize). Pin `viewport` at context creation anyway: device descriptors ship a smaller viewport and dpr is capped in headless. Canvas backing size and resize-derived state settle asynchronously after any resize: wait a few hundred ms before reading them.

## Visual evidence

- A visual anomaly is a data question, not a theory question. FIRST action: a measuring script (pixel spans, centroids, luminance grids). SECOND action: a pixel diff against a verified baseline (`magick compare -metric AE`; exit 1 means images differ — parse the first stderr token). Verify the baseline commit predates the feature BEFORE investing in it; a head-versus-base difference where BOTH sides look wrong is pre-change or environment evidence, not a defect.
- Fixed-distance patches around a body are contaminated by its tilted silhouette: place probe patches relative to the rendered bbox EDGE outward per direction, clamp every patch coordinate inside the frame, and use a frame-percentile luma as the open-floor reference. A "no effect" reading from a contaminated, occluded, or off-canvas patch is void, not a defect. Pixel hue/ink classifiers are structurally fragile (AO and contact shadows crush absolute thresholds): prefer an empty-frame diff instrument; after two threshold nudges, stop nudging and instrument the underlying distribution once or REPLACE the instrument.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, world spies, readback helpers, guards, results writer, console whitelist in one place), with PORT/OUT/CWD read from env vars so copies can retarget. Copy precedent drivers; edit only imports and paths. Never call a remembered helper name: grep the harness exports first and cross-check every call site in the same writing pass. Pass REAL functions to `page.evaluate` (Playwright calls a function but evaluates a string as an expression). No shared mutable scratch buffers between copied steps: a clobbered scratch makes a test silently always-true or always-false.
- Copying a precedent harness: first grep it for every absolute path and decide keep-versus-retarget per path in one pass. `sed` exits 0 on NO-match: after any sed edit, `grep -c` the old and new strings to verify the substitution count. A path that resolves node modules (a `createRequire(<pkg>/package.json)`) must keep pointing at the tree whose node_modules installs them, regardless of which worktree is under test.
- Injected input is slow and lossy: one dispatch can take tens of ms, moves coalesce, and `mouse.up()` reuses the last move's coordinates. Give every move its own explicit position, space moves 40 ms or more apart, and read timings from in-page event records, never Node-side send times. Poll transitions, not flags: a wait-for-flag helper can resolve on the PRE-trigger state (asleep before the toss, held before the grab) — first wait for the state to move the RIGHT way (awake after the click), then wait for the settle flag. Poll settled STATE over consecutive samples or spans, never single-frame velocities or awake/sleep flags. Every check that compares a measurement against an expected value carries a non-degeneracy guard (operand ~0, null, or empty where a real signal is required → FAIL and retry, not pass) and logs the operand in the check line. Retry loops absorb random draws: per-attempt pass flags, logged draw inputs, and gate values logged per attempt. Gate launches on pre-solver captured values, never on post-contact outcomes like apex height.
- Compute geometric feasibility, never assume it: before any grab or sampling check, print target versus body half-width, wall clearance, panel rect, and max silhouette reach; clamp targets into reachable bounds; gate every pointerdown with an in-page `document.elementFromPoint` check. A phase that needs a specific body spawns or repositions its own target and asserts its identity BEFORE grabbing: leftover bodies from earlier phases leak and get grabbed instead.
- Ground every pass/fail gate in source constants or measured references BEFORE the first run. A phase whose outcome depends on uncontrolled collisions or equilibrium gets an observation-only check from the start — never a gate weakened or inverted after a FAIL. A detector whose sampling cadence cannot separate the candidate causes (for example sub-step solver contacts between sparse trace rows) is a harness limit by construction: classify it as such at the FIRST flag, record once, never re-analyze, and never rerun hoping the flag goes away.
- Check-in ladder for EVERY harness, driver, or probe write: `node --check` in the next command; after any edit, re-check syntax AND re-grep the edited block for sibling assertions the edit can have silently deleted; then a 2-5 s smoke launch with clock and spy wrappers installed (grep the console for ReferenceError and TypeError); then one whole-data-path smoke on a single capture that ASSERTS the captured object is defined and has the expected fields; then the full run. The driver self-establishes every precondition, gates clicks on visible+enabled, serves all modes from one results-writer path, runs end-state checks only in phases whose precondition phases ran, and takes a PHASE FILTER env var from the start. Before parsing a results file, print its first entry to pin the schema.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root); start the server BEFORE any HTTP check; vite binds IPv6 loopback only, so use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL first, and build route-rewrite spies from the SERVED response body. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). A baseline worktree OUTSIDE the repo tree cannot resolve vite (npx ENOENT): keep baselines inside the repo tree or symlink `node_modules`. No global `playwright` and ESM import ignores NODE_PATH: import it by absolute path, or via a `createRequire` that points at the tree installing it; browsers live in `~/.cache/ms-playwright`. Launch Chromium with `--disable-dev-shm-usage` from the first run: a mid-run renderer crash voids every later phase. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate it, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths (`cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`), a unique log per attempt, sleep then tail ONCE (an immediate tail races log creation; never pipe into `head`), `grep -a` on large logs, and `echo "== section =="` markers. Wrap each phase in try/catch with periodic page recreation so one crash does not void the rest of the run. Kill by PID or by port (`lsof -ti :PORT | xargs -r kill`), never a pkill pattern that can match your own command line; before killing PIDs found by a broad search, read `ps -o pid,args` and kill only PIDs whose args point at your own harness directory or port.
- Post-green discipline: a green run is done; do not re-litigate passing numbers with speculation (an odd passing number gets one raw-trace print, then it is recorded as an observation or dropped). Wrap up in one pass: file confirmed product defects as cards (duplicate check first; evidence, root cause with file and line references, fix direction), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with its reason), or a filed card. At most one interim notes checkpoint mid-run; the final notes rewrite is the record. Kill every server you started, verify each port with `lsof`, persist notes once, and end the turn without `orchestrator_wait` (the checkpoint release arrives as injected context).
