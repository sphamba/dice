# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass that resolves every harness open question at once: modules under test, mount-point and consumer files, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the single defining module), serve command, `git log --oneline -10`, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file; names do not map to task numbers). Copy a prior driver and edit only imports and paths. Commit the harness choice in one written line and never re-justify it.
- Pick the cheapest harness that reaches the code under test. Pure module with no browser consumer: Node ESM driver importing by absolute path. Rendered page: browser harness. An empty grep for importers is a finding that settles the harness question.
- Timebox design work. When a check's mechanics are uncertain (focus, clipping, visibility, dispatch or sampling order), write a 10-line probe that prints the answer instead of deliberating in thinking; a wrong 40-line driver costs more than the probe.

## Environment and build
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`. Locate it once with a single home-wide search that excludes the browser cache (`find ~ -maxdepth 8 -type d -name "playwright*" -not -path "*ms-playwright*" 2>/dev/null`), record the absolute path, import from it, then run one timed probe (dynamic import, `chromium.launch`, `newPage`, close) before writing any driver. Binaries live in `~/.cache/ms-playwright`.
- Build with `node node_modules/vite/bin/vite.js build`; `npm run build` dies in worktrees because the copied `.bin/vite` shim mis-resolves (ERR_MODULE_NOT_FOUND). Serve with `npx vite --port <uncommon-port>` or `python3 -m http.server` on the built `dist`. Check the port free, curl HTTP 200 for the page and every module URL before any browser step, start detached (`setsid`), kill by port at the end, verify with `lsof -ti :PORT`. Never `pgrep`/`pkill -f` a pattern that appears in your own command line: it matches your own wrapper and the kill terminates the command (exit 143). Use a bracket pattern (`pkill -f "[d]river"`) or kill by port.
- Front-load one probe run that answers every environment unknown before you write the driver: rAF fps, overlay DOM rects, pointer and touch plumbing with ids and targets, autoplay policy, AudioContext state, and a console-message audit. Record each answer once and never re-measure. A behavior headless cannot exercise gets a one-line unit-covered note, never more iteration.

## Playwright evaluate and waits
- `page.evaluate("...")` evaluates a string as an expression and does NOT auto-invoke function strings, so a bare arrow-function string returns `undefined`; if any evaluate result is `undefined`, suspect this trap before anything else. Write snippets as IIFEs: `page.evaluate("(() => { ...; return x; })()")`. `page.evaluate` takes one function or string plus at most one serializable argument; extra arguments crash the call mid-run. Values cross through evaluate args or `globalThis`, never Node scope.
- Bound every wait: explicit timeouts on `goto`, `waitForFunction`, and `waitForSelector`, `protocolTimeout` in launch options, and one step log line per phase. When a run hangs, read that log before building a new theory. Harness cleanup that stops the server makes later standalone probes hit ERR_CONNECTION_REFUSED: start the server and run the probe or driver in one bash command, or let each probe own the lifecycle, and curl the port immediately before any page load.

## State, focus, and motion
- Track toggle state in one driver variable that every action updates, and assert expanded or collapsed at the top of each phase. One stale state assumption invalidates whole phases of checks; gate each phase on its preconditions instead of assuming them.
- A click leaves focus on the clicked control, so a later synthetic Space activates that control, not the page: blur or move focus before every keyboard-on-body check. Synthetic CDP key events never auto-repeat; a held key is one keydown, so test repeat suppression as one roll per keydown pair and mark OS-hold behavior unit-covered.
- Arm motion sampling BEFORE the trigger, in the same sequence (start sampler, then dispatch); sampling started after the roll reads zero movement. Sample state shortly after the input, not after settle, and assert a sampled maximum against an explicit threshold. Copy every expectation (counts, labels, tab order; disabled controls are not tabbable) from source or the live DOM, never derive it in-head.

## Headless timing and pixel diffs
- Headless SwiftShader renders a WebGL canvas at a few fps: physics runs in slow motion and `page.click` actionability stalls, so prefer raw `page.mouse` or CDP coordinate dispatch and never read slow-motion timing as product behavior. Do not gate phases on the scene settling: piles of many bodies can micro-jitter for minutes. Cap settle waits at a few seconds, use the fewest bodies that exercise the check, and on settle timeout fall back to state or geometry assertions, or reroll with fewer bodies, instead of waiting longer.
- Wrap ImageMagick `compare -metric AE`: it exits 1 when images differ (0 identical, 2 on error) and prints the metric to stderr, so tolerate exit 1 and parse the first stderr token, and `ls` the filenames before batch compares. Localize a diff with per-region AE on crops of the moving region; a whole-frame diff or fuzz-trim bounding box covers everything and localizes nothing.
- A pointer resting on a button restyles it and can account for hundreds of differing pixels. Keep the pointer at one neutral position in baseline and post shots, or crop the diff to the region away from panel chrome.

## Driver authoring
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers) plus Node-side helpers (serve, dispatch, capture, results file). Import it into every driver and probe, run `node --check` after every write, and parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change. Console-gate only after a smoke-run audit; whitelist headless artifacts (WebGL context-lost at load, ReadPixels GPU-stall warnings) only after confirming them in `src/render/` and a mid-flight screenshot.
- Long suites go background as one standalone command: `setsid nohup node driver.mjs > log 2>&1 &`. An `&&` chain ending in `&` backgrounds the whole list, and an immediate tail races startup; sleep and tail in follow-up calls, and never pipe a driver into `head`.
- Guard a `localStorage` seed with a `globalThis` marker so a reload does not re-seed. Route every dispatched coordinate through one harness normalizer: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`), clamp to canvas bounds, assert `Number.isFinite`. Pin pointer and touch dispatch semantics empirically in the probe before authoring gestures; when an expected event is missing, compare coordinates against overlay rects and the event log first.

## Debugging and wrap-up
- When checks fail, suspect the check first: guards, signs, units, timing, preconditions. Print actual live values at the decision point before reading more product code, and widen a failed search once at most. Poll background runs with short sleeps and the step log; once two or more checks fail, stop the run, batch-audit every failure in one pass (driver, harness, or product bug), fix the shared root cause once, and rerun only the invalidated checks.
- If bash suddenly fails with "Working directory does not exist", the worktree was externally deleted: recreate the missing directory path, `git worktree add` from the task's pinned commit, restore the kanban and task-file symlinks, restart the server, and re-check the task card. Recover in a few calls; do not diagnose at length.
- Wrap up in one Notes pass: file confirmed product defects and open questions as cards (evidence, root cause with file and line references, fix direction, acceptance criteria, duplicate check first), resolving the card id from the worktree task-file symlink. Kill every server you started and verify each port with `lsof`, persist measured numbers once, and finish with a results table mapping every check to a pass or a filed card. Do not call `orchestrator_wait`: agent sessions are refused; only the project manager session waits for board reports.
