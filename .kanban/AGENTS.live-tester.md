# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and planning

- Read the task file first and fix the acceptance scope and the task id from the task file itself (branch names and card titles can disagree). Then run ONE batched inspection pass that resolves every open question at once: modules under test, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the defining module), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts — `ls`/glob the exact filenames before reading any, and read precedent files one at a time with the file reader; one multi-file dump truncates. Commit the harness choice in one written line, copy a prior working driver, and edit only imports and paths.
- Match verification depth to the diff. Deletion-only or small-diff tasks need static proof only: full `git show`, diff touches only the named files, no orphaned imports, `node --check` per touched file. Verify a merged commit in ONE batched command (`git rev-parse main HEAD; git log --oneline -3; git diff main...HEAD --stat`): empty diff plus equal revs means merged. Never reconcile test counts with naive greps (`it.each` and data-loop describes multiply tests); count structurally (`rg -n '^\s*(it|test)\('`). Do not launch the app unless acceptance demands a live run.
- Never derive physics, geometry, projection, or engine math in-head. Before authoring any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle or motion is detected); every threshold and timing method must trace to those two artifacts, and every settle or flight timer arms BEFORE the trigger, never after. Calibrate every motion helper empirically before the first full run: tilt once and print the drift direction, apply the chosen drag offset once and print the die travel. A sign error or a too-small offset found in a full run voids that run; a numeric knob (angle, offset, distance) chosen by in-head estimation is wrong until measured. Open questions about event injection are answered by the front-loaded probe, not by deliberation.
- Deliberation is not inspection, in planning and in failure triage alike. Any "how do I measure or access X" that survives one read is answered by a 10-line probe, never by another thinking round; three self-corrections in a row ("wait", "actually", a re-derivation) mean stop and print live values. On a FAIL the FIRST action is a raw-sample probe at the decision point (click counter, sim time, per-sample positions and velocities); classify each failure as harness bug, harness limit, or product defect from those samples BEFORE listing hypotheses or touching thresholds. Debug probes get the full check-in ladder too. With two or more failures, batch-audit them once, fix the shared root cause, and rerun only the invalidated checks. Never nudge the same threshold twice.

## Serve and tooling

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` — the `cd` must be in the same command, else vite serves the wrong root and the page 404s. Use `localhost` (vite binds the IPv6 loopback only, never `127.0.0.1`). Curl HTTP 200 for the page and every module URL before any browser step; vite rewrites relative import specifiers, so build route-rewrite and import-rewrite spies from the SERVED response body, not repo source. Kill by port (`lsof -ti :PORT | xargs -r kill`) and verify with `lsof`. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves).
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`: locate it once, record the absolute path, import from it; binaries live in `~/.cache/ms-playwright`. Front-load ONE timed probe run that answers every environment unknown exactly once: launch, rAF fps, WebGL2, reported viewport and canvas or box size, helper return shapes, event injection, console message texts. Playwright device descriptors ship a viewport SMALLER than the screen (browser chrome): when dimensions are pinned, set `viewport` explicitly at context creation and keep only touch and UA flags from the descriptor. Print one whole sample (`JSON.stringify`) of every captured event and helper return BEFORE consuming fields — `node --check` passes code with undefined identifiers and wrong property names.
- Headless Chromium renders a WebGL canvas blank without software-GL flags (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`): define them once as harness launch args. Verify any capture by counting non-background pixels before interpreting it. SwiftShader runs below display fps, so prefer raw `page.mouse`/CDP dispatch, cap settle waits, and use the fewest bodies that exercise the check. `page.setViewportSize` protocol-errors on a maximized window: set the viewport at page creation or restore the window state via CDP first.
- Check-in ladder for EVERY harness, driver, or debug-probe write: `node --check` in the next command (catches duplicate declarations, stray tokens, and undefined references), then one 2-5 s smoke launch with the clock and spy wrappers installed before any full run, grepping the page console for ReferenceError and TypeError. A wrapper bug that kills the simulation turns every later wait into a full-length timeout and voids the whole run; a smoke run costs seconds.

## Transient capture and random draws

- The recurring trap: a Node-side sample taken after a fixed wait lands after the action has already settled, so velocity reads 0.000 and frame diffs read zero. Every transient check (velocity, motion-during, wake, re-sleep) uses an in-page rAF or frame-granular trace ARMED BEFORE the trigger, recording per-frame state and timestamps; Node-side `page.evaluate` after waits is only for rest or final state. When copying a precedent harness, keep its armed-trace helpers and reuse them in new checks instead of re-implementing Node-side sampling. A zero velocity, instant re-sleep, or empty event log is a sampling-window bug until the trace proves otherwise.
- Rapid CDP `mouse.move` calls coalesce into one sample (velocity reads zero, so flings read as motionless): space move samples 40 ms or more apart, and when mid-flight sampling stays unreliable, compare pre/post rest states instead. Measure flight and settle durations with one probe BEFORE designing any transient check; CDP screenshot latency cannot sample sub-100 ms flights.
- A check that depends on a random draw (spawn position, shuffle) needs retry loops with per-attempt pass flags and logged attempts, and criteria independent of the draw: prefer end-state or reached-boundary assertions over displacement thresholds that a bad spawn breaks. Calibrate every numeric instrument on a synthetic signal with known parameters before pointing it at product data, and print measured versus expected; anchor motion metrics at detected motion onset; set tolerances at float32 scale (about 1e-5 relative); assert transitions by final state and prefer robust orderings (A decays slower than B) over fragile absolute windows.

## Playwright mechanics

- `page.evaluate` silently skips a function-shaped string that starts with whitespace or a newline: wrap every injected snippet in a harness helper that evaluates an explicitly invoked IIFE, and follow the precedent's injection pattern verbatim instead of re-litigating it. Reset every capture buffer per phase and mark phase boundaries with in-page timestamps (capture clocks differ: sim time, wall time, rAF). Route every dispatched coordinate through one normalizer (css px, clamp to canvas bounds, log clamps): a clamped fling or edge drag has zero velocity, so keep drag and fling targets well inside bounds.
- Setup parity: every setup step the probe performs to reach an interaction (panel toggle, scroll, focus, modal dismiss) appears in the driver at the same point. Gate every click on visible and enabled — a collapsed row makes the click time out and voids the rest of the run. Track toggle state in one driver variable that every action updates, and gate each phase on asserted preconditions. Blur before every keyboard-on-body check; synthetic CDP key events never auto-repeat. Copy every expectation (labels, counts, tab order; disabled controls are not tabbable) from source or the live DOM, never in-head.
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers, drain) plus Node-side helpers (serve, dispatch, capture, results file, console whitelist in ONE place), imported into every driver and probe. Every probe and driver contains at least one explicit PASS/FAIL check. Parameterize drivers with env vars from v1 (phase gates, result ids). `page.evaluate` passes at most one serializable argument; use dynamic `import()`/`createRequire` for node builtins in ESM.
- While writing a driver, cross-check every helper call site against the harness exports in the same pass, so signature mismatches surface at write time and not as repair cycles. When an edit fails argument validation or lands garbled (duplicated loop, broken condition, leftover identifier), re-read the edited region and resend it as fresh small single-target edits before anything else. After any helper rename, signature change, or block deletion, audit every call site and now-undefined identifier in the SAME edit batch, then `node --check`. Never write "fixed" into notes or cards before the edit has landed.

## Runs and wrap-up

- Long suites go background as one standalone command with ABSOLUTE paths: `cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`. Use a unique log name per attempt. Record the driver PID at launch; kill drivers by that PID or by port (`lsof -ti :PORT | xargs -r kill`), never by a `pgrep`/`pkill -f` pattern that can match your own command line. Gate expensive phases (phone, slow suites) behind env vars so a desktop-only rerun skips them. Separate multi-part bash commands with `echo "== section =="` markers so a truncated result stays interpretable. An immediate tail races log-file creation: sleep, then tail once about 30 s after launch to catch instant crashes. Never pipe a driver into `head`.
- Post-green discipline: when every check passes against source-derived expectations, the run is done. Do not re-litigate passing numbers with speculation; if a passing number looks odd, print its raw trace once and either record it as a report observation (a harness clock or sampling artifact) or drop it. Never invent new failure hypotheses or rerun detectors after a green run.
- Wrap up in one pass: file confirmed product defects as cards (evidence, root cause with file and line references, fix direction, acceptance criteria, duplicate check first; resolve the card id from the worktree task-file symlink), give each run's results a unique id so re-runs never double-count, and finish with a results table mapping every check to a pass, a harness limit, or a filed card. Kill every server you started and verify each port with `lsof`, persist measured numbers once, and end the turn after writing checkpoint or final notes — do not call `orchestrator_wait`; the checkpoint release arrives as injected context.
- Wrap ImageMagick `compare -metric AE`: it exits 1 when images differ (0 identical, 2 on error) and prints the metric to stderr, so tolerate exit 1 and parse the first stderr token; localize a diff with per-region AE on crops of the moving region, and keep the pointer at one neutral position in baseline and post shots.
- If bash suddenly fails with "Working directory does not exist", the worktree was externally deleted: recreate the path, `git worktree add` from the task's pinned commit, restore the kanban and task-file symlinks, restart the server, and move on.
