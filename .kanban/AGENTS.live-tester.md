# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass: entry-point reads, modules under test, `git log --oneline -10`, toolchain checks (Playwright ESM import, free port), and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each `results.json`/log; names do not map to task numbers). Copy a prior driver and edit only imports and paths; never retype algorithms from memory.
- No global `playwright`; browser binaries live in `~/.cache/ms-playwright`. A usable package exists in other repos (for example `/home/phamba/repos/tarot/app/node_modules`). ESM `import` ignores `NODE_PATH`; import Playwright by absolute path and verify with a real dynamic import.
- Serve the built app with `python3 -m http.server <uncommon-port> -d <dir>` (or `npx vite` when bundler behavior matters). Check the port is free (`lsof -i:<port>`), curl-check HTTP 200 for the page and each module URL, start servers detached (`setsid`), track every port you started, and at the end kill by port (`lsof -t -i:<port> | xargs -r kill`) and verify. Never `pkill -f` a pattern that appears in your own command line or log tail; kill by port instead.
- To serve an extra probe page next to the app, symlink it into the served directory instead of a second server or CORS headers. A stale or wrong probe URL returns 404 and the page fails silently. From the first probe run, capture `pageerror`, all console messages, and failed requests, and curl each import URL when a `waitForFunction` times out.

## Harness: one shared module
- Build one shared harness file in `/tmp` at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page rAF frame grabber, WebGL readback, component finder, unit converters) plus Node-side helpers (serve, contexts, PNG dumps). Import it into the driver and every probe. A probe that forgets the INIT fails late with "grabFrame is not a function"; never copy the INIT into each script.
- Convert coordinates with one converter set, in this order: `canvasScale = canvas.width / canvas.getBoundingClientRect().width` (canvas backing scale), backing px to css px, css px to world m. Never assume the backing scale equals `window.devicePixelRatio`; the backing store can be capped and emulation can change DPR. A wrong scale makes rendered dice look displaced and every click miss.
- Validate the converters before any behavioral check: teleport one body to a known world point, click its computed screen position, and assert the pick succeeds (`held == 1`). A click that misses tells you nothing about picking; do not read it as a pick or hold failure.
- Grab frames inside the rAF job that renders them; a `readPixels` outside that job returns a cleared or stale buffer and gives false "no pixels" results. Do not compare state between different runs or probes.

## Driver design
- Run one smoke scenario end to end (including the harness math) before the full matrix. Budget suite runtime: a multi-minute suite overruns the bash timeout; start it in the background (`nohup node ... > log 2>&1 &`) and tail or poll the log in separate calls. Print each check as it completes; set a page default timeout (15-20 s); batch all contexts into one script.
- Make each check robust to scene noise: assert on the specific body's component stability or position, not raw crop pixel diffs that shadows and tumbling neighbors sweep. Global component counts are weak evidence when dice overlap in projection or textures alias; filter speckle components by a minimum pixel area and prefer per-body metrics.
- `page.evaluate` accepts serializable data only; make callbacks `async` when they `await`; share values through `globalThis` or evaluate arguments; never close over Node scope. Synthetic events need instance properties set via `defineProperty`, a controlled `timeStamp`, and a `navigator.maxTouchPoints` override when code gates on it.
- Write output to a log file, keep PNG dumps of every interesting frame, and confirm the dump-writing code ran before reading a PNG. Headless Chromium (SwiftShader): keep `readPixels` readbacks few, rerun once on CONTEXT_LOST, and dump frames in-page with `canvas.toDataURL('image/png')`, then crop with ImageMagick (PIL is not installed).

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, and units before product hypotheses; most single-check failures are harness bugs. After two failed checks in one run, stop and batch-audit every failure; classify each as driver bug, reference bug, or product bug; fix the shared root cause once and rerun.
- Collect runtime evidence before reading more product code. If a pick, hold, or roll check fails, instrument the live page (wrap `addEventListener` and `setPointerCapture`; log pick inputs, body positions, held count) and read the values. Repeated in-head derivation and source re-reads without data are the most expensive failure mode in this role.
- Port expected formulas from the source under test instead of deriving them in-head. When a hand-derived expectation fails, suspect the derivation first and recompute it in a script that prints intermediates. When a value is off by a scale factor, check unit conversions (css px, backing px, world m, DPR) first.
- A tolerance guessed without measurement produces repeat false failures; when a check fails on magnitude only, dump the data, print the worst deviation, then set the tolerance. A flaky check that passes then fails needs a metric change, not a rerun; replace the evidence and keep the old value as extra output.
- Before writing any script, grep the `export` lines of each module it imports and copy the exact names; grep for helper files before referencing their paths; verify a dumped or symlinked artifact exists before reading it. Run `node --check` after every write. A grep with no match exits 1 and aborts an `&&` chain.

## Wrap-up
- Persist measured numbers once (task Notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria. State harness assumptions and test limits in the Notes.
- Resolve the task card id from the worktree task-file symlink before calling kanban tools; a bare "TASK.md" returns not-found. Draft Notes in one clean pass and scan for duplicated lines before posting. Kill every server you started, verify each port with `lsof`, and finish with a results table that maps every check to a pass or a filed card.
