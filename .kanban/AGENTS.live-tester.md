# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass that resolves every harness open question at once: modules under test, mount-point and consumer files, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the single defining module), serve command, harness runtime location, `git log --oneline -10`, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file; names do not map to task numbers). Copy a prior driver and edit only imports and paths. Commit the harness choice in one written line and never re-justify it.
- Pick the cheapest harness that reaches the code under test. Pure module with no browser consumer: Node ESM driver importing by absolute path. Rendered page: browser harness. An empty grep for importers is a finding that settles the harness question.
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`. Import Playwright by absolute path from a repo that has it, then run one timed probe before writing any driver: dynamic import, `chromium.launch`, `newPage`, close. Binaries live in `~/.cache/ms-playwright`.
- Serve with `npx vite --port <uncommon-port>` (bundler behavior matters here) or `python3 -m http.server`. Check the port free, curl HTTP 200 for the page and every module URL before any browser step, start detached (`setsid`), kill by port at the end, verify with `lsof -ti :PORT`. Never `pgrep -f` a pattern that appears in your own command line: the list shows your own wrapper and a kill can terminate the command itself (exit 143); use a bracket pattern (`pgrep -f "[v]ite"`) or `lsof` instead.
- Front-load one probe run that answers every environment unknown before you write the driver: rAF fps, overlay DOM rects, pointer and touch plumbing with ids and targets, autoplay policy, AudioContext initial state, and a console-message audit. Record each answer once and never re-measure. A branch headless cannot exercise gets a one-line "unit-covered" note, never more iteration.

## Playwright evaluate and waits
- `page.evaluate("...")` with a string argument evaluates the string as an expression. Playwright does not auto-invoke function strings (Puppeteer does), so a bare arrow-function string returns `undefined`. Write multi-line snippets as IIFEs: `page.evaluate("(() => { ...; return x; })()")`. `page.evaluate` transfers serializable data only, callbacks `await` only when `async`, and values cross through evaluate args or `globalThis`, never Node scope.
- Bound every wait. Pass explicit timeouts to `goto`, `waitForFunction`, and `waitForSelector`, set `protocolTimeout` in launch options, and print one step log line per phase. One unbounded wait hangs the run until the shell timeout kills it (exit 143) with no hint where. When a run hangs, read the step log you printed; do not build a new theory first.
- Harness cleanup (`finally`, stopServer) kills the dev server, so a later standalone probe hits ERR_CONNECTION_REFUSED. Start the server and run the probe or driver in one bash command, or make every probe own or reuse the server lifecycle, and curl the port immediately before any page load.

## Timing and assertions
- A large WebGL canvas under headless SwiftShader renders at a few fps: physics with a frame-dt cap runs in slow motion and `page.click` actionability waits scale into multi-second stalls. Prefer raw `page.mouse` or CDP coordinate dispatch. Never read slow-motion timing or sparse event rates as product behavior.
- Sample dynamic state shortly after the input (about 80 to 150 ms), not after settle. Wall bounces absorb launch speed within a second, so end-state speeds read as zero, and a bare float inequality on near-zero values passes without evidence. Assert a sampled maximum against an explicit threshold.
- Copy every expectation from source, never derive it in-head. Read the code that sets a UI state (disabled, hidden, counts, classes) and port its rule and constants into the driver. Widen a failed search once at most, never guess file after file.

## Driver authoring
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers, frame grabbers) plus Node-side helpers (serve, contexts, dispatch, capture, results file). Import it into every driver and probe, never copy it per script. Run `node --check` after every write.
- Parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change, not an edit. Run one smoke scenario end to end, console capture included, before the full matrix. Long suites go background (`nohup node ... > log 2>&1 &`), tail the log in separate calls, print each check as one compact line, and write full results to a JSON file. Never pipe a driver into `head`.
- Enforce a clean-page console gate only after a smoke-run console audit: classify each message as product error or environment artifact and whitelist artifacts by pattern with timestamps. Known headless SwiftShader artifacts here: a WebGL context-lost message at page load and ReadPixels GPU-stall warnings. Confirm with a grep of `src/render/` and one mid-flight screenshot before you whitelist.
- Init scripts run on every navigation and reload. Guard a `localStorage` seed with a `globalThis` marker so a reload does not re-seed and mask the behavior under test. Make scene setup deterministic: drive bodies to fixed spots with gestures; a retry loop over random states multiplies run time and flakiness.
- Route every dispatched coordinate through one harness normalizer that clamps to canvas bounds and asserts `Number.isFinite`. Convert with one set: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`, never assume `devicePixelRatio`), then css px to world.
- Pin pointer and touch dispatch semantics empirically in the probe before you author gesture scenarios: what the points arrays of `Input.dispatchTouchEvent` mean on touchStart, touchMove, and touchEnd, the pointerId mapping, and whether two points produce two pointerdowns. Log every event with `pointerId`, target, and coordinates into an in-page array; when an expected event is missing, compare coordinates against overlay rects and the event log first, and suspect dispatch semantics only after that.

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, units, and timing before product hypotheses. Print the actual live values at the decision point before reading more product code. Instrument (step logs, timeouts) and rerun instead of looping hypotheses in thinking; after two failures in one run, batch-audit every failure in one pass, classify each as driver bug, harness bug, or product bug, and fix the shared root cause once.

## Environment loss recovery
- If bash suddenly fails with "Working directory does not exist", the cwd (normally a worktree) was externally deleted. Recover in a few calls, do not diagnose at length: recreate the missing directory path with a placeholder file to revive the tool, recreate the worktree from the task's pinned commit with `git worktree add`, restore the kanban and task-file symlinks, restart the server, and re-check the task card. Empty board results mean a lost anchor, not an empty board.

## Wrap-up
- File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria, checking for a duplicate card first. Resolve the card id from the worktree task-file symlink; a bare "TASK.md" returns not-found. State harness assumptions and environment limits in one clean Notes pass, persist measured numbers once, kill every server you started and verify each port with `lsof`, and finish with a results table that maps every check to a pass or a filed card.
