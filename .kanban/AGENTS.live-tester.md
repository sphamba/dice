# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and inspection

- Read the task file first and fix the acceptance scope and task id from it. Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors, serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time; one multi-file dump truncates). All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; drop precedent checks that do not map to acceptance; never revisit that list later.
- Live-testing can run after the merger: `git diff main...HEAD` may be empty because the fix is already merged. Locate the task's commits (`git log --grep "<task-id>"` on main or the branch), review those diffs, and confirm the served app actually contains the fix before probing behaviour.
- Match verification depth to the diff. Small or deletion-only diffs need static proof only: batched `git show` / `git diff --stat`, no orphaned imports, structural test counts via `rg -n '^\s*(it|test)\('` (data loops and `it.each` multiply tests). Do not launch the app unless acceptance demands a live run.

## Probes and deliberation

- Front-load ONE timed environment probe that answers every environment unknown once: fps, WebGL2, reported viewport, canvas backing size versus `clientWidth * devicePixelRatio`, helper return shapes, event injection, console texts. Print one whole `JSON.stringify` sample of every captured event and helper return BEFORE consuming fields. Build it only from primitives verified standalone FIRST: a risky primitive (CDP overrides, viewport forcing, pointer or event injection) gets a 10-line probe before it enters the shared harness. `node --check` passes code with undefined identifiers and wrong property names.
- Never derive physics, geometry, projection, or engine math in-head. Before authoring any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle or motion is detected). Every threshold must trace to a measured reference captured in the SAME run as the assertion (calibrate against a control reading, e.g. the feature switched off), never to a later rerun; every settle or flight timer arms BEFORE its trigger. Tag every harness quantity with its unit in the name (mm, cssPx, backPx), print one known length through the same scale chain before any measurement code runs, and calibrate motion helpers and numeric instruments once on a known signal.
- Deliberation is not inspection. An open "how do I measure or access X", or "does X throw or degrade", that survives one read is answered by a 10-line probe or ONE targeted grep, not by tracing call paths in-head. Three self-corrections in a row (wait / actually / BUT / a re-derivation) mean STOP and print live values or pixel data. One hypothesis cycle per anomaly, then measure. Write the plan once as a short numbered list and execute it; a plan restated in a second block is already wasted time.
- On a FAIL, the FIRST action is a raw-sample probe at the decision point, read from the run log: build the dump INTO the first driver (on any failed check, print the raw pixel grid, sample values, and reference readings at the decision point), so failures are diagnosed without writing a new driver. Classify each failure as harness bug, harness limit, or product defect from captured record fields BEFORE listing hypotheses or touching thresholds. Two or more failures with one signature share one root cause: fix the shared cause or label the limit, and rerun only the invalidated checks. Never nudge the same threshold twice, and never patch an assertion to match a reading.

## Headless rendering and emulation

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await (even plain counters), while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side, arm traces before triggers, and measure fps once in the environment probe. SwiftShader runs far below display fps, so use the fewest bodies that exercise the check.
- Never read pixels with `drawImage` + `getImageData` on the WebGL canvas: it returns the LAST COMPOSITED bitmap, stale by many frames under SwiftShader, and produces phantom anomalies. Read with `gl.readPixels` inside the same rAF tick after the app's draw: one `readPixels` per region (slice it in-page; many tiny reads per frame are slow), Y-flipped (GL origin is bottom-left) and edge-clamped. `preserveDrawingBuffer` is false by default: readPixels outside the render rAF returns black. Cache `WEBGL_lose_context` with `getExtension` BEFORE calling `loseContext`; the handle is null after loss. Assert fractions over spans or windows, never single pixels or midpoints (one pixel can be a pip, an AA edge, or a hollow-centre fragment), and window each body separately: one scanline or column can cross several bodies.
- Playwright's own viewport emulation overrides raw CDP `setDeviceMetricsOverride`: CDP metric changes do not stick and fire no resize event. Force viewports with `page.setViewportSize` (accepts 0x0 and fires a real resize; it protocol-errors on a maximized window, so pin `viewport` at context creation or CDP-restore the window state first) or with a 0x0 context viewport for degenerate loads. Pin `viewport` at context creation anyway: device descriptors ship a viewport SMALLER than the screen, and dpr is capped in headless (verify the cap once). After any resize, canvas backing size and resize-derived state settle asynchronously: wait a few hundred ms before reading them.

## Visual evidence

- A visual anomaly is a data question, not a theory question. FIRST action: a measuring script (pixel spans, centroids, luminance grids). SECOND action: a pixel diff against a verified baseline (`magick compare -metric AE` exits 1 when images differ; parse the first stderr token and tolerate exit 1). Verify the baseline commit predates the feature BEFORE investing in it. A head-versus-base difference where BOTH sides look wrong is pre-change or environment evidence, not a defect: confirm with one screenshot pair and crops, then record it as an observation.
- Fixed-distance patches around a body are contaminated by its tilted silhouette: compute the max reach from source constants (half-diagonal, corner radius, orientation) and place patches beyond it, or classify a grid over the cell instead of single points. A "no effect" reading from a contaminated or occluded patch is void, not a defect.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, world spies, readback helpers, guards, results writer, console whitelist in one place). Copy precedent drivers; edit only imports and paths. Never write a probe against remembered or imagined helper names: grep the harness exports first and cross-check every call site in the same writing pass. Pass REAL functions to `page.evaluate`, never function-source strings: Playwright serializes and CALLS a function, but evaluates a string as an expression, so a string returns the function itself and downstream reads go `undefined`. Wrap injected snippets through one helper that makes invocation explicit.
- Compute geometric feasibility, never assume it: before any drag-to-target or sampling check, print target versus body half-width, wall clearance, panel rect, and max silhouette reach; clamp targets into reachable bounds; guard every drag with respawn-until-grabbable (a die can spawn under the expanded controls panel) and a null-result guard that names the miss. Space CDP `mouse.move` samples 40 ms or more apart; they coalesce.
- Check-in ladder for EVERY harness, driver, or probe write: `node --check` in the next command, then a 2-5 s smoke launch with the clock and spy wrappers installed (grep the console for ReferenceError and TypeError), then one whole-data-path smoke on a single capture that ASSERTS the captured object is defined and has the expected fields (a smoke that only greps the console lets an evaluate-shape bug through), then the full run. Choose the smoke strategy in one line and run it; do not re-deliberate launch-versus-kill. Setup parity: every precondition the probe needs (a panel or toggle open, for example) appears in the driver at the same point, and every click is gated on visible and enabled. A wrapper bug found at the end of a long run voids the run; a smoke run costs seconds. One results-writer code path shared by all modes.
- File edits are atomic: a failed multi-edit applies nothing. After any failed or doubtful edit, re-read the file before editing again. When a harness file is short and its state is unclear after an edit failure, rewrite it in full instead of stacking partial edits.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root). Start the server BEFORE any HTTP check; combine reuse-check and start in one command. Vite binds the IPv6 loopback only: use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL before any browser step, and build route-rewrite spies from the SERVED response body, not repo source. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). No global `playwright` exists and ESM import ignores NODE_PATH: locate it once and import by absolute path; binaries live in `~/.cache/ms-playwright`. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate the path, `git worktree add` from the pinned commit, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths: `cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`. Use a unique log per attempt. Sleep, then tail once (an immediate tail races log creation; never pipe into `head`). Grep large logs with `grep -a`; binary bytes make plain grep print "binary file matches". Kill by PID or by port (`lsof -ti :PORT | xargs -r kill`), never by a pkill pattern that can match your own command line. Before killing PIDs found by a broad search, read `ps -o pid,args -p <pids>` and kill only PIDs whose args point at your own harness directory or port: other live-tester runs share the machine, and an unattributed process belongs to another task. Mark batched bash sections with `echo "== section =="`. Gate expensive phases behind env vars so a rerun can skip them.
- A check that depends on a random draw (spawn position, shuffle, impact strength) uses retry loops with per-attempt pass flags, logged draw inputs, and end-state assertions over displacement thresholds. Freeze the scene and confirm stillness across consecutive samples before any pixel assertion.
- Post-green discipline: a green run is done. Do not re-litigate passing numbers with speculation. An odd passing number gets one raw-trace print, then it is recorded as a report observation (a harness clock or sampling artifact) or dropped. Never invent new failure hypotheses or rerun detectors after green. Wrap up in one pass: file confirmed product defects as cards (evidence, root cause with file and line references, fix direction, duplicate check first), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with its reason), or a filed card. At most one interim notes checkpoint mid-run; the final notes rewrite is the record. Kill every server you started and verify each port with `lsof`. Persist notes once and end the turn without `orchestrator_wait`; the checkpoint release arrives as injected context.
