# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass that resolves every harness open question at once: modules under test, consumer and mount-point files, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "CANDIDATE_A|CANDIDATE_B" src/`, then read the single defining module), build command, harness runtime location, `git log --oneline -10`, toolchain checks, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each `results.json`/log, names do not map to task numbers). Copy a prior driver and edit only imports and paths, never retype algorithms. Commit the harness choice in one written line and do not re-justify it in later turns. Bound every command's output (`-l`, `-m 20`, `| head`), never cat a large reference file inside a combined command, and remember a grep with no match exits 1 and aborts an `&&` chain.
- Pick the cheapest harness that reaches the code under test. Pure module with no browser consumer: Node ESM driver importing by absolute path. Rendered page: browser harness. An empty grep for importers is a finding that settles the harness question.
- No global `playwright` exists. ESM `import` ignores `NODE_PATH`, so import Playwright by absolute path from a repo that has it and verify with a real dynamic import. Browser binaries live in `~/.cache/ms-playwright`.
- Serve with `python3 -m http.server <uncommon-port> -d <dir>` (or `npx vite` when bundler behavior matters). Check the port free, curl HTTP 200 for the page and each module URL, start detached (`setsid`), kill by port at the end and verify. Never `pkill -f` a pattern that appears in your own command line. A probe page must be symlinked into the served directory and curled once, a 404 fails silently.

## Driver authoring
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, frame grabbers, unit converters) plus Node-side helpers (serve, contexts, PNG dumps). Import it into every driver and probe, never copy it per script.
- Init scripts run on every navigation and reload. Guard a `localStorage` seed with a `globalThis` marker so a reload does not re-seed and mask the behavior under test. A persistence check across reload must verify the app's own write, not the seed reapplying itself.
- Copy every expectation from source, never derive it in-head. Read the code that sets a UI state (disabled, hidden, counts, classes) and port its rule and constants into the driver. Port formulas from the module under test, not from memory. Widen a failed search once at most, never guess file after file.
- `page.evaluate` accepts serializable data only, make callbacks `async` when they `await`, share values via evaluate args or `globalThis`, never Node scope. Synthetic events need `defineProperty` instance props, a controlled `timeStamp`, and a `maxTouchPoints` override when code gates on it.
- Parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change, not an edit. Run one smoke scenario end to end, including console capture, before the full matrix. Long suites go to background (`nohup node ... > log 2>&1 &`), tail the log in separate calls, and print each check as it completes.
- Enforce a clean-page gate only after a smoke-run console audit. Classify each message as product error or environment artifact (headless Chromium logs blocked `navigator.vibrate` calls, AudioContext starts `running` so `resume()` never fires) and whitelist the artifacts before the gate counts them.
- Before writing a check that depends on browser-environment behavior (autoplay policy, initial AudioContext state, vibration support, timer or frame throttling), run one tiny probe evaluate that prints the actual behavior, then write assertions to match. A branch headless cannot exercise gets a one-line "unit-covered" note, never more iteration.

## Browser and canvas specifics
- Measure rAF fps in the first browser run and record it. A large WebGL canvas under headless SwiftShader renders at a few fps: physics with a frame-dt cap runs in slow motion, and `page.click` actionability waits scale with frame time into multi-second stalls. Prefer raw `page.mouse.click`/`move` at coordinates. When a click produces no reaction, settle arrival first (one-shot listener plus `elementFromPoint` at the target center) before suspecting pick logic. Never read slow-motion timing or sparse event rates as product behavior, rate and time-window gates stay in unit tests.
- Convert coordinates with one converter set: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`, never assume it equals `devicePixelRatio`), then css px to world m. Validate the converters before behavioral checks. Never guess the screen position of a rendered object: dump one frame to PNG (in-page `toDataURL` inside the rAF job that renders it, a readback outside that job returns a cleared or stale buffer, crop with ImageMagick, PIL is not installed), read it, and derive css coordinates from the image.
- Make each check robust to scene noise: per-body metrics over raw pixel diffs, speckle filtered by a minimum pixel area. Write output to a log file and confirm the dump code ran before reading a PNG.

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, and units before product hypotheses. After two failures in one run, stop and batch-audit every failure in one pass, classify each as driver bug, reference bug, or product bug, fix the shared root cause once, and rerun. A second thinking or text pass over the same audit is waste.
- Collect runtime evidence before reading more product code: print the actual live values at the decision point instead of re-deriving. Never hand-derive formulas, hashes, seeds, or float arithmetic, copy the exact function into a scratch script and print intermediates. A value off by a scale factor means check unit conversions (css px, backing px, world m, DPR) first. A measured value that saturates its window is a meter artifact, audit the meter or scan code before hypothesizing.
- Numeric expectations (thresholds, tolerances) must come from measured data: print the values first, then set the bound. A flaky check needs a metric change, not a rerun. Isolate an anomaly by changing one variable at a time and prefer a direct probe over grep archaeology. When timestamps look impossible, print page `performance.now()` beside real time at every driver step in one aligned-timeline run, never correlate timestamps across runs. Run `node --check` after every write.

## Wrap-up
- File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria, checking for a duplicate card first. Resolve the task card id from the worktree task-file symlink, a bare "TASK.md" returns not-found.
- State harness assumptions, driver bugs fixed, and environment limits (fps, unexercisable branches marked unit-covered) in one clean Notes pass, scan for duplicated lines before posting. Persist measured numbers once and reuse them when writing cards. Kill every server you started and verify each port with `lsof`. Finish with a results table that maps every check to a pass or a filed card.
