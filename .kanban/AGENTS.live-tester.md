# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass that resolves every harness open question at once: modules under test, consumer and mount-point files, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the single defining module), build command, harness runtime location, `git log --oneline -10`, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file or log, names do not map to task numbers). Copy a prior driver and edit only imports and paths, never retype algorithms. Commit the harness choice in one written line and do not re-justify it later.
- Pick the cheapest harness that reaches the code under test. Pure module with no browser consumer: Node ESM driver importing by absolute path. Rendered page: browser harness. An empty grep for importers is a finding that settles the harness question.
- No global `playwright` exists. ESM `import` ignores `NODE_PATH`, so import Playwright by absolute path from a repo that has it and verify with a real dynamic import. Browser binaries live in `~/.cache/ms-playwright`. Serve with `python3 -m http.server <uncommon-port> -d <dir>` (or `npx vite` when bundler behavior matters). Check the port free, curl HTTP 200 for the page and each module URL, start detached (`setsid`), kill by port at the end and verify with `lsof`. Never `pkill -f` a pattern that appears in your own command line. A probe page must be symlinked into the served directory and curled once; a 404 fails silently.
- Front-load one probe run that answers every environment unknown before you write the driver: rAF fps, canvas background color, hit-target geometry (dump the DOM rects of every element that overlays the canvas), pointer and touch event plumbing with ids and targets, object pixel detection, and each browser-behavior question (autoplay policy, AudioContext initial state, vibration support, timer throttling). Record each answer once and reuse it, never re-measure later. A branch headless cannot exercise gets a one-line "unit-covered" note, never more iteration. Enforce a clean-page gate only after a smoke-run console audit: classify each message as product error or environment artifact and whitelist the artifacts before the gate counts them.
- Measure rAF fps once in the probe and record it. A large WebGL canvas under headless SwiftShader renders at a few fps: physics with a frame-dt cap runs in slow motion, and `page.click` actionability waits scale with frame time into multi-second stalls. Prefer raw `page.mouse` or CDP coordinate dispatch. Never read slow-motion timing or sparse event rates as product behavior; rate and time-window gates stay in unit tests.

## Input and multi-touch
- Pin pointer and touch dispatch semantics empirically in the probe before you author gesture scenarios: what the points arrays of `Input.dispatchTouchEvent` mean on touchStart, touchMove, and touchEnd (which points appear, move, or lift, and what an empty or listed array lifts), the pointerId mapping, and whether two points on the canvas produce two pointerdowns. Never encode unverified lift semantics in the harness; a wrong lift rule silently produces false failures and false passes that cost a full diagnosis cycle.
- Log every pointer and touch event with `pointerId`, target, and coordinates into an in-page array, and dump the rects of overlay elements. When an expected pointer event is missing, compare the dispatched coordinates against the overlay rects and the event log first, and suspect dispatch semantics only after that. Do not filter events by target while you diagnose.

## Driver authoring
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, frame grabbers, unit converters, event loggers) plus Node-side helpers (serve, contexts, touch dispatch, frame capture, blob analysis). Import it into every driver and probe, never copy it per script.
- Route every dispatched coordinate through one harness normalizer that accepts every point shape in play (`{x,y}`, blob centroids, screen and world pairs), clamps to canvas bounds, and asserts `Number.isFinite` before dispatch. Mixed shapes silently produce NaN and a CDP "Invalid parameters" error one scenario deep.
- Init scripts run on every navigation and reload. Guard a `localStorage` seed with a `globalThis` marker so a reload does not re-seed and mask the behavior under test. A persistence check across reload must verify the app's own write, not the seed reapplying itself.
- Copy every expectation from source, never derive it in-head. Read the code that sets a UI state (disabled, hidden, counts, classes) and port its rule and constants into the driver. Port formulas from the module under test, not from memory. Widen a failed search once at most, never guess file after file.
- `page.evaluate` accepts serializable data only, make callbacks `async` when they `await`, share values via evaluate args or `globalThis`, never Node scope. Synthetic events need `defineProperty` instance props, a controlled `timeStamp`, and a `maxTouchPoints` override when code gates on it.
- Parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change, not an edit. Run one smoke scenario end to end, including console capture, before the full matrix. Long suites go to background (`nohup node ... > log 2>&1 &`), tail the log in separate calls, and print each check as it completes. Run `node --check` after every write.
- Never pipe a long-running driver into `head`: SIGPIPE kills node midway and the truncated output reads as a late-stage failure. Bound only short exploratory commands; a driver always writes to a log file that you tail.
- Make scene setup deterministic. Do not re-roll random states and hope for geometry conditions (interior rest, separation, visibility); drive bodies there with single-pointer gestures to fixed far-apart spots, then run the scenario under test. A retry loop over random states multiplies run time and flakiness.

## Browser and canvas specifics
- Convert coordinates with one converter set: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`, never assume it equals `devicePixelRatio`), then css px to world m. Validate the converters before behavioral checks. Never guess the screen position of a rendered object: dump one frame to PNG (in-page `toDataURL` inside the rAF job that renders it, a readback outside that job returns a cleared or stale buffer) and derive css coordinates from the image. Confirm the dump code ran before you read a PNG. Make each check robust to scene noise: per-body metrics over raw pixel diffs, speckle filtered by a minimum pixel area.

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, units, and coordinate shapes before product hypotheses. After two failures in one run, stop and batch-audit every failure in one pass, classify each as driver bug, harness bug, or product bug, fix the shared root cause once, and rerun. A second thinking pass over the same audit is waste.
- Collect runtime evidence before reading more product code: print the actual live values at the decision point. A value off by a scale factor means check unit conversions first. A measured value that saturates its window is a meter artifact. Numeric expectations must come from measured data; a flaky check needs a metric change, not a rerun. Isolate an anomaly by changing one variable at a time and prefer a direct probe over grep archaeology. When timestamps look impossible, print page `performance.now()` beside real time at every driver step in one aligned-timeline run, never correlate timestamps across runs.

## Environment loss recovery
- If bash suddenly fails with "Working directory does not exist", the cwd (normally a worktree) was externally deleted. Recover in a few calls, do not diagnose at length: recreate the missing directory path with a placeholder file to revive the tool, recreate the worktree from the task's pinned commit with `git worktree add`, restore the kanban and task-file symlinks, restart the server, and re-check the task card. Empty board results mean a lost anchor, not an empty board. If the card state changed externally, respect it and still record your results in Notes.

## Wrap-up
- File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria, checking for a duplicate card first. Resolve the task card id from the worktree task-file symlink, a bare "TASK.md" returns not-found. State harness assumptions, driver bugs fixed, and environment limits in one clean Notes pass, scan for duplicated lines before posting, and persist measured numbers once. Kill every server you started and verify each port with `lsof`. Finish with a results table that maps every check to a pass or a filed card.
