# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope, verification, and counting
- Read the task file first and fix the acceptance scope. Then run ONE batched inspection pass that resolves every open question at once: modules under test, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the defining module), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file; names do not map to task numbers). Include in the same pass the full shape of every event/state object the driver will consume: classify from one printed live sample per type instead of reconstructing an object shape with repeated greps across files. Copy a prior driver and edit only imports and paths. Commit the harness choice in one written line and never re-justify or re-litigate it later.
- Match verification depth to the diff. Deletion-only or small-diff tasks need static proof only: full `git show`, diff touches only the named file, no orphaned imports (`rg -c` per imported identifier), `node --check` per touched file. Verify a merged commit in ONE batched command (`git rev-parse main HEAD; git log --oneline -5; git show --stat HEAD; git diff main...HEAD --stat`): empty diff output plus rev-parse equality means merged, stop there. Never reconcile a test count with naive greps: `it.each` and `describe` loops over data arrays multiply tests, so count structurally (`rg -n '^\s*(it|test)\('`), read the generator's array length, and settle the arithmetic in one pass. Do not launch the app unless acceptance demands a live run.
- Pick the cheapest harness that reaches the code under test. When any mechanic is uncertain (focus, clipping, visibility, dispatch order, what the served module looks like), write a 10-line probe that prints the answer instead of deliberating in thinking. Do not re-derive physics, engine math, or DSP behavior in-head: read constants from source or measure them in a probe, then cite the measured value. A wrong cheap choice costs one rerun; long in-head deliberation is pure loss.
- A route-rewrite or import-rewrite spy must match the SERVED module text, not repo source: curl the module URL from the dev server and build match and replace patterns from the response body (vite rewrites relative import specifiers to absolute paths).

## Environment and build
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`. Locate it once with a single home-wide search that excludes the browser cache (`find ~ -maxdepth 8 -type d -name "playwright*" -not -path "*ms-playwright*" 2>/dev/null`), record the absolute path, import from it. Binaries live in `~/.cache/ms-playwright`. Front-load ONE timed probe run that answers every environment unknown before any driver is written: write the unknown list down first (launch, rAF fps, WebGL2, autoplay policy, initial and post-gesture AudioContext state, console message texts) and answer each exactly once, never re-measure.
- Build with `node node_modules/vite/bin/vite.js build` (`npm run build` dies in worktrees because the copied `.bin/vite` shim mis-resolves); serve with `npx vite --port <uncommon-port>`. Vite binds the IPv6 loopback only: use `localhost`, never `127.0.0.1`. Check the port free, curl HTTP 200 for the page and every module URL before any browser step, start detached (`setsid`), kill by port at the end, verify with `lsof -ti :PORT`. Never `pgrep`/`pkill -f` a pattern that appears in your own command line: bracket it or kill by port.
- Put `echo "== section =="` markers between parts of a multi-part bash command so a truncated result stays interpretable; when one call's output truncates, rerun only the missing part with tighter commands, not the whole batch.

## Numeric instruments (fits, band filters, decay estimates, spectral analysis)
- Calibrate a numeric instrument on a SYNTHETIC signal with known parameters (known decay rate, known frequencies, known sample rate) inside the same init script BEFORE pointing it at product data, and print measured versus expected. If an in-head-designed instrument fails against live data, that is an unvalidated instrument, not a product bug: stop, calibrate synthetically, then rerun. Every redesign-against-live-data cycle burns a full run.
- Read all environment constants from the live context and thread them into the analysis: `ctx.sampleRate` (often 44100, never assume 48000), the real buffer `length` for FFT bin math, channel count. Set numeric tolerances at float32 scale (AudioParam values round to float32, so about 1e-5 relative, not 1e-9). Assert transitions by final state, not by transition logs: a headless AudioContext can already be `running`, so a resume-path log never fires; assert the state after the gesture.
- Windowed RMS tail fits blend concurrent modes and can latch onto the zero-padded noise floor or a louder concurrent component. To measure one component's decay, band-pass at that component's known frequency, fit its envelope, and stop the fit at the first cliff to the numerical floor. Prefer robust orderings and distinctness checks (A decays slower than B) before fragile absolute windows; set absolute ranges from measured medians only after the instrument works, never before.

## Instrumentation and sampling
- Capture transients where the frames happen: wrap the hot loop in-page and record per-frame maxima; Node-side polling at coarse intervals misses apexes and one-frame spikes. Arm every sampler BEFORE the trigger, in the same sequence.
- Set check thresholds from what the instrument can observe, and state the derivation in one line. When a marginal check fails, fix the instrument once and rerun; never nudge the same threshold twice.
- When checks fail, suspect the instrumentation first (guards, timing, units, scope, install order, event-to-buffer pairing): print actual live values at the decision point before reading more product code. Once two or more checks fail, stop the run, batch-audit every failure in one pass (driver, harness, or product bug), fix the shared root cause once, and rerun only the invalidated checks. When extending driver check logic, plan all additions in one pass and apply as one edit batch; a grep-read-edit microcycle per assertion costs a call each.
- Keep the console whitelist in ONE place in the shared harness, imported by every driver and probe. Build patterns from the exact captured message text of the first audit run (copy-paste the payload; headless wording is literal, for example SwiftShader emits "CONTEXT_LOST_WEBGL", not "context lost", and vite dev chatter starts with "[vite]"). Never hand-write the regex from memory.

## State, focus, and motion
- Track toggle state in one driver variable that every action updates, and gate each phase on asserted preconditions instead of assuming them. A click leaves focus on the clicked control: blur before every keyboard-on-body check. Synthetic CDP key events never auto-repeat; a held key is one keydown. Copy every expectation (counts, labels, tab order; disabled controls are not tabbable) from source or the live DOM, never derive it in-head.

## Headless timing and pixel diffs
- Headless SwiftShader renders a WebGL canvas at a few fps: physics runs in slow motion and `page.click` actionability stalls, so prefer raw `page.mouse` or CDP coordinate dispatch and never read slow-motion timing as product behavior. Cap settle waits, use the fewest bodies that exercise the check, and on settle timeout fall back to state or geometry assertions, or reroll with fewer bodies, instead of waiting longer.
- Wrap ImageMagick `compare -metric AE`: it exits 1 when images differ (0 identical, 2 on error) and prints the metric to stderr, so tolerate exit 1 and parse the first stderr token. Localize a diff with per-region AE on crops of the moving region, and keep the pointer at one neutral position in baseline and post shots.

## Driver authoring and background runs
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers, `__drain`) plus Node-side helpers (serve, dispatch, capture, results file, console whitelist). Import it into every driver and probe, run `node --check` after every write, and parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change. `page.evaluate` needs IIFEs and passes at most one serializable argument; read in-page values with `page.evaluate` before using them in Node; install every helper set in every driver and diff a copied driver's setup sequence against the working probe. Route every dispatched coordinate through one harness normalizer (backing px to css px, clamp to canvas bounds, assert finite); pin pointer and touch dispatch semantics in the probe.
- Long suites go background as one standalone command: `setsid nohup node driver.mjs > log 2>&1 &`. An `&&` chain ending in `&` backgrounds the whole list. An immediate tail races log-file creation: sleep, `ls` the log, then tail in a follow-up call. Never pipe a driver into `head`.

## Debugging and wrap-up
- Wrap up in one Notes pass: file confirmed product defects and open questions as cards (evidence, root cause with file and line references, fix direction, acceptance criteria, duplicate check first), resolving the card id from the worktree task-file symlink. Kill every server you started and verify each port with `lsof`, persist measured numbers once, and finish with a results table mapping every check to a pass or a filed card. If bash suddenly fails with "Working directory does not exist", the worktree was externally deleted: recreate the path, `git worktree add` from the task's pinned commit, restore the kanban and task-file symlinks, restart the server, and move on. Do not call `orchestrator_wait`: only the project manager session waits for board reports.
