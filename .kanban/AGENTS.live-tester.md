# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and planning

- Read the task file first. Fix the acceptance scope and the task id from it (if the task file has no id, take it from one kanban query at the start and never re-derive it mid-run). Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors AND default UI state (grep the markup and CSS, never infer from class names), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time). Keep every enumeration short (`| head -50`): a flood of filenames forces a second run of the same command. All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; never revisit or re-enumerate that list in later turns. Match verification depth to the diff: a small or deletion-only diff needs static proof only, and no live run unless acceptance demands one.
- Map every phase to an acceptance criterion or a PM-named check before you write it; use the minimal phase that exercises the same constant; cut a phase on its second non-converging design iteration. Choose the gate type from the change shape: an instantaneous state change (delete, toggle, class flip) has no pixel motion, so gate on the resulting state (count, attribute, DOM), with a full-region screenshot diff only as secondary evidence. A phase whose outcome depends on uncontrolled collisions or equilibrium gets an observation-only check from the start; never a gate weakened, loosened, or reclassified after a FAIL. A detector whose sampling cadence cannot separate the candidate causes is a harness limit by construction: classify it as such at the FIRST flag, record once, never re-analyze, and never re-run hoping the flag goes away.

## Expected values and gates

- Before you author any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle is detected). Write every geometry derivation into that table ONCE; a second in-head re-derivation of the same quantity means stop and write it down. Every expected value comes from printed source lines or a measured reference captured in the SAME run, never from assumption. Tag harness quantities with units and compare like with like. Every settle or flight timer arms BEFORE its trigger. A copied check must stress the constant it tests, else it passes on pre-fix code and proves nothing.
- Pixel-space expectations (glyph size in px, px per metre, projected positions) come from ONE in-page probe that prints each live pipeline link - atlas glyph boxes, atlas-to-face scale, canvas size and DPR, camera projection - measured against one captured frame. NEVER chain source constants into a hand-derived pixel prediction. A derivation that misses the first measurement by more than about 30% is wrong: extend the probe to print the next link and find the broken one. Never test alternative scale factors in your head.
- Calibrate every pixel classifier and measurement gate from a PRINTED distribution of one captured frame (luma histograms of body versus ink, component extents) in the smoke phase, BEFORE any gate runs. Prefer relative thresholds (ink luma below a fraction of the per-face body luma) over absolute values; absolute luma thresholds shatter anti-aliased 1-2 px strokes into specks. Fix every gate value before the first gated run: a value changed after a FAIL means the calibration step was skipped. After two threshold nudges, stop and instrument the underlying distribution once.
- The first gated run is ONE face or ONE instance in ONE phase (phase filter), used to confirm calibration, then the full multi-phase run. Every full run carries a settle wait of a minute or more; never spend one on uncalibrated gates. Settle state is judged AT capture time with a bounded wait-verify-retry loop (2-3 attempts) written in from the start, not patched in after a flake.

## Probes and diagnosis

- Deliberation is not inspection. An open "how do I measure X" that survives one read gets a 10-line probe or ONE targeted grep, not an in-head trace of call paths. Three self-corrections in a row (wait / actually / BUT / a re-derivation) mean STOP and print live values or pixel data. A surprising number gets ONE raw print or one log grep, then it is recorded as an observation; never re-theorize it across thinking blocks. A number that resists three hypotheses gets one probe that prints every candidate cause in a single run.
- A TypeError or undefined-identifier error whose stack points inside harness or driver code is a data-shape bug in your OWN glue: read the exact call site and the producer of its argument (grep where the variable is assigned) BEFORE any probe or app-side theory. After the FIRST such error, check EVERY import of that file against the module exports and every cross-file argument shape in one pass, then re-run. Never rewrite a driver to escape an unexplained failure. If a reproduction probe does not reproduce, STOP probing and diff the probe's code path against the failing path line by line; two failed reproductions mean the difference is in your own code, not the app.
- A render anomaly that shows STRUCTURE (the same defect at matching positions across cells, faces, or instances) is a data-pipeline bug, not a sampling artifact. Name the pattern, then stop probing pixels: extract the suspect pure function into a standalone Node script with a synthetic input and run it. Scan intermediate arrays for non-finite values FIRST. The browser probe confirms the pattern; the Node repro names the root cause.

## Headless rendering and readback

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await, while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side; measure fps once in the environment probe; use the fewest bodies that exercise the check (software rasterizer fps is far below display fps). Capture the frame you analyse AFTER the trigger and its settle: a pre-spawn or cached frame reads stale pixels. `preserveDrawingBuffer` is false by default: read pixels with `gl.readPixels` inside the same rAF tick after the app's draw, one read per region (slice it in-page). Force viewports with `page.setViewportSize`, never raw CDP metric overrides. Canvas backing size settles asynchronously after a resize: wait a few hundred ms before reading it.
- NEVER bypass shared readback helpers with direct buffer indexing: raw `(y*w+x)*4` arithmetic skips the Y-flip of bottom-up `readPixels` and reads mirrored coordinates. After any driver rewrite, grep the driver for raw pixel indexing and for every helper the rewrite dropped. Symptom signature: after a rewrite, every face or instance reports zero hits or background while the crop image looks correct - that is a coordinate or flip bug in your own glue; one overlay of the sample window on the crop confirms it in minutes, not hypotheses.
- Setup-mechanism feasibility comes BEFORE any placement code: for each state a body must reach (drop, fling, settle against a surface, grab point), print the numbers that decide reachability (target versus body half-extent, expected rest offset, bounce behavior, max silhouette reach of the candidates). Prefer a mechanism that cannot miss (drive the body to the target) over one that must converge. If a placement mechanism fails to converge TWICE, the mechanism is wrong: switch mechanisms, never write attempt #3, and never run a phase's substance checks against a setup that missed its target. Gate every pointerdown with an in-page `document.elementFromPoint` check.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, world spies, readback helpers, guards, results writer, console whitelist in one place), with PORT/OUT/CWD read from env vars so copies can retarget. Copy precedent drivers; edit only imports and paths. When you copy, first grep the precedent for every absolute path and decide keep-versus-retarget per path in one pass; `sed` exits 0 on NO-match, so after any sed edit `grep -c` the old and new strings to verify the substitution count. A path that resolves node modules must keep pointing at the tree whose node_modules installs them. Never call a remembered helper name: grep the harness exports first, and cross-check every call site AND every argument shape in the same writing pass. Pass REAL functions to `page.evaluate` (Playwright calls a function but evaluates a string as an expression). No shared mutable scratch buffers between copied steps, and no stub or placeholder helpers in a driver write.
- Injected input is slow and lossy: one dispatch can take tens of ms, moves coalesce, and `mouse.up()` reuses the last move's coordinates. Give every move its own explicit position, space moves 40 ms or more apart, and read timings from in-page event records, never Node-side send times. A keyboard phase establishes its focus baseline first (blur, then assert `activeElement` is body) before its first Tab or Enter. Every press helper releases the button on EVERY exit path. Poll transitions, not flags: first wait for the state to move the RIGHT way, then wait for the settle flag. Every comparison check carries a non-degeneracy guard (operand ~0, null, or empty where a real signal is required means FAIL) and logs the operand. A retry loop over ONE mechanism is capped at two attempts before the mechanism itself is replaced.
- Phases are self-contained: each spawns or repositions its own target, asserts the target's identity BEFORE interacting, and establishes its own state (held pointers, focus, open/closed panels). Leftovers from an earlier phase leak and invalidate later checks. Compute interaction feasibility from printed numbers, never assume it; clamp targets into reachable bounds; a candidate search logs its candidate count and widens or switches strategy on zero hits instead of failing the check.
- Check-in ladder for EVERY harness, driver, or probe write: (1) match every import name against `rg -n "^export"` of its source file, mirroring non-exported constants locally with a source pointer; (2) `node --check`; (3) after any edit, re-check syntax AND re-grep the edited block for sibling assertions the edit can have silently deleted; (4) a 2-5 s smoke launch that greps the console for ReferenceError and TypeError; (5) one whole-data-path smoke on a single capture that ASSERTS the captured object is defined and has the expected fields; (6) the one-instance calibrated run; (7) the full run. A failed multi-edit batch is atomic: one unmatched oldText rolls back the whole call; re-read the exact region and reapply in the next commands, before any new analysis. The driver takes a PHASE FILTER env var from the start and writes results to a file whose name includes the run id AND the phase filter; print a results file's first entry before parsing it.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root). Start the server BEFORE any HTTP check. Vite binds IPv6 loopback only, so use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL first. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). A baseline worktree OUTSIDE the repo tree cannot resolve vite (npx ENOENT): keep baselines inside the repo tree or symlink `node_modules`. No global `playwright`, and ESM import ignores NODE_PATH: import it by absolute path, or via a `createRequire` that points at the tree installing it; browsers live in `~/.cache/ms-playwright`. Launch Chromium with `--disable-dev-shm-usage` from the first run: a mid-run renderer crash voids every later phase. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate it, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths (`cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`), a unique log per attempt, sleep then tail ONCE (an immediate tail races log creation; never pipe into `head`), `grep -a` on large logs, and `echo "== section =="` markers. Wrap each phase in try/catch with periodic page recreation so one crash does not void the rest of the run. After a run, extract env and summary lines by grepping the log; never re-run a phase because its output scrolled off. Kill by PID or by port (`lsof -ti :PORT | xargs -r kill`), never a pkill pattern that can match your own command line; verify absence with `pgrep -af` (a bare `pgrep -f` matches your own pipeline) or `lsof` on the port. After a final green run, one full-suite re-run to produce a single clean results file is the only re-run you may do; do not re-run to reconcile differing phase outcomes by analysis.
- Post-green discipline: a green run is done; do not re-litigate passing numbers with speculation (an odd passing number gets one raw-trace print, then it is recorded as an observation or dropped). Read the one or two evidence screenshots that carry the verdict, then write the report; do not debate whether evidence reading is in scope. At most ONE interim notes checkpoint mid-run, after the first full run; the final notes rewrite is the record.
- Wrap up in one pass: file confirmed product defects as cards (duplicate check first; the card tool requires a `summary` field; give evidence, root cause with file and line references, and a fix direction), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with its reason), or a filed card. Kill every server you started, verify each port with `lsof`, persist notes once, and end the turn without `orchestrator_wait` (the checkpoint release arrives as injected context).
