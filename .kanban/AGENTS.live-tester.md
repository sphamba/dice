# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass: entry-point grep, reads of the modules under test, `git log --oneline -10`, toolchain checks (Playwright ESM import, free port), and the artifact harvest. Write the smallest harness (one scenario, one readback) immediately after, then extend scenarios only once it runs. Probe output settles design questions faster than deliberation.
- Harvest prior run material in the same pass: `/tmp/<repo>-lt*/` directories hold `reference.mjs`, `live.test.mjs`, and `expected.json`. Their names do not map to task numbers; list by mtime and read each `results.json`/`run.log` instead of guessing. Copy a prior reference or driver and edit only imports and paths; never retype algorithms from memory. Trace the feature's runtime data flow before designing the harness; if a producer of needed state is not merged yet, inject the state and record it in Notes as a test limit. Trust the repo state over the task prose.

## Reference math
- Port expected-value formulas verbatim from the source under test. Never derive geometry, contact counts, signs, or clip and weld behavior in-head: one dropped term or flipped axis invalidates every prediction and forces a redo. When a hand-derived expectation fails, suspect the derivation first and recompute it in the script. If behavior resists one in-head derivation, stop and write a trace or dump script that prints intermediates; do not re-derive.
- The reference script computes all expected values, writes one `expected.json` the driver reads, and models the pipeline in the code's order. It also derives scene layout by feasibility search (containment, clearance, non-overlap) instead of hand-picked offsets, classifies each probe sample against the surface or face it actually touches, and has a `--trace` mode that prints per-candidate verdicts. Write the expected JSON in a `finally` block so a failed assert still leaves the artifact.
- Validate the reference on static or frozen poses first, then extend to dynamic scenarios. Group checks by class (counts, on-plane, containment, depth, identity) so a failure names its class. Record diagnostic deviations (per-point deviation, plane distance, footprint overshoot) into the results JSON automatically; a failure must be diagnosable from the artifact without a rerun.

## Comparisons and tolerances
- Never guess a tolerance. When a check fails on magnitude only, dump the recorded data and print the worst observed deviation, then set the tolerance from that measurement. A tolerance set without measurement produces repeat false failures.
- Compare unordered point or corner sets by nearest-neighbor matching, never index-aligned; float ties make sort order unstable across runs.
- A containment or legitimacy check that assumes a fixed owner (reference face, incident face, hit surface) must accept both ownership directions; solver-internal selection can flip between near-equivalent poses. Verify every check's sign and orientation against real recorded data once before trusting it.
- Read back state at the measurement boundary. If the engine mutates bodies after the event you assert on (for example detection before integration), capture pre-step state through an engine hook (before-step) into a snapshot and read recorded values from that snapshot, never from live objects after the step. Fix a staleness or ordering defect once, in the shared helper, and apply it to every scenario that reads the same data.

## Environment
- No global `playwright` package; browser binaries live in `~/.cache/ms-playwright`. A usable package exists in other repos (e.g. `/home/phamba/repos/tarot/app/node_modules`). ESM `import` ignores `NODE_PATH`; import Playwright by absolute path and verify with a real ESM dynamic import (`node -e "import('<abs path>').then(()=>console.log('ok'))"`).
- Serve with `python3 -m http.server <uncommon-port> -d <repo-dir>` for plain ES modules, or `npx vite --port <port>` when bundler behavior is needed. Check the port is free (`lsof -i:<port>`) and curl-check HTTP 200 for the page and module URLs. Start servers detached (`setsid`); track every port you started; at the end kill each by port (`lsof -t -i:<port> | xargs -r kill`) and verify with `lsof`. Never `pkill -f` a pattern that appears in your own command line; do not touch ports you did not start.
- Headless Chromium (SwiftShader): keep `readPixels` readbacks few, rerun once on CONTEXT_LOST, and use pixel values as evidence (dump frames in-page with `canvas.toDataURL('image/png')`, then crop with ImageMagick; PIL is not installed). Classify environment anomalies with at most one probe plus a page reload; keep them out of pass/fail tallies and record them in Notes. Synthetic events need instance properties set via `defineProperty`, a controlled `timeStamp`, and a `navigator.maxTouchPoints` override when code gates on it.

## Scripts, shell, and edits
- Grep the `export` lines of every module a script imports and copy the exact names before writing it. Offset-read large modules; grep for line numbers first when an offset read misses. Grep for helper files before referencing their paths.
- `node --check` immediately after every write. After a long write, read the file back and verify the tail before running. Before the first run, grep your own script for hardcoded magic numbers, dead assignments, and unused helpers. Rewrite the whole file instead of chaining edits when the structure changes.
- Shell traps: a `grep` with no match exits 1 and aborts an `&&` chain. `$?` after a pipe is the last stage's code; when the exit status matters, run the command bare or read `${PIPESTATUS[0]}`.
- Batched edit calls are atomic: one mismatched `oldText` means nothing applies. Grep-verify each target snippet first; on failure, reapply in small verified chunks or rewrite the file.

## Drivers
- `page.evaluate` accepts serializable data only. Make callbacks `async` when they `await`; share values through `globalThis` or evaluate arguments; never close over Node scope. Declare each variable in the function that uses it.
- A module the app does not import yet is still testable: serve the repo and `await import('/src/<path>.js')` in the page; capture console and page errors in the driver. Run hygiene: smoke-test one scenario end to end, including the harness math, on an asymmetric non-zero point before the full matrix; write output to a log file and tail it; print each check as it completes; set a page default timeout (15-20 s); batch all contexts into one script. Update todos only at phase transitions, 3-5 items total.
- Define each scenario once as data (initial state, per-step resets, measurement flags, tolerances) consumed by both reference and driver. Adopt tolerance and layout choices from prior artifacts wholesale instead of re-deciding settled questions. Reset every state field between measured steps, assert at the exact step boundary the scenario defines, and keep test objects inside bounded geometry at all times.

## Failure diagnosis
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, and scenario before forming product hypotheses; most single-check failures are harness bugs. After two failed checks in one run, stop and batch-audit every failure, classifying each as driver bug, reference bug, or product bug; fix the shared root cause once, regenerate the expected data, and rerun.
- Time-box anomalies: a failure that does not block acceptance gets at most two probes, then annotate the check and move on. When a value is off by orders of magnitude, stop deriving in-head and write a script that calls the stage functions directly and prints intermediates.

## Wrap-up
- Persist measured numbers once (notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria. State harness assumptions and test limits in the task Notes.
- Resolve the task card id from the worktree task-file symlink before calling kanban tools; a bare "TASK.md" or a guessed name returns not-found. Draft task Notes in one clean pass and scan for duplicated lines before posting. Stop every server you started, verify each port with `lsof`, and finish with a results table that maps every check to a pass or a filed card.
