# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass: entry-point reads, modules under test, `git log --oneline -10`, toolchain checks, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each `results.json`/log; names do not map to task numbers). Copy a prior driver and edit only imports and paths; never retype algorithms from memory.
- Pick the cheapest harness that reaches the code under test, and commit to it in one written line during this pass. For a pure module with no browser consumer, skip Playwright and write a Node ESM driver that imports the module by absolute path from the worktree. Reserve browser harnesses for code that needs the rendered page. Do not re-justify the harness choice in later turns.
- Before writing any script, grep the `export` lines of every module it imports and copy the exact names. To find app-wide constants (sizes, radii, thresholds), run one repo-wide search (`rg -n "CANDIDATE_A|CANDIDATE_B" src/`) and read the single defining module. Bound every command's output (`-l`, `-m 20`, `| head`); never cat a large reference file inside a combined command. An empty grep for importers is a finding, not a miss: it settles the harness question. Widen a failed search once at most, never guess file after file.
- No global `playwright`; browser binaries live in `~/.cache/ms-playwright`. ESM `import` ignores `NODE_PATH`; import Playwright by absolute path from a repo that has it and verify with a real dynamic import.
- Serve with `python3 -m http.server <uncommon-port> -d <dir>` (or `npx vite` when bundler behavior matters). Check the port free (`lsof -i:<port>`), curl HTTP 200 for the page and each module URL, start detached (`setsid`), kill by port at the end (`lsof -t -i:<port> | xargs -r kill`) and verify. Never `pkill -f` a pattern that appears in your own command line. To serve a probe page next to the app, symlink it into the served directory and curl it once; a 404 fails silently. Capture `pageerror`, all console messages, and failed requests from the first run on.

## Environment probes before assertions
- Before writing any check that depends on browser-environment behavior (autoplay policy, initial AudioContext state, vibration support, timer or frame throttling), run one tiny probe evaluate that prints the actual behavior, then write assertions to match. Headless Chromium creates AudioContext already `running`, so `resume()` never fires there. A branch headless cannot exercise gets a one-line "unit-covered" note, never more iteration.
- Measure rAF fps in the first browser run and record it with the results. A large WebGL canvas under headless SwiftShader renders at a few fps: physics with a frame-dt cap runs in slow motion, and `page.click` actionability waits scale with frame time into multi-second stalls. Never read slow-motion timing or sparse event rates as product behavior; rate and time-window gates stay in unit tests.

## Harness and driver
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, rAF frame grabber, unit converters) plus Node-side helpers (serve, contexts, PNG dumps). Import it into every driver and probe; never copy it per script. Grab frames inside the rAF job that renders them; a readback outside that job returns a cleared or stale buffer.
- Convert coordinates with one converter set: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`, never assume it equals `devicePixelRatio`) then css px to world m. Validate the converters before behavioral checks (teleport a body to a known world point, click its computed position, assert the pick). Never guess the screen position of a rendered object: dump one frame to PNG, read it, and derive css coordinates from the image. Pixel-blob heuristics match UI and panel pixels; confirm candidates visually before interacting.
- Parameterize every driver with env vars from v1 (viewport, gesture targets, forced seeds, scenario phases) so a diagnosis rerun is a parameter change, not an edit. Run one smoke scenario end to end, including harness math, before the full matrix.
- `page.evaluate` accepts serializable data only; make callbacks `async` when they `await`; share values via evaluate args or `globalThis`, never Node scope. Synthetic events need `defineProperty` instance props, a controlled `timeStamp`, and a `maxTouchPoints` override when code gates on it. Long suites go to background (`nohup node ... > log 2>&1 &`); tail the log in separate calls and print each check as it completes.
- In heavy scenes prefer raw `page.mouse.click`/`move` at coordinates over `page.click(selector)`: selector clicks run actionability and hit-target checks per frame and stall for seconds at low fps. When a click produces no reaction, settle arrival first (one-shot listener plus `elementFromPoint` at the target center) before suspecting the app's pick logic.
- Make each check robust to scene noise: per-body metrics over raw pixel diffs, speckle filtered by a minimum pixel area. Write output to a log file; dump frames as PNG (in-page `toDataURL`, crop with ImageMagick; PIL is not installed) and confirm the dump code ran before reading the PNG.

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, and units before product hypotheses. After two failures in one run, stop and batch-audit every failure; classify each as driver bug, reference bug, or product bug; fix the shared root cause once and rerun.
- Collect runtime evidence before reading more product code: print the actual data (live values, per-type outputs) instead of re-deriving. A threshold question ("will this event exceed X?") is answered by printing the value from the instrumented page at the decision point, never by estimating geometry, masses, or impulses in-head. In-head derivation loops are the most expensive failure mode in this role.
- Never hand-derive formulas, hashes, seeds, or float arithmetic in-head; copy the exact function into a scratch script, print intermediates, and compare against the expectation. Port expected formulas from the source under test, not from memory. A measured value that saturates its window is a measurement artifact; audit the meter or scan code before hypothesizing physics.
- When event timestamps look impossible, print page `performance.now()` beside real time at every driver step in one aligned-timeline run; do not correlate timestamps across runs. Isolate a stall or anomaly by changing one variable at a time, and prefer a direct probe over grep archaeology.
- Numeric expectations (thresholds, tolerances) must come from measured data: print the values first, then set the bound. A flaky check needs a metric change, not a rerun. A value off by a scale factor means check unit conversions (css px, backing px, world m, DPR) first. Run `node --check` after every write; a grep with no match exits 1 and aborts an `&&` chain.

## Wrap-up
- Persist measured numbers once (task Notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria; check for a duplicate card first. Resolve the task card id from the worktree task-file symlink before kanban calls; a bare "TASK.md" returns not-found.
- State harness assumptions, driver bugs you fixed, and environment limits (fps, unexercisable branches marked unit-covered) in the Notes; draft Notes in one clean pass and scan for duplicated lines before posting. Kill every server you started and verify each port with `lsof`. Finish with a results table that maps every check to a pass or a filed card.
