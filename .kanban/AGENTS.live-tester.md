# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope, verification, and counting
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass that resolves every open question at once: modules under test, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the single defining module), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file; names do not map to task numbers). Copy a prior driver and edit only imports and paths. Commit the harness choice in one written line and never re-justify or re-litigate a settled decision later in the run.
- Match verification depth to the diff. For deletion-only or small-diff tasks, static proof is enough: full `git show` of the commit, diff touches only the named file, no orphaned imports or helpers (loop each imported identifier and `rg -c` its remaining uses), `node --check` on every touched file, and reconciled test arithmetic. Do not launch the app or the test suite unless acceptance demands a live run.
- Verify a merged commit in ONE batched command: `git rev-parse main HEAD; git log --oneline -5; git show --stat HEAD; git diff main...HEAD --stat`. Empty `git diff main...HEAD` output only means main already contains HEAD: confirm with rev-parse equality and `git show`, and never spend further calls re-deriving a clean worktree or a merged state.
- Never reconcile a recorded test count with naive greps. A fixed-indent `grep -c "it("` misses indentation variants and a word-boundary grep overcounts. Suspect generated or parameterized tests FIRST: a `describe` looping over a constant list emits one `it` per entry, and `it.each` or dynamic describes multiply too. Count structurally (`rg -n '^\s*(it|test)\('`), read the generator's data array length and multiply, and settle the arithmetic in one pass.
- Pick the cheapest harness that reaches the code under test. When any mechanic is uncertain (focus, clipping, visibility, dispatch order, what the served module looks like), write a 10-line probe that prints the answer instead of deliberating in thinking. Do not re-derive physics or engine math in-head: read constants from source or measure them in the probe, then cite the measured value.
- A route-rewrite or import-rewrite spy must match the SERVED module text, not repo source: curl the module URL from the dev server and build the match and replace pattern from the response body (vite rewrites relative import specifiers to absolute paths).

## Environment and build
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`. Locate it once with a single home-wide search that excludes the browser cache (`find ~ -maxdepth 8 -type d -name "playwright*" -not -path "*ms-playwright*" 2>/dev/null`), record the absolute path, import from it, then run one timed probe (dynamic import, `chromium.launch`, `newPage`, close) before writing any driver. Binaries live in `~/.cache/ms-playwright`.
- Build with `node node_modules/vite/bin/vite.js build`; `npm run build` dies in worktrees because the copied `.bin/vite` shim mis-resolves. Serve with `npx vite --port <uncommon-port>`. Vite binds the IPv6 loopback only: use `localhost`, never `127.0.0.1`, in health checks, BASE URLs, and curl. Check the port free, curl HTTP 200 for the page and every module URL before any browser step, start detached (`setsid`), kill by port at the end, verify with `lsof -ti :PORT`. Never `pgrep`/`pkill -f` a pattern that appears in your own command line: bracket it (`pkill -f "[d]river"`) or kill by port.
- Front-load one probe run that answers every environment unknown before you write the driver: rAF fps, WebGL2 availability, helper and event plumbing, autoplay policy, AudioContext state, and a console audit that captures exact message texts. Record each answer once and never re-measure.
- Put an `echo "== section =="` marker between the parts of a multi-part bash command, so a truncated result stays interpretable. When one call's output looks truncated, rerun only the missing part with tighter commands, not the whole batch.

## Playwright evaluate and waits
- `page.evaluate("...")` evaluates a string as an expression and does NOT auto-invoke function strings; write snippets as IIFEs (`page.evaluate("(() => { ...; return x; })()")`) and pass at most one serializable argument. Page state lives in the page: read any in-page value with `page.evaluate` before using it in Node, because a Node-scope reference to a page global is `undefined` and poisons a waitForFunction target with NaN. Install every in-page helper set in every driver; before running a copied driver, diff its setup sequence against the working probe, since one missing helper call costs a failed run.

## Instrumentation and sampling
- Capture transients where the frames happen: wrap the hot loop in-page (for example wrap the world `update` call) and record max speed, max height, and apex per frame. Node-side polling at 100 ms class intervals misses apexes and one-frame spikes, and sampling after settle measures nothing. Arm every sampler BEFORE the trigger, in the same sequence.
- Set check thresholds from what the instrument can observe: a sampled max underestimates peaks, so derive each pass threshold from the sampling design (frame-granular wrapper gives near-true peaks; coarse polls give much lower maxima) or from source constants, and state the derivation in one line. When a marginal check fails, fix the instrument once and rerun; never nudge the same threshold twice.
- When checks fail, suspect the instrumentation first (guards, timing, units, scope, install order, settle-vs-flight): print actual live values at the decision point before reading more product code. Once two or more checks fail, stop the run, batch-audit every failure in one pass (driver, harness, or product bug), fix the shared root cause once, and rerun only the invalidated checks.
- Keep the console whitelist in ONE place in the shared harness, imported by every driver and probe. Build patterns from the exact captured message text of the first audit run (copy-paste the payload; headless wording is literal, for example SwiftShader emits "CONTEXT_LOST_WEBGL", not "context lost", and vite dev chatter starts with "[vite]"), and grep a captured log against the pattern before gating. Never hand-write the regex from memory and never keep per-script copies.

## State, focus, and motion
- Track toggle state in one driver variable that every action updates, and assert expanded or collapsed at the top of each phase. One stale state assumption invalidates whole phases of checks; gate each phase on its preconditions instead of assuming them.
- A click leaves focus on the clicked control, so a later synthetic Space activates that control, not the page: blur or move focus before every keyboard-on-body check. Synthetic CDP key events never auto-repeat; a held key is one keydown, so test repeat suppression as one roll per keydown pair. Copy every expectation (counts, labels, tab order; disabled controls are not tabbable) from source or the live DOM, never derive it in-head.

## Headless timing and pixel diffs
- Headless SwiftShader renders a WebGL canvas at a few fps: physics runs in slow motion and `page.click` actionability stalls, so prefer raw `page.mouse` or CDP coordinate dispatch and never read slow-motion timing as product behavior. Cap settle waits at a few seconds, use the fewest bodies that exercise the check, and on settle timeout fall back to state or geometry assertions, or reroll with fewer bodies, instead of waiting longer.
- Wrap ImageMagick `compare -metric AE`: it exits 1 when images differ (0 identical, 2 on error) and prints the metric to stderr, so tolerate exit 1 and parse the first stderr token, and `ls` the filenames before batch compares. Localize a diff with per-region AE on crops of the moving region. A pointer resting on a button restyles it: keep the pointer at one neutral position in baseline and post shots, or crop the diff away from panel chrome.

## Driver authoring and background runs
- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers) plus Node-side helpers (serve, dispatch, capture, results file, console whitelist). Import it into every driver and probe, run `node --check` after every write, and parameterize drivers with env vars from v1 so a diagnosis rerun is a parameter change. Guard a `localStorage` seed with a `globalThis` marker so a reload does not re-seed. Route every dispatched coordinate through one harness normalizer: backing px to css px, clamp to canvas bounds, assert `Number.isFinite`; pin pointer and touch dispatch semantics empirically in the probe.
- Long suites go background as one standalone command: `setsid nohup node driver.mjs > log 2>&1 &`. An `&&` chain ending in `&` backgrounds the whole list. An immediate tail races log-file creation: sleep, `ls` the log, then tail in a follow-up call. Never pipe a driver into `head`.

## Debugging and wrap-up
- Wrap up in one Notes pass: file confirmed product defects and open questions as cards (evidence, root cause with file and line references, fix direction, acceptance criteria, duplicate check first), resolving the card id from the worktree task-file symlink. Kill every server you started and verify each port with `lsof`, persist measured numbers once, and finish with a results table mapping every check to a pass or a filed card. If bash suddenly fails with "Working directory does not exist", the worktree was externally deleted: recreate the path, `git worktree add` from the task's pinned commit, restore the kanban and task-file symlinks, restart the server, and move on in a few calls. Do not call `orchestrator_wait`: agent sessions are refused; only the project manager session waits for board reports.
