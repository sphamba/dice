# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and planning

- Read the task file first. Fix the acceptance scope and the task id from it (if the task file has no id, take it from one kanban query at the start and never re-derive it mid-run). Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors AND default UI state (grep the markup and CSS, never infer from class names), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time). Keep every enumeration short (`| head -50`). All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; never revisit or re-enumerate that list in later turns. Match verification depth to the diff: a small or deletion-only diff needs static proof only, and no live run unless acceptance demands one.
- Map every phase to an acceptance criterion or a PM-named check before you write it; use the minimal phase that exercises the same constant; cut a phase on its second non-converging design iteration (a gesture or setup mechanism that cannot satisfy one hard requirement from the input code is dropped at design time, not after more design rounds). Resolve an acceptance-wording doubt ONCE: reread the task line, commit to the strictest reasonable reading, and list it under assumptions in the report; never re-litigate it across thinking blocks. Choose the gate type from the change shape: an instantaneous state change has no motion to observe, so gate on resulting state (count, attribute, DOM, data record), with screenshots only as secondary evidence. A phase whose outcome depends on uncontrolled collisions or equilibrium gets an observation-only check from the start; never a gate weakened, loosened, or reclassified after a FAIL. A detector whose sampling cadence cannot separate the candidate causes is a harness limit by construction: classify it as such at the FIRST flag, record once, never re-analyze, and never re-run hoping the flag goes away.

## Expected values and gates

- Before you author any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle is detected). Derive every tolerance from the observed value's storage width: values stored through float32 (AudioParam values, typed arrays, analyser output) quantize, so fround the expectation and set eps above float32 resolution; a 1e-9 tolerance on a float32 path fails by construction. A check whose precondition is a world state (bodies resting, impacts available, audio unlocked) asserts that precondition first or runs after the phase that creates it; a check ordered before its precondition voids its phase in every run. Every timer and every trace arm goes BEFORE its trigger; a window that opens after the event reads nothing. Every expected value comes from printed source lines or a measured reference captured in the SAME run, never from assumption; compare like with like. Write every derivation into the table ONCE; a second in-head re-derivation means stop and write it down.
- Pixel-space expectations come from ONE in-page probe that prints each live pipeline link, measured against one captured frame; read every scale number from its printed output, never chain source constants into a hand prediction, and never redo the arithmetic across thinking blocks. A hand prediction that misses the first measurement by more than about 30% is wrong by construction: adopt the measured value, record the delta once, move on.
- Calibrate every classifier, threshold, and UI-exclusion rect from a PRINTED distribution of one captured frame in the smoke phase, BEFORE any gate runs; use the measured rects of the VISIBLE controls (a fixed full-viewport container's rect excludes the whole scene). Prefer relative thresholds over absolute values. Fix every gate value AND every classification convention in the calibration table BEFORE the first gated run; a convention invented or changed after a FAIL is a reclassification, not a fix. When two readings are defensible, print BOTH, declare the binding one, and report a marginal FAIL under it with the alternative on record - no rerun. Treat a detected bbox far smaller than the target's known size as a calibration bug: stop the run, never finish on a suspect detector. After two threshold nudges, instrument the underlying distribution once.
- The first gated run is ONE face or ONE instance in ONE phase, to confirm calibration, then the full multi-phase run. Every full run carries a settle wait of a minute or more; never spend one on uncalibrated gates. Settle is judged AT capture time with a bounded wait-verify-retry loop (2-3 attempts) written in from the start, not patched in after a flake.

## Probes and diagnosis

- Deliberation is not inspection. An open "how do I measure X" that survives one read gets a 10-line probe or ONE targeted grep, not an in-head trace of call paths. Three self-corrections in a row (wait / actually / BUT) mean STOP and print live values or data. A surprising number gets ONE raw print or one log grep, then it is recorded as an observation; never re-theorize it across thinking blocks. When offline overlap, concurrency, or interval math disagrees with in-page counts, suspect the DATA RECORDS first (missing fields, mixed clocks, absent end-of-life), not the app or the statistics: print two complete records end to end before theorizing. A number that resists three hypotheses gets one probe that prints every candidate cause in a single run. A self-check that disagrees with a hand expectation is as likely to have wrong expectations as wrong code: pin conventions from source first, test one trivially-computable case plus one strictly non-degenerate case, and on disagreement print intermediates once instead of re-deriving by hand.
- A TypeError or undefined-identifier whose stack points inside harness or driver code is a data-shape bug in your OWN glue: read the exact call site and the producer of its argument BEFORE any app-side theory; after the FIRST such error, check EVERY import of that file against the module exports and every cross-file argument shape in one pass, then re-run. A fresh node process owns no page: adopt `context.pages()[0]` or create one at start, in every entry point. Never rewrite a driver to escape an unexplained failure. If a reproduction probe does not reproduce, diff the probe's code path against the failing path line by line; two failed reproductions mean the difference is in your own code.

## Headless rendering, capture, and readback

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await, while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side. Use the fewest bodies that exercise the check (software rasterizer fps is far below display fps). Force viewports with `page.setViewportSize`, never raw CDP metric overrides. Canvas backing size settles asynchronously after a resize: wait a few hundred ms before reading it.
- Measure capture cost ONCE in the env phase (one timed screenshot) and budget every capture plan against the event duration BEFORE writing the driver. A full-viewport `page.screenshot` costs seconds per frame; the working method for transient frames is a sequential Node-side loop of small CLIPPED screenshots (no image tooling in the loop), frame period well under the event duration, armed BEFORE the trigger, scored offline afterwards, crops padded well beyond the detected bbox. Identical signatures across a burst mean the transient preceded the first frame: capture earlier next attempt or record a harness limit, never re-run hoping for new frames. Keep one measurement pass free of captures. NEVER bypass shared readback helpers with raw `(y*w+x)*4` indexing (it skips the Y-flip of bottom-up `readPixels`); `preserveDrawingBuffer` is false by default: read pixels inside the same rAF tick after the app's draw, one read per region (slice it in-page). After any driver rewrite, grep the driver for raw pixel indexing and for every helper the rewrite dropped. Symptom: after a rewrite, everything reports zero hits while the crop image looks correct - a coordinate or flip bug in your own glue.
- Setup-mechanism feasibility comes BEFORE any placement code: for each state a body must reach, print the numbers that decide reachability AND alignment, plus expected rest behavior; compare velocities at the contact point, never center of mass. Prefer a mechanism that cannot miss (drive the body to the target) over one that must converge. If a placement mechanism fails to converge TWICE, the mechanism is wrong: switch mechanisms, never write attempt #3, and never run a phase's substance checks against a setup that missed its target. Gate every pointerdown with an in-page `document.elementFromPoint` check.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, spies, readback helpers, guards, results writer, console whitelist in one place), with PORT/OUT/CWD read from env vars. Copy precedent drivers; edit only imports and paths; grep every absolute path and decide keep-versus-retarget per path in one pass (`sed` exits 0 on NO-match: after any sed edit `grep -c` the old and new strings). Never call a remembered helper name: grep the harness exports first, and cross-check every call site AND argument shape in the same writing pass. No stub or placeholder helpers in a driver write. Design the spy's DATA MODEL before its first write: enumerate every field any later phase will read, then instrument the app-managed resource's FULL lifecycle (create, start, AND stop/release/steal/reuse) in that same first write - app caps routinely stop and reuse resources, and a spy that misses end-of-life makes every downstream concurrency, interval, or duration number wrong, invalidates all prior data, and forces a redesign mid-investigation.
- Injected velocity-dependent gestures fail silently by default: Node-side mouse dispatch is slow, coalesces moves, and stamps the up event late, so release velocity reads near zero. Build them on in-page synthetic pointer dispatch as the FIRST mechanism, all moves and the up inside one evaluate with faked, evenly spaced timestamps; give the pointer path monotonic absolute screen coordinates inside the canvas. Decide feasibility from ONE read of the input code's hard requirements (trusted-event capture, velocity windows, sampling cadence); if synthetic dispatch cannot satisfy one, drop the gesture phase at design time. Gate stochastic impacts on the MEDIAN over attempts with a per-attempt staging gate that skips weak gestures. For non-velocity input, read timings from in-page event records, never Node-side send times. Poll transitions, not flags. Every comparison check carries a non-degeneracy guard (operand ~0, null, or empty where real signal is required means FAIL) and logs the operand. A retry loop over ONE mechanism is capped at two attempts before the mechanism is replaced.
- Phases are self-contained: each spawns or repositions its own target, asserts the target's identity BEFORE interacting, and establishes its own state (held pointers, focus, open/closed panels). Gate the FIRST click on any control with an in-page visibility check (`isVisible` / `elementFromPoint`): a control hidden by a collapsed panel means its toggle click is written into the phase setup from the start, not patched in after a click timeout that voids the run. Compute interaction feasibility from printed numbers; a candidate search logs its candidate count and widens or switches strategy on zero hits. A keyboard phase establishes its focus baseline (blur, assert `activeElement`) before its first Tab; every press helper releases the button on every exit path.
- Check-in ladder for EVERY harness, driver, or probe write: (1) match every import name against `rg -n "^export"` of its source; (2) `node --check ... && echo OK`; (3) after any edit, re-check syntax AND re-grep the edited block for sibling assertions the edit deleted; (4) BEFORE the first launch, re-read every helper and driver block you wrote once, end to end, with special attention to the data records' field completeness and the phase ordering; (5) a 2-5 s smoke launch grepping the console for ReferenceError and TypeError; (6) one whole-data-path smoke that ASSERTS the captured object is defined and has every expected field; (7) the one-instance calibrated run; (8) the full run. When an edit call fails to match, suspect your OWN arguments first (swapped oldText/newText, stale text from an earlier draft) before file-state theories: one re-read of the call plus one grep of the region settles it - do not spend multiple turns on atomicity or whitespace hypotheses. The driver takes a PHASE FILTER env var from the start and writes results INCREMENTALLY (flush one record per phase) to a file named with the run id AND phase filter; print a results file's first entry before parsing it.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root). Start the server BEFORE any HTTP check. Vite binds IPv6 loopback only, so use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL first. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). A baseline worktree OUTSIDE the repo tree cannot resolve vite (npx ENOENT): keep baselines inside the repo tree or symlink `node_modules`. No global `playwright`, and ESM import ignores NODE_PATH: import it by absolute path or via a `createRequire` pointing at the tree installing it; browsers live in `~/.cache/ms-playwright`. Launch Chromium with `--disable-dev-shm-usage` from the first run. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate it, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths (`cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`), a unique log per attempt, sleep then tail ONCE (an immediate tail races log creation). NEVER pipe a run's own output through tail or head: redirect full stdout to the log and grep the file afterwards; `grep -a` on large logs, and `echo "== section =="` markers. Wrap each phase in try/catch with periodic page recreation so one crash does not void the rest. Size each sleep to the driver's expected duration and poll at most twice per run; extract summary lines by grepping the log, never re-run a phase because output scrolled off. Multi-line Node belongs in a script file, not `node -e` (bash expands `$` inside double quotes before Node parses it); after one inline-eval failure, write a script file, never fight quoting. Kill by PID or port (`lsof -ti :PORT | xargs -r kill`), never a pkill pattern that can match your own command line; verify absence with `pgrep -af` or `lsof` on the port. After a final green run, one full-suite re-run for a single clean results file is the only re-run you may do; do not re-run to reconcile differing phase outcomes by analysis.
- Post-green discipline: a green run is done; do not re-litigate passing numbers (an odd passing number gets one raw-trace print, then it is an observation or dropped). Read the one or two evidence artifacts that carry the verdict, then write the report. Write the interim notes checkpoint IMMEDIATELY after the first full run completes, before any post-run analysis; at most ONE interim checkpoint exists, and the final notes rewrite is the record. The injected Notes context can display empty after a successful write: trust the tool result, verify with one query, never rewrite notes because of a display artifact. Wrap up in one pass: file confirmed product defects as cards (duplicate check first; the card tool requires a `summary` field; evidence, root cause with file:line, fix direction), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with reason), or a filed card. Kill every server you started, verify each port with `lsof`, persist notes once, and end the turn without `orchestrator_wait` (the checkpoint release arrives as injected context).
