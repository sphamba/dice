# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping and setup
- Read the task file first and fix the acceptance scope. Then run one batched inspection pass: entry-point reads, modules under test, `git log --oneline -10`, toolchain checks, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each `results.json`/log; names do not map to task numbers). Copy a prior driver and edit only imports and paths; never retype algorithms from memory.
- Pick the cheapest harness that reaches the code under test, and commit to it in one written line during this pass. For a pure module with no browser consumer, skip Playwright entirely and write a Node ESM driver that imports the module by absolute path from the worktree. Reserve browser harnesses for code that needs the rendered page. Do not re-derive or re-justify the harness choice in later turns.
- Before writing any script, grep the `export` lines of every module it imports and copy the exact names. To find app-wide constants (sizes, radii, scales), run one repo-wide search (`rg -n "CANDIDATE_A|CANDIDATE_B" src/`) and read the single defining module.
- Bound the output of every command: cap each search (`-l`, `-m 20`, `| head`) and never cat a large reference file inside a combined command (read it separately). An empty grep for importers is a finding, not a miss: it means the module has no consumer yet and settles the harness question. Widen a failed search once at most, never guess file after file.
- No global `playwright`; browser binaries live in `~/.cache/ms-playwright`. ESM `import` ignores `NODE_PATH`; import Playwright by absolute path (a usable package exists in other repos, e.g. `/home/phamba/repos/tarot/app/node_modules`) and verify with a real dynamic import.
- Serve with `python3 -m http.server <uncommon-port> -d <dir>` (or `npx vite` when bundler behavior matters). Check the port free (`lsof -i:<port>`), curl HTTP 200 for the page and each module URL, start detached (`setsid`), kill by port at the end (`lsof -t -i:<port> | xargs -r kill`) and verify. Never `pkill -f` a pattern that appears in your own command line. To serve a probe page next to the app, symlink it into the served directory; curl it once, a 404 fails silently. From the first probe run capture `pageerror`, all console messages, and failed requests.

## Harness and driver
- For browser work, build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page rAF frame grabber, WebGL readback, component finder, unit converters) plus Node-side helpers (serve, contexts, PNG dumps). Import it into the driver and every probe; never copy the INIT per script. Grab frames inside the rAF job that renders them; a readback outside that job returns a cleared or stale buffer.
- Convert coordinates with one converter set: backing px to css px (`canvas.width / canvas.getBoundingClientRect().width`, never assume it equals `devicePixelRatio`) then css px to world m. Validate the converters before any behavioral check: teleport one body to a known world point, click its computed screen position, and assert the pick succeeds. A missed click tells you nothing about picking.
- Run one smoke scenario end to end (including harness math) before the full matrix. Long suites go to background (`nohup node ... > log 2>&1 &`), tail the log in separate calls, and print each check as it completes. `page.evaluate` accepts serializable data only; make callbacks `async` when they `await`; share values via evaluate args or `globalThis`, never Node scope. Synthetic events need `defineProperty` instance props, a controlled `timeStamp`, and a `maxTouchPoints` override when code gates on it.
- Make each check robust to scene noise: per-body metrics over raw pixel diffs, speckle filtered by minimum pixel area. Write output to a log file, dump interesting frames as PNG (in-page `toDataURL`, crop with ImageMagick; PIL is not installed), and confirm the dump code ran before reading a PNG.

## Debugging discipline
- When one check fails while siblings pass, suspect the check first: re-read its guards, signs, and units before product hypotheses. After two failures in one run, stop and batch-audit every failure; classify each as driver bug, reference bug, or product bug; fix the shared root cause once and rerun.
- Collect runtime evidence before reading more product code: print the actual data (worst deviation, actual value sets, per-type outputs) instead of re-deriving or re-reading source. For a failed pick, hold, or roll check, instrument the live page (wrap `addEventListener`/`setPointerCapture`, log inputs and state) and read the values. In-head derivation loops are the most expensive failure mode in this role.
- Never hand-derive formulas, hashes, seeds, or float arithmetic in-head; copy the exact function into a scratch script, print intermediates, and compare against the expectation. Port expected formulas from the source under test, not from memory. When a mental estimate lands close to a limit, stop the arithmetic and print the real value in the driver instead.
- Numeric expectations (thresholds, tolerances) must come from measured data: print the values first, then set the bound. A measured value that saturates its window (a duration equal to the capture length, a value pinned at a limit) is a measurement artifact; audit the scan or meter code before hypothesizing physics.
- A flaky check that passes then fails needs a metric change, not a rerun; keep the old value as extra output. When a value is off by a scale factor, check unit conversions (css px, backing px, world m, DPR) first.
- Run `node --check` after every write. A grep with no match exits 1 and aborts an `&&` chain.

## Wrap-up
- Persist measured numbers once (task Notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with evidence, root cause with file and line references, fix direction, and acceptance criteria. Check for a duplicate card before creating one.
- State harness assumptions, driver bugs you fixed, and test limits in the Notes. Resolve the task card id from the worktree task-file symlink before kanban calls; a bare "TASK.md" returns not-found. Draft Notes in one clean pass and scan for duplicated lines before posting.
- Kill every server you started and verify each port with `lsof`. Finish with a results table that maps every check to a pass or a filed card.
