# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope, harness choice, and verification

- Read the task file first and fix the acceptance scope. Then run ONE batched inspection pass that resolves every open question at once: modules under test, exact `export` lines of every module the driver imports, app-wide constants (`rg -n "PATTERN" src/`, then read the defining module), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (list by mtime, read each results file; names do not map to task numbers). Include one printed live sample of every event/state object the driver will consume, and `ls`/glob exact artifact filenames before reading any of them. Copy a prior driver and edit only imports and paths; commit the harness choice in one written line and never re-justify or re-litigate it later.
- Match verification depth to the diff. Deletion-only or small-diff tasks need static proof only: full `git show`, diff touches only the named file, no orphaned imports (`rg -c` per imported identifier), `node --check` per touched file. Verify a merged commit in ONE batched command (`git rev-parse main HEAD; git log --oneline -5; git show --stat HEAD; git diff main...HEAD --stat`): empty diff output plus rev-parse equality means merged, stop there. Never reconcile a test count with naive greps: `it.each` and `describe` loops over data arrays multiply tests, so count structurally (`rg -n '^\s*(it|test)\('`) and settle the arithmetic in one pass. Do not launch the app unless acceptance demands a live run.
- Pick the cheapest harness that reaches the code under test. When any mechanic is uncertain, write a 10-line probe that prints the answer instead of deliberating in thinking. Never derive physics, geometry, projection, or engine math in-head: read constants from source, measure them in a probe, and lay viewport-to-world mappings out as one printed table. Before building any multi-step detector, run one control probe that proves the base trigger (roll, grab, dispatch, event) behaves as assumed in the current build; a failing control invalidates the detector, not the product. Read the exact source path that produces the signal you check (spin assignment, release velocity, damping) BEFORE writing the check.
- A route-rewrite or import-rewrite spy must match the SERVED module text, not repo source: curl the module URL from the dev server and build match and replace patterns from the response body (vite rewrites relative import specifiers to absolute paths).

## Build, serve, and processes

- Rebuild fresh from HEAD into a temp outDir before every live run and serve THAT build; never serve a pre-existing `dist/`, which can be stale relative to HEAD (tell-tale: a source-verified selector times out while the source clearly defines it). Recipe: `node node_modules/vite/bin/vite.js build --outDir /tmp/<run>/dist` (`npm run build` dies in worktrees: the copied `.bin/vite` shim mis-resolves); serve with `npx vite --port <uncommon-port>`. Vite binds the IPv6 loopback only: use `localhost`, never `127.0.0.1`. Check the port free, curl HTTP 200 for the page and every module URL before any browser step, start detached (`setsid`), kill by port at the end, verify with `lsof -ti :PORT`.
- No global `playwright` exists and ESM `import` ignores `NODE_PATH`. Locate it once (`find ~ -maxdepth 8 -type d -name "playwright*" -not -path "*ms-playwright*" 2>/dev/null`), record the absolute path, import from it. Binaries live in `~/.cache/ms-playwright`. Front-load ONE timed probe run that answers every environment unknown before any driver is written: write the unknown list first (launch, rAF fps, WebGL2, autoplay policy, initial and post-gesture AudioContext state, console message texts) and answer each exactly once, never re-measure.
- Put server boot INSIDE the shared page-launching helper (`newSeededPage` calls `startServer` first), so no probe or driver can forget it; a hand-rolled entry point will, and the failure only surfaces as `ERR_CONNECTION_REFUSED` after the browser launches. Never kill by a `pgrep`/`pkill -f`/`grep | xargs kill` pattern that can match your own command line (it SIGTERMs the invoking shell): kill by port (`lsof -ti :PORT | xargs -r kill`, `fuser -k PORT/tcp`) or a bracketed pattern applied to ps output.
- Put `echo "== section =="` markers between parts of a multi-part bash command so a truncated result stays interpretable; when one call's output truncates, rerun only the missing part with tighter commands, not the whole batch.

## Numeric instruments

- Calibrate a numeric instrument on a SYNTHETIC signal with known parameters (known decay rate, known frequencies, known sample rate) inside the same init script BEFORE pointing it at product data, and print measured versus expected. If an in-head-designed instrument fails against live data, that is an unvalidated instrument, not a product bug: stop, calibrate synthetically, then rerun. Every redesign-against-live-data cycle burns a full run.
- Read environment constants from the live context and thread them into the analysis: `ctx.sampleRate` (often 44100, never assume 48000), the real buffer `length` for FFT bin math, channel count. Set numeric tolerances at float32 scale (about 1e-5 relative, not 1e-9). Assert transitions by final state, not by transition logs (a headless AudioContext can already be `running`). For one component's decay, band-pass at its known frequency and stop the fit at the first cliff to the numerical floor; prefer robust orderings (A decays slower than B) over fragile absolute windows, and set ranges from measured medians only after the instrument works.

## Instrumentation and transient sampling

- Headless SwiftShader renders a WebGL canvas below display fps, so physics runs in slow motion and `page.click` actionability stalls: prefer raw `page.mouse` or CDP coordinate dispatch, cap settle waits, use the fewest bodies that exercise the check, and on settle timeout fall back to state or geometry assertions or reroll with fewer bodies. Capture transients where the frames happen (in-page rAF, per-frame maxima); Node-side polling misses apexes. Arm every sampler BEFORE the trigger. Measure flight/settle duration with one probe BEFORE designing any transient check: CDP screenshot latency cannot sample sub-100 ms flights, and rapid CDP `mouse.move` calls coalesce into one sample (velocity reads zero, so flings read as motionless) — space move samples 40 ms or more apart, and when mid-flight sampling stays unreliable, compare pre/post rest states instead. A check that depends on a random draw (random spin axis or magnitude) needs a retry loop with per-attempt pass flags.
- Set check thresholds from what the instrument can observe, and state the derivation in one line. When a marginal check fails, fix the instrument once and rerun; never nudge the same threshold twice.
- When checks fail, suspect the instrumentation first (guards, timing, units, scope, install order, event-to-buffer pairing): print actual live values at the decision point, then classify each failure as harness bug, harness limit, or product defect BEFORE editing thresholds or product code. Once two or more checks fail, stop the run, batch-audit every failure in one pass (driver, harness, or product bug), fix the shared root cause once, and rerun only the invalidated checks.
- Keep the console whitelist in ONE place in the shared harness, imported by every driver and probe. Build patterns from the exact captured message text of the first audit run (copy-paste the payload; headless wording is literal: SwiftShader emits "CONTEXT_LOST_WEBGL", vite dev chatter starts with "[vite]"). Never hand-write the regex from memory.

## State, input, and pixels

- Track toggle state in one driver variable that every action updates, and gate each phase on asserted preconditions instead of assuming them. A click leaves focus on the clicked control: blur before every keyboard-on-body check. Synthetic CDP key events never auto-repeat; a held key is one keydown. Copy every expectation (counts, labels, tab order; disabled controls are not tabbable) from source or the live DOM, never derive it in-head.
- Route every dispatched coordinate through one harness normalizer (backing px to css px, clamp to canvas bounds, assert finite) and log every clamp: a clamped fling or edge drag has zero velocity, so keep drag and fling targets well inside bounds. Pin pointer and touch dispatch semantics in the probe once (CDP touch: one reused session per page, touchStart/touchMove/touchEnd/touchCancel point rules, sequential pointerIds). Wrap ImageMagick `compare -metric AE`: it exits 1 when images differ (0 identical, 2 on error) and prints the metric to stderr, so tolerate exit 1 and parse the first stderr token; localize a diff with per-region AE on crops of the moving region, and keep the pointer at one neutral position in baseline and post shots.

## Driver authoring and runs

- Build one shared `/tmp` harness at the start: the INIT script for `addScriptToEvaluateOnNewDocument` (in-page spies, event loggers, `__drain`) plus Node-side helpers (serve, dispatch, capture, results file, console whitelist). Import it into every driver and probe, and diff a copied driver's setup sequence against the working probe. `node --check` passes code with undefined identifiers and wrong property names, so also: print one whole sample (`JSON.stringify`) of every captured event and every helper return BEFORE consuming fields — reading a stored `{id}` as `.pointerId` yields `undefined` and silent defaults; after any helper rename, signature change, or block deletion, audit every call site and every now-undefined identifier in the SAME edit batch, then `node --check`. Every probe and driver must contain at least one explicit PASS/FAIL check: a "0/0 checks passed" run validated nothing. Parameterize drivers with env vars from v1 so a single scenario can be rerun. `page.evaluate` needs IIFEs and passes at most one serializable argument; read in-page values with `page.evaluate` before using them in Node; in ESM use dynamic `import()` for node builtins.
- Long suites go background as one standalone command: `setsid nohup node driver.mjs > log 2>&1 &`. An `&&` chain ending in `&` backgrounds the whole list. An immediate tail races log-file creation: sleep, `ls` the log, then tail in a follow-up call. Tail the log once about 30 s after launch to catch instant crashes before committing to a long sleep. Never pipe a driver into `head`. After a multi-edit batch to a driver, re-read the edited region before launching the next run.

## Debugging and wrap-up

- Wrap up in one Notes pass: file confirmed product defects and open questions as cards (evidence, root cause with file and line references, fix direction, acceptance criteria, duplicate check first), resolving the card id from the worktree task-file symlink. Kill every server you started and verify each port with `lsof`, persist measured numbers once, and finish with a results table mapping every check to a pass, a harness limit, or a filed card. If bash suddenly fails with "Working directory does not exist", the worktree was externally deleted: recreate the path, `git worktree add` from the task's pinned commit, restore the kanban and task-file symlinks, restart the server, and move on. Do not call `orchestrator_wait`: only the project manager session waits for board reports.
