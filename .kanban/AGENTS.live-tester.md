# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping
- Read the task file first and fix the acceptance scope. Then make one inspection pass that batches: entry-point grep, reads of the modules under test, `git log --oneline -10`, toolchain checks (Playwright ESM import, free port), and the harvest below. Write the smallest harness (one scene, one readback) immediately after, then extend scenarios only once it renders. Probe output settles design questions faster than deliberation.
- Harvest prior run material inside that first pass: check `/tmp/<repo>-lt*/` directories for `reference.mjs`, `live.test.mjs`, and `expected.json`, and read kanban done-task notes for scene setups. Scene and scenario names are task vocabulary, not source identifiers; grepping `src/` for them returns nothing.
- If a prior reference or driver exists, copy the file and edit only imports and paths; never retype algorithms from memory. Trace the feature's runtime data flow before designing the harness; if a producer of a needed state is not merged yet, inject the state directly and record it in Notes as a test limit. Trust the repo state over the task prose.

## Reference math
- Port expected-value formulas verbatim from the source under test (GLSL shaders, physics code) into the reference script. Never re-derive lighting, geometry, or sign conventions in-head: one dropped shader term or flipped offset invalidates every predicted color and forces a full redo.
- Compute every expected value with an independent Node reference script that writes one expected JSON the driver reads, modeling the pipeline in the code's order. The same script must SEARCH for probe points (candidate rings or grids over each face and the floor, filtered by visibility, clearance, and lit plus shadowed feasibility) and assert at least one sample of each class exists. Never hand-pick fixed sample points.
- Let the reference script also compute scene layout and object placement with an automated feasibility search (non-overlap, in-bounds). Do not derive spacing, projected sizes, or safe offsets in-head.
- Write the expected JSON before any asserts (or in a `finally` block) so a failed assert still leaves the artifact for debug scripts. Build in a `--trace` mode that prints per-candidate verdicts instead of editing ad-hoc `console.log` lines into the script.

## Environment
- No global `playwright` package; browser binaries live in `~/.cache/ms-playwright`. A usable package exists in other repos (e.g. `/home/phamba/repos/tarot/app/node_modules`). ESM `import` ignores `NODE_PATH`; import Playwright by absolute path on first use and verify with a real ESM dynamic import (`node -e "import('<abs path>').then(()=>console.log('ok'))"`); a require- or NODE_PATH-based check can pass while the ESM import fails.
- Serve with `python3 -m http.server <uncommon-port> -d <repo-dir>` for plain ES modules, or `npx vite --port <port>` when bundler behavior is needed. Check the port is free (`lsof -i:<port>`) and curl-check HTTP 200 for the page and module URLs. Start servers detached (`setsid`); keep a list of every server you start and kill each by port at the end (`lsof -t -i:<port> | xargs -r kill`); never `pkill -f` a pattern that appears in your own command line; do not touch ports you did not start.
- Headless Chromium (SwiftShader): keep `readPixels` readbacks few, rerun once on CONTEXT_LOST, and use pixel values as evidence (screenshots can come back blank; dump frames in-page with `canvas.toDataURL('image/png')`, then crop and inspect with ImageMagick `convert`; PIL is not installed). Synthetic events need instance properties set via `defineProperty`, a controlled `timeStamp`, and a `navigator.maxTouchPoints` override when code gates on it. Hardware-only paths go in Notes as limits, never as pass/fail checks.

## Scripts and shell
- Grep the `export` lines of every module a script imports and copy the exact names before writing it. Offset-read the region under test in large modules instead of a full read (a truncated read leaves blind spots that surface as mid-run hedging). Grep for helper files before referencing their paths.
- `node --check` immediately after every write, and re-check scratch and diagnostic scripts before each browser run. Never write an unfinished or speculative file; rewrite the whole file instead of chaining edits when the structure changes.
- Shell trap: a `grep` with no match exits 1 and aborts an `&&` chain, so later commands never run. Run greps as separate commands or append `|| true` when a chain must continue.

## In-page code and drivers
- `page.evaluate` accepts serializable data only. Make callbacks `async` when they `await`; share values through `globalThis` or evaluate arguments; never close over Node scope. Declare each variable in the function that uses it.
- A module the app does not import yet is still testable: serve the repo and `await import('/src/<path>.js')` in the page; capture console and page errors in the driver. Run hygiene: smoke-test the driver end to end before the first full run; write output to a log file and tail it (never pipe a long run through `| tail`); print each check as it completes; set a page default timeout (15-20 s); batch all contexts into one script. Update the todo list only at phase transitions, 3-5 items total.

## Scenario design
- Define each scenario once as data (initial state, per-step resets, measurement flags, tolerances) consumed by both reference and driver. Adopt tolerance, sampling, and layout choices from prior artifacts wholesale instead of re-deciding settled questions. Reset every state field between measured steps, assert at the exact step boundary the scenario defines, and keep expected values strictly inside pass regions. Name probe IDs so none is a prefix of another (`d20-top`, never a token prefix).
- Assert colors by majority vote over a small patch, never a single pixel: antialiasing and label ink make single-pixel probes flaky. Keep test objects inside bounded geometry at all times; an object outside the region turns a harness mistake into a false product failure.

## Failure diagnosis
- When one check fails while sibling checks pass, suspect the check first: re-read its guard conditions and scenario before forming product hypotheses; most single-check failures are harness bugs. After more than two failed checks in one run, stop and batch-audit every failure, classifying each as driver bug, reference bug, or product bug. Time-box anomalies: a failure that does not block acceptance gets at most two probes, then file a card, annotate the check, and move on.
- When behavior resists two hypotheses, or a value is off by orders of magnitude, stop deriving in-head: write a trace or bisect script that calls the stage functions directly and prints intermediates. For rendering defects (missing geometry, culling, blank regions), escalate fast to a minimal raw-WebGL repro with no app code; it settles winding, culling, and attribute questions that shader-level reasoning cannot.

## Wrap-up
- Persist measured numbers once (notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with live-test evidence, root cause with file and line references, fix direction, and acceptance criteria. State harness assumptions and test limits in the task notes.
- Draft task Notes in one clean pass and scan for duplicated lines before posting. End of run: stop every server you started and verify with `lsof`; finish with a results table that maps every pass and fail to a check or a filed card.
