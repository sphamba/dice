# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and inspection

- Read the task file first and fix the acceptance scope and task id from it. Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors, serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time; one multi-file dump truncates). All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; drop precedent checks that do not map to acceptance; never revisit that list later.
- Live-testing can run after the merger: `git diff main...HEAD` may be empty because the fix is already merged. Locate the task's commits (`git log --grep "<task-id>"` on main or the branch), review those diffs, and confirm the served app actually contains the fix before probing behaviour. Match verification depth to the diff: small or deletion-only diffs need static proof only (batched `git show` / `git diff --stat`, no orphaned imports, structural test counts). Do not launch the app unless acceptance demands a live run.

## Probes and deliberation

- Front-load ONE timed environment probe that answers every environment unknown once: fps, WebGL2, reported viewport, canvas backing size versus `clientWidth * devicePixelRatio`, helper return shapes, event injection, console texts, and the latency of one synthetic input dispatch (print the in-page timestamps of a CDP down-move-up). Print one whole `JSON.stringify` sample of every captured event and helper return BEFORE consuming fields. Build it only from primitives verified standalone FIRST: a risky primitive (CDP overrides, viewport forcing, pointer or event injection) gets a 10-line probe before it enters the shared harness. `node --check` passes code with undefined identifiers and wrong property names.
- Never derive physics, geometry, projection, or engine math in-head. Before authoring any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle or motion is detected). Every threshold must trace to a measured reference captured in the SAME run as the assertion, never to a later rerun; every settle or flight timer arms BEFORE its trigger. Tag every harness quantity with its unit in the name (mm, cssPx, backPx), print one known length through the same scale chain before any measurement code runs, and calibrate motion helpers and numeric instruments once on a known signal.
- Deliberation is not inspection. An open "how do I measure or access X", or "does X throw or degrade", that survives one read is answered by a 10-line probe or ONE targeted grep, not by tracing call paths in-head. Three self-corrections in a row (wait / actually / BUT / a re-derivation) mean STOP and print live values or pixel data. One hypothesis cycle per anomaly, then measure. When a hand-copied replica contradicts observed app behaviour, stop reconciling theory: run the replica on a case with a known answer and verify the replica itself first.
- On a FAIL, the FIRST action is a raw-sample probe at the decision point, read from the run log: build the dump INTO the first driver (on any failed check, print raw samples, event logs with in-page timestamps, and reference readings at the decision point), so failures are diagnosed without writing a new driver. Classify each failure as harness bug, harness limit, or product defect from captured record fields BEFORE listing hypotheses or touching thresholds. Two or more failures with one signature share one root cause: fix the shared cause or label the limit, and rerun only the invalidated checks. After two nudges of the same threshold, stop nudging: instrument the underlying distribution (dt, latency, amplitude) once and pick the value from it.

## Headless rendering and emulation

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await (even plain counters), while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side, arm traces before triggers, and measure fps once in the environment probe. SwiftShader runs far below display fps, so use the fewest bodies that exercise the check.
- Never read pixels with `drawImage` + `getImageData` on the WebGL canvas: it returns the LAST COMPOSITED bitmap, stale by many frames under SwiftShader, and produces phantom anomalies. Read with `gl.readPixels` inside the same rAF tick after the app's draw: one `readPixels` per region (slice it in-page; many tiny reads per frame are slow), Y-flipped (GL origin is bottom-left) and edge-clamped. `preserveDrawingBuffer` is false by default: readPixels outside the render rAF returns black. Cache `WEBGL_lose_context` with `getExtension` BEFORE calling `loseContext`; the handle is null after loss. Assert fractions over spans or windows, never single pixels or midpoints (one pixel can be a pip, an AA edge, or a hollow-centre fragment), and window each body separately: one scanline or column can cross several bodies.
- Playwright's own viewport emulation overrides raw CDP `setDeviceMetricsOverride`: CDP metric changes do not stick and fire no resize event. Force viewports with `page.setViewportSize` (it fires a real resize but protocol-errors on a maximized window, so pin `viewport` at context creation or CDP-restore the window state first) or with a 0x0 context viewport for degenerate loads. Pin `viewport` at context creation anyway: device descriptors ship a viewport SMALLER than the screen, and dpr is capped in headless (verify the cap once). After any resize, canvas backing size and resize-derived state settle asynchronously: wait a few hundred ms before reading them.

## Visual evidence

- A visual anomaly is a data question, not a theory question. FIRST action: a measuring script (pixel spans, centroids, luminance grids). SECOND action: a pixel diff against a verified baseline (`magick compare -metric AE` exits 1 when images differ; parse the first stderr token and tolerate exit 1). Verify the baseline commit predates the feature BEFORE investing in it; a head-versus-base difference where BOTH sides look wrong is pre-change or environment evidence, not a defect. Fixed-distance patches around a body are contaminated by its tilted silhouette: compute the max reach from source constants (half-diagonal, corner radius, orientation) and place patches beyond it. A "no effect" reading from a contaminated or occluded patch is void, not a defect.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, world spies, readback helpers, guards, results writer, console whitelist in one place). Copy precedent drivers; edit only imports and paths. Never write a probe against remembered or imagined helper names: grep the harness exports first and cross-check every call site in the same writing pass. Pass REAL functions to `page.evaluate`, never function-source strings: Playwright serializes and CALLS a function, but evaluates a string as an expression, so a string returns the function itself and downstream reads go `undefined`. Do not share mutable scratch buffers between steps of copied code: a clobbered scratch makes a copied test silently always-true or always-false and voids its verdicts.
- Injected input is slow and lossy: one CDP dispatch can take tens of ms, moves coalesce, and Playwright's `mouse.up()` reuses the last move's coordinates. Give every move its own explicit position and space moves 40 ms or more apart. When an app derives velocity from event timestamps inside a window comparable to dispatch latency, dispatch the final move and the up back-to-back via raw CDP with explicit coordinates, and read timings from in-page event records, never from Node-side send times.
- Every check that compares a measurement against a replica or expected value needs a non-degeneracy guard: if the operand is ~0, null, or empty where a real signal is required, the check is vacuous and must FAIL and retry, not PASS. A vacuous pass hides a broken stimulus for many runs; log the operand value in every check line.
- Compute geometric feasibility, never assume it: before any drag-to-target or sampling check, print target versus body half-width, wall clearance, panel rect, and max silhouette reach; clamp targets into reachable bounds; guard every drag with respawn-until-grabbable. Gate every pointerdown with an in-page `document.elementFromPoint` check that the press lands on the canvas, not an overlay: a grab error that holds steady near half the body size means the pick missed or the press hit another element. Prefer grab points well inside a face; near-edge points miss on small pose differences.
- Poll settled STATE, not transient predicates: assert a position-error window over consecutive samples, or motion below a threshold over a span. Awake/sleep flags and single-frame velocities flip within a second, so wait-for-flag waits race. Confirm stillness across consecutive samples before any pixel assertion.
- Check-in ladder for EVERY harness, driver, or probe write: `node --check` in the next command, then a 2-5 s smoke launch with the clock and spy wrappers installed (grep the console for ReferenceError and TypeError), then one whole-data-path smoke on a single capture that ASSERTS the captured object is defined and has the expected fields, then the full run. Choose the smoke strategy in one line and run it; do not re-deliberate launch-versus-kill. A wrapper bug found at the end of a long run voids the run; a smoke run costs seconds. Setup parity: every precondition the driver needs (a panel open, for example) is established by the driver itself, every click is gated on visible and enabled, and one results-writer code path serves all modes.
- File edits are atomic: a failed multi-edit applies nothing. After any failed or doubtful edit, re-read the file before editing again. When a harness file is short and its state is unclear after an edit failure, rewrite it in full instead of stacking partial edits.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root). Start the server BEFORE any HTTP check; combine reuse-check and start in one command. Vite binds the IPv6 loopback only: use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL before any browser step, and build route-rewrite spies from the SERVED response body, not repo source. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). No global `playwright` exists and ESM import ignores NODE_PATH: locate it once and import by absolute path; binaries live in `~/.cache/ms-playwright`. Launch Chromium with `--disable-dev-shm-usage` from the first run: heavy SwiftShader scenes crash the renderer on /dev/shm pressure, and a mid-run crash voids every later phase. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate the path, `git worktree add` from the pinned commit, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths: `cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`. Unique log per attempt. Sleep, then tail once (an immediate tail races log creation; never pipe into `head`); grep large logs with `grep -a`; mark batched bash sections with `echo "== section =="`. Give the driver a PHASE FILTER env var from the start so a debugging rerun executes only the failing phase, and wrap each phase in try/catch with periodic page recreation so one crash or phase error does not void the rest of the run. Kill by PID or by port (`lsof -ti :PORT | xargs -r kill`), never by a pkill pattern that can match your own command line; before killing PIDs found by a broad search, read `ps -o pid,args -p <pids>` and kill only PIDs whose args point at your own harness directory or port: other runs share the machine.
- A check that depends on a random draw (spawn position, shuffle, impact strength) uses retry loops with per-attempt pass flags, logged draw inputs, and end-state assertions over displacement thresholds. Post-green discipline: a green run is done; do not re-litigate passing numbers with speculation; an odd passing number gets one raw-trace print, then it is recorded as an observation or dropped. Wrap up in one pass: file confirmed product defects as cards (evidence, root cause with file and line references, fix direction, duplicate check first), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with its reason), or a filed card. At most one interim notes checkpoint mid-run; the final notes rewrite is the record. Kill every server you started and verify each port with `lsof`. Persist notes once and end the turn without `orchestrator_wait`; the checkpoint release arrives as injected context.
