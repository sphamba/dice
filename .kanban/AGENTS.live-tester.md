# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scope and planning

- Read the task file first. Fix the acceptance scope and the task id from it (if the task file has no id, take it from one kanban query at the start and never re-derive it mid-run). Run ONE batched inspection pass that resolves every open question at once: modules under test, exact export lines of every imported module, app-wide constants (`rg -n "PATTERN" src/`), UI selectors AND default UI state (open/closed panels, initial values; grep the markup and CSS, never infer from class names), serve command, and a harvest of `/tmp/<repo>-lt*/` artifacts (ls the filenames first, then read precedent files one at a time). Keep every enumeration output short (`ls ... | head -50`, targeted greps): a flood of filenames forces a second run of the same command. All source reading belongs to this pass. Commit the harness choice AND the check list in one written line; drop precedent checks that do not map to acceptance; never revisit or re-enumerate that list in later turns. Match verification depth to the diff: a small or deletion-only diff needs static proof only, and no live run unless acceptance demands one. Live-testing can run after the merger (`git log --grep "<task-id>"` locates the commits).
- Map every phase to an acceptance criterion or a PM-named check before you write it. Cut a phase on its second non-converging design iteration; use the minimal phase that exercises the same constant. Before you author any check, print ONE constants table from source (file:line, value, unit, consumer) and ONE observation plan (which clock, what arms the trace, how settle or motion is detected). Write every geometry derivation into that table ONCE. A second in-head re-derivation of the same quantity means stop and write it down. Every expected value that an app asserts about itself comes from printed source lines, never from assumption. Tag harness quantities with units and compare like with like (a per-axis offset is not a radius). Every threshold traces to a measured reference captured in the SAME run. Every settle or flight timer arms BEFORE its trigger. A copied check must stress the constant it tests, else it passes on pre-fix code and proves nothing. Choose the gate type from the change shape: an instantaneous state change (delete, toggle, class flip) has no pixel motion, so gate on the resulting state (count, attribute, DOM) and use a full-region screenshot diff only as secondary evidence.
- Setup-mechanism feasibility comes BEFORE any placement code. For each state a body must reach (drop, fling, settle against a surface, grab point), print the numbers that decide reachability (target versus body half-extent, expected rest offset, bounce behavior, max silhouette reach of the grab candidates). Prefer a mechanism that cannot miss (drive the held body to the target) over one that must converge. If a placement mechanism fails to converge TWICE, the mechanism is wrong: switch mechanisms, never write attempt #3, and never run a phase's substance checks against a setup that missed its target.

## Probes and diagnosis

- Front-load ONE timed environment probe that answers every environment unknown once: fps, WebGL2, reported viewport, canvas backing size versus the source-derived expectation, helper return shapes, event injection, console texts, and the latency of one synthetic input dispatch. Print one whole `JSON.stringify` sample of every captured event and helper return BEFORE you consume fields. Verify a risky primitive standalone with a 10-line probe BEFORE it enters the shared harness. Keep probe output compact and greppable (one JSON line per probe, `echo "== env =="` markers): lines that scroll away force re-verification later. `node --check` passes code with undefined identifiers and wrong property shapes. The first smoke phase is the real identifier cross-check: make it phase-filterable from the start and run it before any other phase.
- Deliberation is not inspection. An open "how do I measure X" or "does X throw" that survives one read gets a 10-line probe or ONE targeted grep, not an in-head trace of call paths. Three self-corrections in a row (wait / actually / BUT / a re-derivation) mean STOP and print live values or pixel data. One hypothesis cycle per anomaly, then measure. A surprising number gets ONE raw print or one log grep, then it is recorded as an observation; never re-theorize it across thinking blocks. Write sign and axis conventions once from printed source lines; a second in-head re-derivation of the same sign means print a truth table with real coordinates or demote the check to observation-only.
- A TypeError or undefined-identifier error whose stack points inside harness or driver code is a data-shape bug in your OWN glue: read the exact call site and the producer of its argument (grep where the variable is assigned) BEFORE any probe or app-side theory. After the FIRST such error, check EVERY import of that file against the harness exports and every cross-file argument shape in one pass, then re-run. Fix only the crasher and the same class strikes again in another phase. Never rewrite a driver to escape an unexplained failure. If a reproduction probe does not reproduce, STOP probing and diff the probe's code path against the failing path line by line. Two failed reproductions mean the difference is in your own code, not the app.
- A render anomaly that shows STRUCTURE (the same defect at matching positions across cells, faces, or instances) is a data-pipeline bug, not a sampling artifact. Name the pattern, then stop probing pixels: extract the suspect pure function (bake, SDF, distance transform, atlas build) into a standalone Node script with a synthetic input and run it. Scan intermediate arrays for non-finite values FIRST. The browser probe confirms the pattern; the Node repro names the root cause.

## Headless rendering and emulation

- Headless Chromium renders WebGL on demand: rAF chains registered in-page stall during any in-page await, while the app's own loop keeps drawing. Never await in-page while sampling; wait Node-side, arm traces before triggers, and measure fps once in the environment probe. SwiftShader fps is far below display fps: use the fewest bodies that exercise the check. Capture the frame you analyse AFTER the trigger and its settle: a pre-spawn or cached frame reads stale pixels. Read pixels with `gl.readPixels` inside the same rAF tick after the app's draw: one read per region (slice it in-page), Y-flipped, edge-clamped. `preserveDrawingBuffer` is false by default: a read outside the render rAF, or via drawImage/getImageData, returns stale or black. Cache `WEBGL_lose_context` with `getExtension` BEFORE you call `loseContext`. Assert fractions over spans or windows, never single pixels, and window each body separately. Force viewports with `page.setViewportSize`, never raw CDP metric overrides; pin `viewport` at context creation. Canvas backing size and resize-derived state settle asynchronously after any resize: wait a few hundred ms before you read them.

## Visual evidence

- A visual anomaly is a data question, not a theory question. FIRST action: a measuring script (pixel spans, centroids, luminance grids). SECOND action: a pixel diff against a verified baseline (`magick compare -metric AE`; exit 1 means the images differ, so parse the first stderr token). Verify the baseline commit predates the feature BEFORE you invest in it; a head-versus-base difference where BOTH sides look wrong is pre-change or environment evidence, not a defect. Place probe patches relative to the rendered bbox EDGE outward, clamp every patch coordinate inside the frame; a "no effect" reading from a contaminated, occluded, or off-canvas patch is void. A change-detection clip must cover every position the change can reach; when in doubt, diff the full viewport, not a center crop.
- Pixel hue and ink classifiers are structurally fragile. Calibrate every classifier on a PRINTED distribution of the real pixels BEFORE any gate exists. After two threshold nudges, stop nudging: instrument the underlying distribution once, or replace the instrument.

## Harness and drivers

- Build ONE shared `/tmp` harness at the start (serve, page creation, world spies, readback helpers, guards, results writer, console whitelist in one place), with PORT/OUT/CWD read from env vars so copies can retarget. Copy precedent drivers; edit only imports and paths. When you copy, first grep the precedent for every absolute path and decide keep-versus-retarget per path in one pass; `sed` exits 0 on NO-match, so after any sed edit `grep -c` the old and new strings to verify the substitution count. A path that resolves node modules must keep pointing at the tree whose node_modules installs them. Never call a remembered helper name: grep the harness exports first, and cross-check every call site AND every argument shape in the same writing pass. Pass REAL functions to `page.evaluate` (Playwright calls a function but evaluates a string as an expression). No shared mutable scratch buffers between copied steps, and no stub or placeholder helpers in a driver write; stubs leak into runs and cost a cleanup pass.
- Injected input is slow and lossy: one dispatch can take tens of ms, moves coalesce, and `mouse.up()` reuses the last move's coordinates. Give every move its own explicit position, space moves 40 ms or more apart, and read timings from in-page event records, never Node-side send times. A KEYBOARD phase establishes its own focus baseline first (blur, then assert `activeElement` is body) before its first Tab or Enter; a preceding pointer interaction leaves focus elsewhere, and Tab then leaves the document. Every press helper releases the button on EVERY exit path; a missed pointerdown that leaves the button held corrupts every later phase. Poll transitions, not flags: first wait for the state to move the RIGHT way, then wait for the settle flag. Every comparison check carries a non-degeneracy guard (operand ~0, null, or empty where a real signal is required means FAIL) and logs the operand. A retry loop over ONE mechanism is capped at two attempts before the mechanism itself is replaced.
- Phases are self-contained: each spawns or repositions its own target, asserts the target's identity BEFORE grabbing, and establishes its own state (held pointers, focus, open/closed panels). Leftovers from an earlier phase leak and invalidate later checks. Gate every pointerdown with an in-page `document.elementFromPoint` check. Compute grab feasibility, never assume it: print target versus body half-extent, wall clearance, panel rect, and max silhouette reach; clamp targets into reachable bounds. A candidate search logs its candidate count and widens or switches strategy on zero hits instead of failing the check.
- Ground every pass/fail gate in source constants or measured references BEFORE the first run, and scope it to ITS phase's constraint: a tolerance copied from another phase's physics is invalid where a different constraint sets the pose. A phase whose outcome depends on uncontrolled collisions or equilibrium gets an observation-only check from the start; never a gate weakened, loosened, or reclassified after a FAIL. A detector whose sampling cadence cannot separate the candidate causes is a harness limit by construction: classify it as such at the FIRST flag, record once, never re-analyze, and never re-run hoping the flag goes away.
- Check-in ladder for EVERY harness, driver, or probe write: `node --check` in the next command; after any edit, re-check syntax AND re-grep the edited block for sibling assertions the edit can have silently deleted; then a 2-5 s smoke launch with clock and spy wrappers installed (grep the console for ReferenceError and TypeError); then one whole-data-path smoke on a single capture that ASSERTS the captured object is defined and has the expected fields; then the full run. The driver takes a PHASE FILTER env var from the start, self-establishes every precondition, serves all modes from one results-writer path, and writes results to a file whose name includes the run id AND the phase filter, so a filtered re-run never overwrites the full-run record. Before you parse a results file, print its first entry to pin the schema. A failed multi-edit batch is atomic: one unmatched oldText rolls back the whole call. Re-read the exact region and reapply; never assume partial application.

## Runs and wrap-up

- Serve with `cd <worktree> && setsid npx vite --port <uncommon-port> &` (the cd must be in the same command, else vite serves the wrong root). Start the server BEFORE any HTTP check. Vite binds IPv6 loopback only, so use `localhost`, never `127.0.0.1`. Curl HTTP 200 for the page and every module URL first, and build route-rewrite spies from the SERVED response body. `npm run build` dies in worktrees (the copied `.bin/vite` shim mis-resolves). A baseline worktree OUTSIDE the repo tree cannot resolve vite (npx ENOENT): keep baselines inside the repo tree or symlink `node_modules`. No global `playwright`, and ESM import ignores NODE_PATH: import it by absolute path, or via a `createRequire` that points at the tree installing it; browsers live in `~/.cache/ms-playwright`. Launch Chromium with `--disable-dev-shm-usage` from the first run: a mid-run renderer crash voids every later phase. If bash fails with "Working directory does not exist", the worktree was deleted externally: recreate it, restore the kanban and task-file symlinks, restart the server.
- Long suites go background with ABSOLUTE paths (`cd X && setsid nohup node driver.mjs > /abs/log 2>&1 & echo $!`), a unique log per attempt, sleep then tail ONCE (an immediate tail races log creation; never pipe into `head`), `grep -a` on large logs, and `echo "== section =="` markers. Wrap each phase in try/catch with periodic page recreation so one crash does not void the rest of the run. After a run, extract env and summary lines by grepping the log; never re-run a phase because its output scrolled off. Kill by PID or by port (`lsof -ti :PORT | xargs -r kill`), never a pkill pattern that can match your own command line. After a final green run, one full-suite re-run to produce a single clean results file is the only re-run you may do; do not re-run to reconcile differing phase outcomes by analysis.
- Post-green discipline: a green run is done; do not re-litigate passing numbers with speculation (an odd passing number gets one raw-trace print, then it is recorded as an observation or dropped). Read the one or two evidence screenshots that carry the verdict, then write the report; do not debate whether evidence reading is in scope. Wrap up in one pass: file confirmed product defects as cards (duplicate check first; the card tool requires a `summary` field; give evidence, root cause with file and line references, and a fix direction), give each run's results a unique id, and finish with a results table mapping every check to a PASS, a harness limit (with its reason), or a filed card. At most one interim notes checkpoint mid-run; the final notes rewrite is the record. Kill every server you started, verify each port with `lsof`, persist notes once, and end the turn without `orchestrator_wait` (the checkpoint release arrives as injected context).
