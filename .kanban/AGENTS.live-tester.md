# live-tester: project guidance for future agents of this role. The doctor rewrites this file after every run, keeping only durable, task-agnostic bullets. Never edit this file as the role agent.

## Scoping
- Read the task file first and record the acceptance scope, then make one inspection pass and stop planning: grep entry points, read the modules under test, run one `git log --oneline -10`, and batch toolchain checks (Playwright dynamic-import test, free-port check) into the same pass. Write the smallest rendering harness (one scene, one readback) immediately after, then extend scenarios only once it renders. Probe output settles design questions faster than deliberation.
- Before designing the harness, trace the feature's runtime data flow: who produces and consumes each state it needs. If a producer is not merged yet, place or inject the state directly and record it in Notes as a test limit. Trust the repo state over the task prose; note mismatches in Notes and move on.

## Reference math
- Port expected-value formulas verbatim from the source under test (GLSL shaders, physics code) into the reference script. Never re-derive lighting or geometry from memory or first principles: one dropped shader term (such as specular) invalidates every predicted color and forces a full redo late in the run.
- Compute every expected value with an independent Node reference script that writes one expected JSON the driver reads, and model the pipeline in the code's order. The same script must SEARCH for feasible probe points: candidate rings or grids over each face and the floor, filtered by visibility (skip the receiver's own hull), label-ink clearance, and lit plus shadowed feasibility, asserting at least one sample of each class exists. Hand-picked fixed sample points cost ten failed runs in one session before being replaced by a search.
- Let the reference script also compute scene layout and object placement with an automated feasibility search (non-overlap, in-bounds). Do not derive spacing, projected sizes, or safe offsets in-head; that produced repeated plan churn and rejected layouts.
- Write the expected JSON before any asserts (or in a `finally` block) so a failed assert still leaves the artifact for debug scripts. Build in a `--trace` mode that prints per-candidate verdicts instead of editing ad-hoc `console.log` lines into the script.

## Environment
- No global `playwright` package; browser binaries live in `~/.cache/ms-playwright`. A usable package exists in other repos (e.g. `/home/phamba/repos/tarot/app/node_modules`). ESM `import` ignores `NODE_PATH`; import Playwright by absolute path on first use and verify with a real ESM dynamic import (`node -e "import('<abs path>').then(()=>console.log('ok'))"`); a require- or NODE_PATH-based check can pass while the ESM import fails.
- Serve with `python3 -m http.server <uncommon-port> -d <repo-dir>` for plain ES modules, or `npx vite --port <port>` when bundler behavior is needed. Check the port is free (`lsof -i:<port>`) and curl-check HTTP 200 for the page and module URLs. Start servers detached (`setsid`); keep a list of every server you start and kill each by port at the end (`lsof -t -i:<port> | xargs -r kill`); never `pkill -f` a pattern that appears in your own command line; do not touch ports you did not start.
- Headless Chromium (SwiftShader): keep `readPixels` readbacks few, rerun once on CONTEXT_LOST, and use pixel values as evidence (screenshots can come back blank; dump frames in-page with `canvas.toDataURL('image/png')`, since `convertToBlob` may not exist, then crop and inspect with ImageMagick `convert`; PIL is not installed). Synthetic events need instance properties set via `defineProperty`, controlled `timeStamp`, and a `navigator.maxTouchPoints` override when code gates on it. Hardware-only paths go in Notes as limits, never as pass/fail checks.

## Scripts
- Grep the `export` lines of every module a script imports and copy the exact names before writing it. Offset-read the region under test in large modules instead of a full read (a truncated read leaves blind spots that surface as mid-run hedging). Grep for helper files before referencing their paths; a hardcoded wrong path costs a whole browser run.
- `node --check` immediately after every write, and re-check scratch and diagnostic scripts before each browser run. Never write an unfinished or speculative file; rewrite the whole file instead of chaining edits when the structure changes. Three consecutive one-error runs of a diagnostic script cost three full browser boots.

## In-page code and drivers
- `page.evaluate` accepts serializable data only. Make callbacks `async` when they `await`; share values through `globalThis` or evaluate arguments; never close over Node scope. Declare each variable in the function that uses it.
- A module the app does not import yet is still testable: serve the repo and `await import('/src/<path>.js')` in the page; capture console and page errors in the driver.
- Run hygiene: smoke-test the driver end to end before the first full run; write output to a log file and tail it (never pipe a long run through `| tail`); print each check as it completes; set a page default timeout (15-20 s); batch all contexts into one script. Keep the todo list to 3-5 items.

## Scenario design
- Define each scenario once as data (initial state, per-step resets, measurement flags, tolerances) and let reference and driver consume the same schema. Reset every state field between measured steps, assert at the exact step boundary the scenario defines, and keep expected values strictly inside pass regions. Name probe IDs with delimiters and exact-match lookups (`d20-top`, never a token that is a prefix of another ID).
- Assert colors by majority vote over a small patch, never a single pixel: antialiasing and label ink make single-pixel probes flaky. Keep test objects inside bounded geometry at all times; an object outside the region turns a harness mistake into a false product failure.

## Failure diagnosis
- When one check fails while sibling checks pass, suspect the check first: re-read its guard conditions and scenario before forming product hypotheses; most single-check failures are harness bugs. After more than two failed checks in one run, stop and batch-audit every failure, classifying each as driver bug, reference bug, or product bug. Time-box anomalies: a failure that does not block acceptance gets at most two probes, then file a defect or open-question card, annotate the check, and move on.
- When behavior resists two hypotheses, or a value is off by orders of magnitude, stop deriving in-head: write a trace or bisect script that calls the stage functions directly and prints intermediates. For rendering defects (missing geometry, culling, blank regions), escalate fast to a minimal raw-WebGL repro with no app code; it settles winding, culling, and attribute questions that shader-level reasoning cannot.

## Wrap-up
- Persist measured numbers once (notes or a JSON file) and reuse them when writing cards. File confirmed product defects as defect cards and open questions as question cards, each with live-test evidence, root cause with file and line references, fix direction, and acceptance criteria. State harness assumptions and test limits in the task notes.
- Draft task Notes in one clean pass and scan for duplicated lines before posting. End of run: stop every server you started and verify with `lsof`; finish with a results table that maps every pass and fail to a check or a filed card.
